# 飞船系统 — 消耗管理器规格

> 基于 `d:\Unity\Spaceship` 代码分析 | 更新：2026-08-21

---

## 一、适用范围

三类消耗（燃料、能源、弹药）**只作用于玩家控制的飞船**：

| 消耗 | 生效范围 | 守卫位置 |
|------|----------|----------|
| 燃料 | `ShipAssembly.IsPlayerControlled == true` | `ShipFuelConsumptionManager.OnDistanceRecorded` |
| 能源 | `ShipAssembly.IsPlayerControlled == true` | `ShipFoodConsumptionManager.OnDayEnded` |
| 弹药 | 仅玩家控制飞船开火时检查；`ShipAssembly.IsPlayerControlled == false` 的飞船不检查弹药 | `ShipCombatController.TryFire` |

非玩家单位、残骸、中立飞船不参与任何结算消耗。非玩家单位开火不消耗弹药（规格未定义非玩家单位弹药压力，见文末「与设计的差异」）。

---

## 二、统一结算语义：不足才死，耗尽不死

> 规格原文曾同时出现「耗尽即死亡」与「不足以支付才坠毁」两种表述，语义冲突。当前实现统一为 **「不足才死」**。

**统一规则**：结算时先计算本次所需总量，再判断库存。

- 若**可消耗量 ≥ 所需总量** → 正常扣减，扣满后即使归零也**存活**，下一轮若无补给再触发「不足」。
- 若**可消耗量 < 所需总量**（差 1 也算不足）→ 整船坠毁，**不做部分扣减**。

**可消耗量** = 货舱该类别总量（`ShipCargoHold.GetConsumableTotal`），**含未鉴定货物**。Tab 揭示只把槽位翻成已鉴定并播放动画，不作为消耗门禁。

实现要点：

- 结算前总额判定使用 `cargo.GetConsumableTotal(category) < totalCost`，判定通过后使用 `CargoInsufficiencyPolicy.KeepUnchanged` 扣减，杜绝「部分扣减」中间态。
- 三个管理器统一的判定先于扣减，保证「判定足够则必能扣满」。
- 「存活核心模块」查询统一收敛到 `ShipAssembly.LiveCore`（与 `HasCore`/`IsOperational` 同源），燃料与能源管理器复用，避免重复查询逻辑漂移。

## 三、燃料消耗

| 项 | 规则 |
|----|------|
| 触发 | 每累计 **100 米**真实质心位移结算一次（`settlementDistance`，可配置） |
| 所需总量 | 核心模块 **2** 单位 + 每个存活动力模块 **1** 单位（`coreFuelCost` / `fuelCostPerThruster`，可配置） |
| 扣减对象 | 核心向离自己最近的储存槽位扣 2；每个动力模块向离自己最近的储存槽位扣 1 |
| 不足判定 | 可消耗燃料 < 所需总量 → 坠毁（原因「燃料不足」） |
| 核心缺失 | 无存活核心模块 → 坠毁（原因「核心模块不存在」） |

### 航程口径

- 距离由 `ShipTravelDistanceTracker` 按飞船质心累计，**单物理帧位移 ≤ 25 米** 计入；单帧位移超过 25 米视为传送/弹飞，**不计入燃料航程**（`teleportThresholdPerPhysicsStep`）。
- **被动位移计费（定稿）**：碰撞弹飞、爆炸冲击等被动位移与主动航行一视同仁，只要单帧不超过 25 米阈值即计入燃料航程。这是有意为之——规避「被打飞反而省油」的反直觉博弈，也避免运动系统区分主动/被动位移的额外复杂度。
- 结算在 `FixedUpdate` 同步完成；一次位移可触发多轮结算（如一口气跑过 200 米）。

## 四、能源消耗

| 项 | 规则 |
|----|------|
| 触发 | 每个游戏日结束时（`DayEnded` 事件）结算一次 |
| 所需总量 | 世界规则 `FoodPerDay`，默认 **5** |
| 扣减对象 | 向离核心模块最近的储存槽位扣所需量 |
| 不足判定 | 可消耗能源 < 所需总量 → 坠毁（原因「能源不足」） |
| 核心缺失 | 无存活核心模块 → 坠毁（原因「核心模块不存在」） |

---

## 五、弹药消耗

| 项 | 规则 |
|----|------|
| 触发 | 武器模块每次射击前（`TryConsumeForShot`） |
| 所需总量 | 武器模块定义 `AmmunitionPerShot`，默认 1 |
| 扣减对象 | 向离该武器模块最近的储存槽位扣弹药 |
| 不足判定 | 弹药不足 → **本次射击不触发**，不扣弹，不坠毁 |
| 失败节流 | 弹药不足时按武器冷却时长节流该武器（`ShipCombatController.ammunitionBlockedUntil`），避免每帧点射触发事件风暴；补弹后需等冷却结束才能开火 |
| 失败事件 | 弹药不足时广播 `AmmunitionInsufficientEvent`（HUD 订阅后弹药数字短暂红闪） |
| 成功事件 | 扣弹成功时广播 `AmmunitionConsumedEvent`（HUD 用其刷新剩余值） |

弹药不足只会拒射，**不会导致坠毁**——这是与燃料/能源（不足即坠毁）的关键区别。

---

## 六、未鉴定货物规则

- **未鉴定货物（`CargoIdentificationState.Unidentified`）可直接计入可消耗量**，参与燃料 / 能源 / 弹药扣减。
- `ShipCargoHold.GetConsumableTotal` 与 `GetTotal` 对同类货物数量一致；`CargoConsumptionService` 的候选槽位不再过滤 `IsIdentified`。
- 鉴定状态只服务整理界面：未鉴定格显示问号，按 Tab（或史诗/结算强制打开）时由 `CargoRevealCoordinator` 逐格 `Identify()` 并播放揭示动画。消耗不会把槽位翻成已鉴定。
- 影响示例：打捞到未鉴定燃料后不必先开整理界面，行驶即可扣减；仅有未鉴定弹药时也可以射击。

---

## 七、事件契约

| 事件 | 触发时机 | 负载 |
|------|----------|------|
| `AmmunitionConsumedEvent` | 弹药扣弹成功 | 飞船、武器模块、消耗量、剩余总量 |
| `AmmunitionInsufficientEvent` | 弹药不足拒射 | 飞船、武器模块、请求量、当前总量 |
| `CargoChangedEvent` | 货物数量变化 | 飞船、类别、总量 |

HUD（`AssemblyPlaytestHud`）订阅 `AmmunitionInsufficient` 后在 2 秒窗口内让弹药行红色闪烁；燃料/能源数量经 `CargoChanged` 与结算事件刷新。

## 与设计的差异

| 差异点 | 当前实现 | 说明 |
|--------|----------|------|
| 非玩家单位弹药 | 非玩家单位开火完全免弹药 | 规格未定义非玩家单位弹药压力，未来如需非玩家单位打空弹药需补充规则 |
| 25 米传送阈值 | 单帧位移超 25 米不计燃料 | 规格原文未写明该排除口径，属实现约定，已在本文档落档 |
| 「耗尽」与「不足」 | 统一为「不足才死」 | 规格原文两种表述并存，此处为正式定稿 |
