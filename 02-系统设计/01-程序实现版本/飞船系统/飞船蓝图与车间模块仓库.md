# 飞船蓝图与车间模块仓库

>
> 本文档聚焦三个紧密关联的系统：**飞船蓝图**（飞船的静态配置数据）、**车间模块仓库**（模块库存的获取、存储与拼装消耗），以及**车间编辑器**（玩家拼装飞船的操作界面）。从策划视角串讲为一个整体，涵盖数据的来龙去脉。

## 1. 系统全景

Spaceship 的核心玩法循环围绕模块展开：

> **打捞残骸获取模块 → 结算入库 → 车间拼装消耗模块 → 出航再打捞**

三个系统在这个循环中的角色：

| 系统 | 一句话定位 | 发生时机 |
|------|-----------|----------|
| **飞船蓝图** | 「这艘船长什么样」——飞船的静态配置数据资产 | 策划/编辑器配置 |
| **车间模块仓库** | 「我有哪些模块可用」——玩家收集的模块作为局外资源存档 | 跨局持久存在 |
| **车间编辑器** | 「怎么拼这艘船」——从仓库取出模块、放置到网格、拼出飞船 | 两次出航之间的整备阶段 |

三者关系：

> 蓝图是**图纸**，仓库是**零件库**，编辑器是**工作台**。编辑器从仓库取出零件、按玩家意愿拼成飞船；飞船出航打捞到的新零件在结算时入库；下次回车间又能用新零件拼更好的船。

## 2. 飞船蓝图

### 2.1 什么是飞船蓝图

飞船蓝图是一个**数据资产**（`ShipBlueprint` ScriptableObject），完整描述一艘飞船的静态配置：

- **模块布局**：每个模块的类型、在 1m 网格上的坐标、旋转朝向
- **初始货物**：这艘船出厂时储存模块里带的初始物资
- **阵营归属**：玩家、非玩家单位、或残骸

蓝图本身只是配置数据，不包含运行时行为。运行时由工厂类（`ShipBlueprintRuntimeBuilder`）实例化为一艘完整飞船。

### 2.2 蓝图的结构

```
ShipBlueprint (ScriptableObject)
├── 飞船名称
├── 阵营（Player / Enemy / Derelict / Neutral）
├── 模块布局列表（ShipModulePlacement[]）
│   ├── 模块定义引用
│   ├── 网格 X 坐标、Y 坐标
│   └── 旋转（四分之一圈计数）
├── 初始货物列表（ShipInitialCargoPlacement[]）
│   ├── 货物类型 + 数量
│   └── 目标储存模块索引
└── 导出预制体引用（可选）
```

### 2.3 现有蓝图资产

| 蓝图 | 阵营 | 用途 |
|------|------|------|
| `玩家飞船` | Player | 玩家初始飞船（旧版） |
| `玩家新飞船` | Player | 玩家可选飞船（新版布局） |
| `非玩家单位新飞船` | Enemy | 标准非玩家单位 |
| `非玩家单位新飞船 1` | Enemy | 另一种非玩家单位布局 |
| `非玩家单位3` | Enemy | 第三种非玩家单位布局 |

### 2.4 蓝图校验

编辑器与运行时均校验三项：

- **布局连通性**：所有模块必须通过链接关系构成一个连通整体，不允许孤立模块
- **初始货物合法**：初始货物不能超出储存模块的总容量
- **核心模块存在**：出航校验确保至少有一个核心模块

### 2.5 蓝图与车间编辑的关系

在车间中选择已有蓝图时，行为如下：

1. 当前网格上所有模块**全部归还到模块仓库**（`ReturnAllPlacedModulesToInventory`）
2. 清空编辑网格
3. 从蓝图数据加载全部模块布局到网格

> **「套用蓝图不额外消耗模块」**——选择蓝图的本质是用蓝图数据填充网格，不涉及仓库的增减。网格上原有的模块在加载蓝图前已归还，不会丢失。

蓝图也可以通过「保存新飞船」或「更新飞船」将当前编辑器中的拼装结果导出为蓝图资产，供残骸生成器或跨项目复用。

## 3. 车间模块仓库

### 3.1 什么是模块仓库

模块仓库（Module Inventory）是玩家的**局外资源**——收集到的模块零件库，随存档跨局、跨会话保留。它不存储模块的单个实例，而是按「类别 × 朝向」聚合为条目的计数。

数据结构（`ModuleInventoryEntry`）：

| 维度 | 说明 |
|------|------|
| 模块类别（`ModuleKind`） | Core / Thruster / Radar / Light / Cannon / Grapple / Shield / Storage / Empty |
| 基础朝向（`Facing`） | Forward / Right / Back / Left |
| 数量（`Count`） | 该类别、该朝向下拥有的模块个数 |

> 举例：仓库中「动力模块（Forward 朝向）× 3」「机炮（Forward 朝向）× 2」「储存模块（Forward 朝向）× 1」，拼装时面板分别显示它们的可用数量。

仓库数据通过 `GameSaveService` 以 JSON 格式持久化到 `persistentDataPath/save.json`，是整个单存档模型的一部分。

### 3.2 模块入库——「我的零件从哪来」

#### 3.2.1 首次游戏：预配置初始飞船「拆」出零件

首次进入游戏时，玩家仓库为空。系统执行「库存播种」：

```
从预配置初始飞船蓝图读取所有模块 →
按类别与朝向逐个写入模块仓库（每种 ×1）→
保存存档
```

这意味着首次游戏的玩家有刚好拼出初始飞船的全套零件。

#### 3.2.2 结算入库——「出航带回来的模块归我」

每次成功结算（返回星球）时，入库逻辑（`SettleInventoryIntoSave`）执行：

1. 遍历玩家飞船**所有未摧毁模块**
2. 按 `(类别, 朝向)` 分组聚合，得到每种有多少个
3. 逐组调用 `AddModules` 追加到仓库
4. 宝藏换算为金币，不纳入模块仓库
5. 能源/燃料/弹药等消费品按类别入库到货物库存（独立于模块仓库）

> **关键设计**：结算入库的不是「每种 +1」，而是**船上实际有多少就入库多少**。如果玩家在出航中链接了 3 个非玩家单位的动力模块残骸，结算时仓库就增加 3 个动力模块。

#### 3.2.3 休整站返回——「飞船直接带回，不用入库」

这是最容易混淆的部分。结算后返回休整站（ShipBuild 场景）时，模块**并不走仓库**：

- 结算时飞船模块已入库（见 §3.2.2）
- 同时捕获一个飞船运行时快照（`ShipRuntimeSnapshot`）存入跨场景上下文
- 休整站加载时，用这个快照恢复编辑器网格（`RestoreFromSnapshot`）
- 恢复快照**不扣仓库**——因为飞船本身带的零件不是从仓库取的，而是出航时带出去的

简单说：**结算把模块复制进仓库 → 飞船本身也保留零件回到车间**。玩家回来时飞船上零件都在，仓库里也有增量。

#### 3.2.4 失败不返还

失败时模块与货物随飞船销毁，**不入仓库**。玩家还需支付预配置初始飞船费用（资金不足记欠账），获得一艘新的初始飞船。

### 3.3 模块出库——「拼装时零件怎么消耗」

在车间编辑器中：

| 操作 | 仓库变化 | 数据调用 |
|------|----------|----------|
| 从面板拖入新模块到网格 | 仓库同类别同朝向数量 -1 | `ConsumeModuleFromInventory` |
| 右键移除网格上的模块 | 仓库同类别同朝向数量 +1，立即保存 | `ReturnModuleToInventory` |
| 新建飞船 / 套用蓝图 | 网格上全部模块批量归还仓库，立即保存 | `ReturnAllPlacedModulesToInventory` |

**库存不足时**：面板中该模块条目变灰不可拖拽，防止超扣。

### 3.4 测试模式——「开发期无限制零件」

当 ShipBuild 场景被直接启动（而非由其他场景加载）时，进入测试模式：

- `IsTestMode = true`
- 模块仓库显示全部目录中的模块，数量显示为 `∞`
- 放置不扣库存、移除不写存档
- 用于编辑器中自由改造飞船、无代价测试不同布局

正式模式（由开始菜单加载或结算/失败返回）则按存档结算。

### 3.5 仓库与存档的关系

```
SaveData (save.json)
├── coins: 金币
├── debt: 欠账
├── isFirstGame: 首次游戏标记
├── moduleInventory: ModuleInventoryEntry[]  ← 模块仓库
│   └── 每项：[Kind, Facing, Count]
├── cargoInventory: CargoInventoryEntry[]    ← 货物库存（能源/燃料/弹药）
└── schemaVersion: 存档结构版本
```

存档在以下时机保存：
- 模块入库/出库变更后（`saveService.Save()`）
- 退出游戏时（`OnApplicationQuit`）

## 4. 车间编辑器

### 4.1 编辑器是什么

车间编辑器（Workshop Editor）是玩家拼装飞船的操作界面，对应 ShipBuild 场景。它分为三个区域：

| 区域 | 位置 | 功能 |
|------|------|------|
| **已保存飞船列表** | 左侧面板 | 列出所有蓝图，点击套用；预览选中飞船的模块布局与连接状态 |
| **飞船编辑网格** | 中央区域 | 可配置半径的方形网格，拖入模块拼装飞船；显示连接面状态（绿=可连/红=不可连） |
| **模块库存面板** | 右侧面板 | 显示模块仓库中可用的各类模块与数量；点选拖拽放置到网格 |

编辑器提供两种模式：

| 模式 | 说明 |
|------|------|
| **编辑模式（Edit）** | 默认模式：在网格上放置/移除/旋转/移动模块 |
| **操控模式（Control）** | 生成可操控的飞船试驾，测试手感与性能；返回时重新加载编辑器 |

### 4.2 编辑操作

| 操作 | 交互方式 | 规则 |
|------|----------|------|
| 放置模块 | 从右侧库存面板选中模块 → 拖到网格空白格松开 | 消耗仓库该模块×1；目标格已被占用则拒绝 |
| 移动模块 | 按住网格中已有模块 → 拖到目标格松开 | 不涉及仓库增减；目标格非空则拒绝 |
| 旋转模块 | 选中模块 → 按 R 键（拖拽中也可按 R） | 每次顺时针旋转 90°；原地旋转与拖拽到位同时生效 |
| 移除模块 | 右键点击网格中模块 | 归还仓库该模块×1；同时清除该格上的初始货物配置 |
| 套用蓝图 | 左侧列表点击蓝图 | 先归还全部模块到仓库 → 再加载蓝图布局 |
| 新建飞船 | 点击「新建玩家飞船」/「新建非玩家单位飞船」 | 归还全部模块 → 空白网格 |

### 4.3 连接面提示

编辑网格上每个模块格的四边显示连接状态：

- **绿色条**：该面连接开放，可与相邻模块建立链接
- **红色条**：该面连接关闭，或紧邻模块但双方连接面不匹配（即「断裂」原因）

选中一个模块后，其四边才显示红绿条。断裂模块在未被选中时也会在问题方向上显示红条。

### 4.4 出航校验

点击「出航」时执行三重校验：

| 校验项 | 不通过提示 |
|--------|-----------|
| 至少有一个核心模块 | 「飞船必须包含核心模块，才能出航或试驾。」 |
| 所有模块连通为一个整体 | 「模块之间存在断裂；所有模块必须通过有效连接面连接到同一艘飞船后才能出航或试驾。」 |
| 飞船已配置至少一种初始物资 | 「飞船尚未配置任何初始物资，禁止空仓出航。」 |

通过校验后，编辑器生成飞船运行时快照（`CreateSnapshot`），写入跨场景上下文，加载出航探索场景。

### 4.5 储存模块初始库存配置

编辑器的右侧面板下方是「储存模块初始库存」配置区。选中网格中的储存模块（或核心模块）后，可为其配置初始携带的四类物资（能源/燃料/弹药/宝物）的数量，每格上限 10 个单位同类货物。对宝物类别还可进一步选择具体货物定义（如「失落的星核」而非通用「宝物」类别）。

## 5. 完整数据流

### 5.1 模块的一生

```
                     ┌──────────┐
                     │ 首次游戏  │
                     └────┬─────┘
                          │ 预配置飞船模块写入仓库
                          ▼
                  ┌───────────────┐
                  │   模块仓库     │  ← JSON 持久化
                  │ (存档局外资源) │
                  └───┬───────┬───┘
         放置扣库存    │       ▲    移除归还 / 结算入库
                      ▼       │
┌──────────┐    ┌──────────┐  │
│ 车间编辑器 │───▶│  出航探索  │──┤
│ (拼装飞船) │    │ (打捞残骸) │  │
└──────────┘    └────┬─────┘  │
       ▲              │        │
       │       失败   │  结算  │
       │       销毁   ▼        │
       │     ┌──────────┐     │
       └─────│  失败界面  │     │
   获得初始飞船│ (支付费用) │     │
             └──────────┘     │
                              │
                     结算成功 │
                              ▼
                     ┌────────────┐
                     │  结算界面    │
                     │ 模块入库    │
                     │ 宝藏→金币   │
                     │ 飞船快照保留 │
                     └────┬───────┘
                          │ 返回休整站
                          ▼
                     ┌──────────┐
                     │ 车间编辑器 │ ← 快照恢复飞船（不扣仓库）
                     └──────────┘
```

### 5.2 关键路径总结

| 路径 | 发生了什么 |
|------|-----------|
| 首次进入车间 | 初始飞船蓝图「拆」出零件 → 写入模块仓库 → 套用蓝图到网格 |
| 从仓库拖模块到网格 | 仓库该条目数量 -1 |
| 从网格移除模块 | 仓库该条目数量 +1，立即保存 |
| 点击出航 | 创建飞船快照 → 仓库当前余额保存 → 加载出航场景 |
| 出航中打捞残骸 | 链接残骸模块 → 加入玩家飞船 Assembly（不涉及仓库） |
| 返回星球结算 | 船上未摧毁模块按 (类别,朝向) 聚合入库；飞船快照保留 |
| 结算后回到车间 | 快照恢复飞船到网格（不消耗仓库）；仓库已有新增模块 |
| 出航失败 | 模块随飞船销毁、不入库；支付初始飞船费用 → 获得初始飞船 |

## 6. 设计决策记录

| 决策 | 理由 |
|------|------|
| 模块仓库按 (类别, 朝向) 聚合而非存储实例 | 简化库存模型：模块没有个体差异，不需要追踪「这个特定的动力模块」，只需记录「有多少个动力模块」。减少存档体积与序列化复杂度 |
| 结算时「飞船保留 + 模块入库」双线并存 | 结算入库是「资源收益」——玩家打捞到的零件变成永久资产；飞船快照保留是「装备延续」——玩家拼好的飞船不用重新拼。两条线各自独立、互不干扰 |
| 失败时模块不入库 | 失败 = 高风险零收益，维护「出航有风险」的紧张感，同时给结算以正反馈 |
| 套用蓝图先归还全部模块再加载 | 避免「套用蓝图后原有模块丢失」——属于零和操作：归还 N 个旧模块、加载 M 个新模块，净变化是归还 (N-M) 个 |
| 移除模块立即保存存档 | 玩家在车间里反复试错模块布局时，每次移除都即时持久化，杜绝「铺好了但没存档、崩溃后全丢」 |
| 测试模式无限库存 | 开发期无需频繁切场景、无需反复出航积累模块，直接自由拼装测试 |
| 模块不开放金币购买 | 保持模块唯一来源是残骸打捞，维护「探索 → 获得 → 改造」的核心循环完整性 |
| 出航前校验「飞船必须携带初始物资」 | 防止玩家空仓出航后秒失败（无燃料/能源），提供明确的引导 |
