# 究极手拼装与输入重构设想讨论

> **状态：设想讨论记录（未立项，仅留存底稿）**

## 1. 背景与目标

### 1.1 现存问题

| # | 问题 | 现象 |
|---|------|------|
| 1 | 自动拆卸违背玩家预期 | 钩爪自动选"最近+半角内"目标，玩家路过/瞄准时被拆走不想要的模块，读条打断静默、冷却静默 |
| 2 | 快拆快安缺少控制权 | 飞行中拼装只有"右键长按拆（2s）＋靠近自动链接"；安装位置由系统就近决定、朝向由几何自动对齐（`LinkGeometry.ComputeAlignTransform`：残骸对齐本船、本船位姿不变），玩家被迫"开船调整角度"凑位置，无法旋转、无法选位 |
| 3 | 无手柄承载方案 | 全部交互直接轮询 `Mouse.current` / `Keyboard.current`，指针型交互（模块选择/拆除/链接）无法映射手柄；陀螺仪未接入 |
| 4 | 钩爪定位尴尬 | 全自动拆装与"玩家掌控"的预期冲突；"安装到敌船"存在资敌风险；是否装钩爪缺少真实 build 价值 |

### 1.2 设计目标

1. 拼装自由度：探索中玩家能自由重组自己的飞船（拆下即拿起、旋转、贴到任意位置），参考《王国之泪》究极手（Ultrahand）手感。
2. 输入统一：键鼠/手柄同一套命令语义，不因模块增多而增加按键；陀螺仪作为手柄指针的可插拔方案。
3. 预期可控：玩家只掌控自己的船；敌人飞船不可被"活拆"；删除拆卸钩爪模块。
4. 战利品流闭环：敌人被打爆后掉残骸，可打捞装到自己船（"搜打撤"循环保底）。

## 2. 设计总览（三支柱）

```
输入抽象层（键鼠/手柄同构命令集）
   └─ X 万能键（Interact）：对指针上下文执行唯一动作
        └─ 究极手（Ultrahand）：拆下即拿起 → 旋转 → 贴回任意位置
```

- **支柱一：输入抽象层**：统一 Move / Turn / Aim / Fire / Interact / Rotate 等命令，键鼠与手柄各一份映射，陀螺仪可插拔。
- **支柱二：X 万能键**：唯一交互键，语义 = "对指针所指的对象执行操作"；短按/长按/上下文分派。
- **支柱三：究极手**：`X 长按拆下` 即进入手持状态，模块悬浮跟随、可旋转、贴回船体任意空闲链接面；释放为自由残骸。
- **删除**：`ModuleKind.Grapple`、`ShipGrappleController`、相关 API 与验证。
- **补充**：非玩家单位被摧毁后掉残骸，战利品流闭环。

## 3. 输入抽象层

### 3.1 统一命令集

| 命令 | 语义 | 键鼠映射 | 手柄映射 |
|------|------|----------|----------|
| Move | 四向移动（局部空间） | W/A/S/D | 左摇杆 |
| Turn | 旋转 | Q/E | 右摇杆 X 轴 |
| Aim | 指针（世界坐标） | 鼠标 | 陀螺仪（按住 LB 激活）＋右摇杆 Y 轴粗调兜底 |
| Fire | 开火 | 鼠标左键 | RT |
| **Interact** | **万能交互键** | 鼠标右键 | **X** |
| Rotate | 手持物旋转（连续，松手吸附 90°） | R | LB ＋ 右摇杆 X |
| Organize | 整理储存界面 | Tab | Y |
| Pause | 暂停 | Esc | Start |

- 现有 `IShipActionInput`（`PlayerShipInputSystem` 为键鼠实现）扩展出 `Aim` 指针、`Interact` 事件、`Rotate` 轴三个成员；新增手柄实现 `PlayerGamepadInputSystem`。
- 射击弹道沿用现状：沿机炮模块朝向发射（`ShipCombatController.TryFire` 的 `GetModuleWorldDirection`），不依赖指针，因此 Fire 命令零弹道改动。
- 移动/转向沿用现状：键鼠 `ReadKeyboardCommand` 的 WASD/QE 与手柄左摇杆/右摇杆 X 一一对应。

### 3.2 陀螺仪策略（可插拔 AimInput）

| 项 | 设计 |
|----|------|
| 激活方式 | 按住 LB 时陀螺仪接管指针微调（避免待机光标乱飘，符合 Steam 惯例） |
| 兜底 | 无陀螺仪/不可用时，右摇杆 Y 轴做指针粗调（映射为 Aim 平移量） |
| 抽象 | `AimInput` 接口：`Vector2 ReadPointerDelta()`；键鼠实现＝鼠标位移，手柄实现＝陀螺仪角速度或右摇杆，按平台能力插拔 |
| 平台差异 | Unity Input System `Gyroscope.current` 原生覆盖移动端；PC 上 DualSense/DualShock4 有限支持，Switch Pro 无官方支持，Steam Deck 走 Steam Input 映射；实现时按"可用则用、不可用兜底"设计，不写死 |

### 3.3 按键约束

- **不因模块新增而新增按键**：全游戏只有一个交互键（X/右键），所有模块共享；Rotate 复用车间已有的 R（键鼠），手柄映射到 LB＋右摇杆。
- 释放 B 键为空闲（可留作通用取消/暂停兜底）。

## 4. X 万能键分派表

X（右键）＝ 对指针所指的对象执行操作。**作用范围只限于玩家自己的飞船**。

| 指针所指 | 空手状态 | 手持状态（究极手拿起中） |
|----------|----------|--------------------------|
| 自己船模块（非核心） | X 短按＝开关模块；X 长按 2s＝**拆下即拿起** | 无（手持中指针不指向自己船模块） |
| 自己船模块（核心） | 不可操作（提示"核心模块不可拆除"） | — |
| 自己船空闲链接面 | — | 重叠即自动读条链接（5s，刚拆 2s） |
| 残骸 | 维持自动吸附链接（现状，究极手不碰） | 无 |
| 敌船/敌模块 | **完全不可操作**（无任何提示之外的交互） | 无 |
| 空白太空 | 无操作 | X（0.3~0.5s 短读条，松手取消）＝**释放为自由残骸** |

规则：**X 对指针上下文执行动作，唯一例外是敌人飞船——不可碰**。

## 5. 究极手（飞行中自由拼装）

### 5.1 核心原则：拆下即拿起

现状 `ShipAssembly.DetachModule` 拆下后生成"自由残骸"（独立物理、可飘可转、玩家不可控）。**改为：拆下即进入手持状态，中间不存在不可控阶段**。

```
X 长按 2s 拆下 → 手持（悬浮跟随）→ 旋转调向 → 靠近空闲链接面 → 重叠即读条 → 装回
                                                                    └→ X(空白) 短读条 → 释放为自由残骸
```

### 5.2 手持状态规格

| 项 | 规格 |
|----|------|
| 悬浮位置 | 玩家船头前方固定距离（约 1.5~2m），跟随船体移动旋转 |
| 物理 | 物理关闭（不参与刚体模拟），与船体无碰撞 |
| 质量 | 手持模块**不计入船体总质量与质心**（装上/释放才恢复）——重组零代价 |
| 多模块组 | 拆下时随被拆模块断开的模块组整体手持（复用 `CollectDetachedGroup` 分组逻辑） |
| 旋转 | 按住 Rotate 键连续旋转，松手自动吸附到最近 90° 朝向（四向链接面） |
| 贴合触发 | 手持模块某链接面与船体空闲链接面重叠/靠近 → 自动开始读条（5s，刚拆下 2s），复用 `LinkSessionDriver` |
| 读条打断 | 链接读条中若脱离贴合范围 → 取消并提示（不再静默） |
| 释放 | 指针指向空白太空按 X，0.3~0.5s 短读条（松手取消）→ 生成自由残骸（走原 `DetachModule` 残骸生成路径） |
| 防误触 | 释放只在"指向空白"时触发；指向船体但该处无空闲链接面时提示"该处无空闲链接点"而非释放 |

### 5.3 与现有系统的关系

| 系统 | 关系 |
|------|------|
| 残骸自动吸附链接（`ShipAssemblyInteractionController.TickAutomaticLink`） | **完全保留**，究极手不碰残骸；手持模块非残骸，不会进入自动链接候选 |
| 链接计时（5s / 刚拆 2s） | 保留；"拆卸后 60s 内更短链接时间"规则保留 |
| 清灰/蒙尘 | 保留（野外残骸蒙尘，拆解/掉落的残骸无灰） |
| 右键拆除自己船模块（现状 2s 长按） | 语义保留并升级为"拆下即拿起" |
| 携带计数（`CarriedModules` / `AttachCarriedAssembly` 等钩爪专用路径） | 被手持状态取代，随钩爪删除清理 |

### 5.4 反馈规格

| 状态 | 反馈 |
|------|------|
| 指向可拆模块 | 高亮＋提示"X 长按拆下"（复用 `ShipModuleActivityPresenter` 高亮体系） |
| 手持中 | 模块跟随高亮；旋转中显示朝向；靠近空闲链接面显示黄线"可接上"（复用 `LinkFeedbackPresenter`） |
| 读条中 | 进度文本"正在安装 xxx：x.x/5.0 秒"；打断时提示"目标脱离，安装取消" |
| 释放中 | "释放中，松手取消" |
| 冷却 | 钩爪删除后不再有 30s 冷却概念；自己船重组无冷却（读条即成本） |

## 6. 删除拆卸钩爪模块

### 6.1 删除范围清单

| 类别 | 项 |
|------|----|
| 枚举 | `ModuleKind.Grapple`（`ModuleDefinition.cs`） |
| 控制器 | `ShipGrappleController.cs` 整文件删除；`ShipAssembly.AttachCarriedAssembly` / `ReleaseCarriedAssembly` / `CarriedModules` 若仅钩爪使用则一并删除或改造 |
| API | `CombatApi.GetGrappleStatus / GetGrappleProgress01 / IsGrappleOperating`；`SequenceMapCombatApi` 对应三个查询；`ApiEnum.cs` 中 `ModuleKind.Grapple => "拆卸钩爪"` 映射 |
| 验证 | `AllModuleFunctionValidator.TestGrapple`、"拆卸钩爪测试飞船/测试残骸" |
| 资产 | 检查并清理引用 Grapple 的 `ModuleDefinition` SO 资产与模块 Prefab（注意序列化兼容，先查引用再删） |
| 文档 | 核心系统.md、武器与对抗.md、战斗系统.md、拼装与模块.md、飞船组装系统.md、API 框架.md、AssemblyPlaytestValidation.md、SpaceshipPrototype.md、界面与操作.md、SequenceMap原子行为清单、GameFlowImplementation.md 等全部同步 |

### 6.2 定位变更

钩爪从"自动拆装工具"删除后，**模块系统不再有对外操作能力**。装不装模块的 build 决策聚焦于：武器、护盾、雷达、动力、储存——每个模块一份清晰心智。

## 7. 敌人被打爆掉残骸（战利品流闭环）

### 7.1 规则

| 项 | 规格 |
|----|------|
| 触发 | 非玩家单位/中立飞船被摧毁（`ShipAssembly` 摧毁路径，`RaiseShipDestroyed` 处） |
| 产物 | 按连通分组裂成残骸碎片（复用 `SplitDisconnectedGroups` / `DetachModule` 的残骸生成逻辑），每个独立结构一块残骸 |
| 货物 | 模块携带的货物随残骸保留（复用现有货物转移逻辑） |
| 蒙尘 | 掉落残骸无灰（与"从飞船上拆解/拽落"的残骸一致） |
| 打捞 | 残骸进入 `ShipSceneRegistry`，走现有自动吸附链接打捞；可开货舱取货 |
| 玩家船 | 玩家船被摧毁按现有结算流程处理，不掉残骸（待确认） |

### 7.2 设计意图

"不活拆敌人"＋"打爆掉残骸"并存：敌人是被打死的（武器路线），不是被扒光的（无究极手对外能力）。战利品流＝ 打爆敌人 → 捞残骸 → 装到自己船，闭合"搜打撤"循环。

## 9. 风险与待确认

| 项 | 说明 |
|----|------|
| 手持模块与子弹/碰撞 | 手持模块物理关闭、无碰撞；被子弹命中如何处理（建议：视为不可命中）——实现时定 |
| 玩家船被摧毁是否掉残骸 | 建议按现有结算流程不掉；待确认 |
| Grapple 序列化引用 | 删除枚举前先全量检查 SO/Prefab 引用，避免反序列化异常 |
| 陀螺仪平台差异 | PC 各手柄支持不一，AimInput 必须"可用则用、不可用兜底" |
| 读条被打断的判定 | "脱离贴合范围"的判定阈值需调参（链接面间距容差） |
| 手持模块与自动链接并存 | 手持模块非残骸，不进自动链接候选；释放后才进入——无冲突 |
| 核心模块 | 始终不可拆（现状保留） |
| 架构决策记录 | 本设计属重大变更（删除模块、重构交互），实施时按 `AGENTS.md` 要求在 `Assets/Documentation/Execute/` 落一条架构决策记录（含影响与回滚条件） |
