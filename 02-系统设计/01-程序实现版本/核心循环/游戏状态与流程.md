## 2. 目标设计：游戏管理器系统

### 2.1 系统描述

游戏管理器是游戏全局的总控制器：游戏启动时初始化，游戏退出时销毁。负责全局状态机流转、失败判定与结算协调。**不定义各界面内部的具体行为**，只负责状态机流转与跨系统协调调度。

### 2.2 数据

| 数据 | 类型 | 说明 |
|------|------|------|
| 首次游戏标记 | 全局布尔 | 首次为 `True` 时跳过拼装界面，直接使用预设初始飞船进入飞行模式；首次飞行结束（进入结算或失败）后置为 `False`，此后每次开始游戏均先进入拼装界面 |
| 预设初始飞船 | 配置（飞船蓝图） | 玩家首次游戏使用的飞船配置，由内容策划提前配置，必定包含核心模块 |
| 金币 | 全局数值（存档内局外资源） | 玩家在单一存档内永久持有的货币数量，通过宝藏结算获得，在结算界面展示；存储于游戏管理器（运行期），不随飞船损毁或单局结束而丢失，跨局、跨会话持久化至存档。失败后用于支付预配置初始飞船费用，资金不足时扣至 0、差额计入欠账（见 §2.6）；商店「借贷补全」等兜底路径同样在资金不足时计入欠账（见《[货币与商店系统](../../02-本地设计版本/经济系统/货币与商店系统.md)》决策 S-20） |
| 欠账（兜底） | 全局数值（存档内局外资源） | 资金不足时自动垫付的差额累计值（失败罚金差额、最低供给借贷补全等）；当前可无限累计、不设上限，不会为负；欠账的额度机制（偿还、封顶等）仍在设计中，本版仅存档累计 |
| 预配置初始飞船 | 配置（飞船蓝图） | 开发者预先配置的初始飞船资产：模块布局、购买费用、初始货物（燃料/能源等）均在资产内配置；玩家失败后付费获得（见 §2.6）；与「预设初始飞船」为同一资产机制 |
| 模块库存 | 存档内局外资源 | 玩家结算时拥有的模块（宝藏不纳入）放入库存，作为局外资源随存档保存、跨局保留；下一轮出航可从库存装载模块并拼装；局内被消耗的模块（被摧毁 / 拆除丢弃等）即为消耗、不返还库存。失败时模块随飞船销毁，不进入库存（见 §2.6） |
| 货物库存 | 存档内局外资源 | 玩家结算时拥有的货物（宝藏已被结算换算为金币，不纳入）放入库存，作为局外资源随存档保存、跨局保留；下一轮出航可从库存装载；局内被消耗的货物即为消耗、不返还库存。失败时货物随飞船销毁，不进入库存（见 §2.6） |

### 2.3 存档与局内外资源

本游戏采用**单存档模型**，全部数据归属同一个存档，不存在多存档：

| 类别 | 说明 |
|------|------|
| 局外资源 | 金币、欠账（资金不足自动垫付的差额累计）、模块库存、货物库存、首次游戏标记等，随存档保存，跨局保留，不随单局结束或失败而销毁 |
| 局内资源 | 飞船配置、货物、燃料、能源，以及世界内容（敌舰/残骸/小行星/星球等），随一局游戏开始/结束而生成或重置；每局出航世界重新生成；失败后新一局以「开发者指定的预配置初始飞船」开始（见 §2.6） |

- **一局游戏**：从拼装（或首次游戏直接飞行）开始，到结算或失败结束。
- 游戏**失败或成功（结算）后，在同一存档内开始新一局游戏**：进入拼装界面或返回主菜单重新开始。
- 单局内获得的宝藏仅在结算时换算为金币累加入存档；单局失败时宝藏销毁、不进行结算，并支付预配置初始飞船费用（资金不足记账，见 §2.6）。
- **库存结算规则**：结算时玩家拥有的模块与货物（宝藏不纳入，已换算为金币）分别放入模块库存与货物库存；失败时模块与货物随飞船销毁，不进入库存（见 §2.6）。
- **存档实现**：JSON 服务层。存档数据为 `[Serializable]` 的 `SaveData` 纯数据类（金币、欠账、模块库存、货物库存、首次标记、`schemaVersion`），由存档服务读写 `persistentDataPath/save.json`；启动时 `Load()`，金币/欠账变更、模块/货物库存变更、首次标记翻转、退出前 `Save()`。归属层为 `Spaceship.Core`，场景内显式组合。

### 2.4 状态机（7 态）

同一时刻只能处于一种状态：

| 状态 | 说明 |
|------|------|
| 开始 | 游戏启动后的初始状态，显示开始界面 UI |
| 拼装 | 玩家自由拼装飞船，显示拼装界面 UI |
| 飞行 | 玩家操控飞船在太空中探索，可移动、战斗、拾荒 |
| 暂停 | 飞行或整理中按 Esc 进入；飞船不可操控，游戏暂停 |
| 整理 | 飞行中按 Tab 进入，或暂停中返回，或结算前强制进入揭示；飞船不可移动，摄像机切换为整理模式，游戏暂停 |
| 结算 | 玩家返回星球后触发，显示本次探索收益 |
| 失败 | 触发失败条件后进入，显示失败原因 |

### 2.5 状态转移

| 转移 | 触发条件 |
|------|----------|
| 启动 → 开始 | 游戏启动，初始化全局数据 |
| 开始 → 拼装 | 点击「开始游戏」（非首次游戏） |
| 开始 → 飞行 | 首次游戏：加载预设初始飞船，直接进入飞行 |
| 开始 → 退出 | 点击「退出游戏」，关闭游戏 |
| 拼装 → 飞行 | 点击「出航」，使用当前飞船配置；出航需先通过校验（拼装结果至少包含一个核心模块，见 §2.8） |
| 拼装 → 开始 | 点击「返回主菜单」 |
| 飞行 → 暂停 | 按 Esc |
| 暂停 → 飞行 | 暂停前状态为飞行时：点击「继续游戏」或再次按 Esc，回到飞行 |
| 暂停 → 整理 | 暂停前状态为整理时：点击「继续游戏」或再次按 Esc，回到整理 |
| 暂停 → 开始 | 点击「返回主菜单」 |
| 暂停 → 退出 | 点击「退出游戏」 |
| 飞行 → 整理 | 按 Tab，飞船停止移动，摄像机切换整理模式 |
| 整理 → 飞行 | 按 Tab（非结算流程），摄像机恢复，飞船恢复可移动 |
| 整理 → 暂停 | 按 Esc |
| 飞行 → 结算 | 结算触发条件满足（见 §2.7）。若货舱存在未揭示物品，先进入整理界面揭示（飞行 → 整理 → 结算） |
| 整理 → 结算 | 结算流程中强制进入的整理：未揭示物品揭示完成后**自动退出整理**，跳转结算 |
| 飞行 → 失败 | 任一失败条件满足（见 §2.6） |
| 结算 → 拼装 | 点击「返回拼装界面」，拼装界面显示上一轮结算时的飞船配置与货物状态 |
| 失败 → 拼装 | 点击「返回星球」：支付预配置初始飞船费用（进入失败态时即扣，资金不足记账，见 §2.6），获得该预配置初始飞船；本次宝藏全部销毁、不进行结算；失败时玩家现有模块与货物随飞船销毁（见 §2.6） |
| 失败 → 开始 | 点击「返回主菜单」 |

### 2.6 失败判定

**失败条件（已确认）**：

| 条件 | 说明 |
|------|------|
| 核心模块被摧毁 | 与现有 `ShipAssembly.IsOperational` 判定一致 |
| 能源储量归零 | 能源消耗归零即失败（现行实现为每日结算时不足 5） |
| 燃料归零 | 燃料消耗归零即失败 |

任一满足即触发失败：状态切换至失败的同时，从存档支付开发者指定的预配置初始飞船费用；资金不足时扣至 0，差额累加至欠账（欠账为兜底累计：资金不足自动垫付、可无限累计不设上限、不会为负；额度机制设计中）。本次宝藏全部销毁、不进行结算。玩家点击「返回星球」后获得该预配置初始飞船，进入拼装界面。失败判定仅在「飞行」状态执行。

> 核心模块提供基础动力、动力模块提升机动性（见 §2.8）；无论基础推力还是机动推力均消耗燃料，故燃料归零仍判失败。

### 2.7 返回结算

**结算触发（已确认）**：飞船进入星球范围后，按住确认键持续 5 秒读条；读条期间核心模块必须持续保持在星球范围内，否则视为被打断，读条重置。

**结算前揭示（已确认）**：读条完成触发结算时，若货舱仍存在未揭示物品，先进入整理界面（Tab 界面）逐格揭示，揭示完成后**自动退出整理界面**，再进入结算状态。若货舱无未揭示物品，直接进入结算状态。

**揭示与价格展示实现（已确认）**：结算前揭示**复用现有 `CargoRevealCoordinator` 逐格揭示流程**，仅将其与整理界面锁定的强依赖解耦（结算场景无可锁定界面）；价格展示作为独立环节，结算界面订阅 `CargoIdentifiedEvent`，按宝物稀有度查询价值表（S-1 策划填表）显示价格，`CargoRevealCompleted` 后累计金币总额。宝藏仅指宝物类别货物，能源/燃料/弹药不参与换算。

**结算内容**：进入结算状态时，本次宝藏（**含未鉴定货物**）按各自价值换算为金币，累加至全局金币；未鉴定货物在结算揭示的同时展示其价格。

**结算后配置保留**：玩家结算后再次出航时，拼装界面直接显示上一轮结算时的飞船配置与货物存储状态，可直接出航或继续修改；结算时玩家拥有的模块与货物同时进入模块库存与货物库存（宝藏不纳入），作为局外资源随存档保存。

### 2.8 已确认的规则决策

| 决策 | 内容 |
|------|------|
| 失败条件 | 核心模块被摧毁、能源储量归零、燃料归零（删除「动力模块全灭」一条） |
| 基础动力 | 核心模块提供基础动力，动力模块提升机动性；推进均消耗燃料，燃料归零仍判失败 |
| 结算触发 | 长按 5 秒读条，期间核心模块须持续在星球范围内，出范围打断并重置读条 |
| 首次游戏 | 首次游戏跳过拼装界面，直接以预设初始飞船进入飞行 |
| 存档模型 | 单存档；失败或成功（结算）后在同一存档内开始新一局；金币、模块库存、货物库存为存档内局外资源，跨局保留 |
| 结算宝藏范围 | 含未鉴定货物；结算揭示时同步展示价格 |
| 结算配置保留 | 结算后再次出航，拼装界面直接显示上一轮结算时的飞船配置与货物存储状态；模块与货物同时进入库存（见「模块/货物库存」决策） |
| 失败惩罚 | 进入失败态时即支付开发者指定的预配置初始飞船费用（取代固定扣 20）；资金不足扣至 0，差额计入欠账存档保留（欠账为兜底累计，见 §2.2）；点击「返回星球」后获得该预配置初始飞船；失败时玩家现有模块与货物随飞船销毁，不进入库存，预配置初始飞船自带的初始货物保留 |
| 模块/货物库存 | 结算时玩家拥有的模块与货物（宝藏不纳入，已换算为金币）分别入模块库存、货物库存，作为局外资源跨局保留；下一轮出航可从库存装载；局内被消耗者不返还；失败时不入库存 |
| 金币购买补给 | 拼装界面可用金币购买能源/燃料/弹药三类消耗品；模块不开放购买（模块走残骸链接获得，保持玩法来源唯一）；价格由策划填表，初期建议一轮正常出航宝藏换算的金币能购买约一轮消耗量的货物 |
| 飞船展示 | 结算/失败界面以镜头定格呈现飞船样貌：保持当前相机视角，UI 面板作为覆盖层叠加，复用 `ShipCameraFollower` 冻结能力 |
| 结算累加时机 | 进入结算状态时累加本次宝藏金币 |
| 结算前揭示 | 触发结算时若存在未揭示物品，先进入整理界面揭示，揭示完成后**自动退出**再进入结算；复用 `CargoRevealCoordinator` 揭示流程，价格订阅 `CargoIdentifiedEvent` 展示 |
| 预配置初始飞船 | 开发者预先配置飞船资产（模块布局、购买费用、初始货物如燃料/能源），程序直接使用该资产；失败后付费获得 |
| 出航校验 | 拼装结果至少包含核心模块才能出航；拼装界面点击「出航」时现场校验，未通过时弹提示文案（如「出航需要至少一个核心模块」）且不切换状态 |
| 世界重置 | 每局出航时世界重新生成（敌舰/残骸/小行星/星球位置等） |
| 首次标记翻转时机 | 进入结算或失败状态时置为 False |
| 主菜单入口 | 拼装状态提供「返回主菜单」；结算状态不提供 |
| Esc 仲裁 | 飞行/整理按 Esc 进入暂停；暂停按 Esc 回到暂停前的状态（飞行或整理） |
| 持久化方案 | JSON 服务层：`SaveData` 纯数据类（金币、欠账、模块库存、货物库存、首次标记、schemaVersion）+ 存档服务读写 `persistentDataPath/save.json`；启动 Load、关键时机 Save |

## 3. 现状实现（代码分析）

### 3.1 游戏状态机

开始与拼装状态已迁往独立场景（`StartMenu` / `ShipBuild`），`SpaceshipGameFlowController`（`Spaceship.Core` 命名空间）只管理出航会话内的状态，初始化或快照重建完成后直接进入探索：

| 状态 | 进入条件 | 允许操作 | 转移目标 |
|------|----------|----------|----------|
| `Expedition` | 会话初始化或快照重建完成 | 驾驶、开火、模块开关/拆除、货舱整理、星球交互 | `Paused` / `Organizing` / `Failure` |
| `Paused` | Esc 暂停（含整理中） | 继续游戏、返回休整站、退出游戏 | `Expedition` / 切换场景 |
| `Organizing` | Tab 打开货舱整理；结算前存在未揭示货物时强制打开 | 货舱整理、逐格揭示 | `Expedition` / `Settlement` |
| `Settlement` | 结算触发并确认 | 返回休整站（拼装）、返回主菜单 | 切换场景 |
| `Failure` | 生存条件失败 | 返回休整站、返回主菜单 | 切换场景 |

Settlement 与 Failure 通过 `SpaceshipExpeditionContext` 携带飞船快照与返回意图加载休整站场景。

> **休整站场景入口与测试模式**：`ShipBuild` 场景由其他场景加载（开始菜单「开始游戏」或结算/失败返回）时按存档结算——模块库存取自存档，放置扣库存、移除归还。直接启动该场景（如编辑器中单独运行 `ShipBuild` 场景）时进入**测试模式**：模块视为无限可用，放置不扣库存、移除不写存档，用于无代价自由改造飞船。判定入口为 `SpaceshipExpeditionContext.WorkshopTestMode`（由 `LoadRestStop()` 置位 `WorkshopLaunchedFromOtherScene` 推导）。

**代码位置**：`Assets/Scripts/Core/SpaceshipGameFlowController.cs`

### 3.2 出航循环

1. 玩家驾驶飞船在 500m×500m 世界探索（`SpaceshipWorldMap`）
2. 发现残骸 → 对齐链接位 → 自动链接并重新计算质量/质心（`ShipAssemblyInteractionController`）
3. 遭遇敌舰 → 战斗（`EnemyShipController`，状态机：Patrol → Tracking → Destroyed）
4. 货物管理 → Tab 键暂停游戏时间并放大镜头进入仓库整理（`CargoOrganizationController`）
5. 新星球按 F 降落 / 母星按 F 返航（`PlanetDestination`）

### 3.3 失败规则

由 `SpaceshipGameFlowController` 判定，全部进入 `Failure` 状态并冻结摄像机：

| 条件 | 检测位置 |
|------|----------|
| 核心模块被摧毁 | `ShipAssembly.IsDestroyed` |
| 所有动力模块被摧毁或拆除 | `ShipAssembly` 模块列表检查 |
| 燃料归零 | `ShipFuelConsumptionManager` |
| 每日结算时能源不足 5 | `TemporaryGameDirector.DayEnded 事件` |

### 3.4 时间系统

- `TemporaryGameDirector` 管理 5 分钟日循环
- 每日消耗 5 能源（通过 `ShipFoodConsumptionManager`）
- 日结束时广播 `DayEnded` 事件

### 3.5 关卡初始化流程

`LevelContentInitializationController` 执行 5 阶段初始化：

1. 随机模块槽位填充（`RandomModuleSlot`）
2. 货物初始化（`ShipCargoHold`）

## 4. 目标与现状差异对照

| 维度 | 现状（4 态） | 目标（7 态） | 对应改动 |
|------|--------------|--------------|----------|
| 状态数量 | Title / Expedition / ExpeditionComplete / Failure | 开始 / 拼装 / 飞行 / 暂停 / 整理 / 结算 / 失败 | 新增拼装、暂停；整理并入状态机；ExpeditionComplete 升级为结算 |
| 拼装界面 | 无独立拼装状态，拼装发生在飞行中（残骸链接、钩爪拆装） | 独立拼装状态与拼装界面 | 新增拼装界面系统，可选复用 `ShipWorkshopModeController` |
| 失败条件 | 核心毁 / 动力全灭 / 燃料归零 / 每日能源不足 5 | 核心毁 / 能源归零 / 燃料归零 | 删除动力全灭判定；能源判定从严（归零即失败）；燃料归零保留为失败条件 |
| 动力模型 | 动力模块决定推力，模块全毁则飞船坠毁 | 核心提供基础动力，动力模块提升机动性 | 调整 `ShipMotionController` 推力计算与 `ShipAssembly` 摧毁逻辑 |
| 结算触发 | 按 F 手动降落/返航 → 完成面板 | 进入范围 + 长按 5 秒读条 + 核心在范围内 → 结算界面 | 改造 `PlanetDestination`，新增结算读条交互 |
| 金币系统 | 无 | 存档内局外资源，宝藏换算、结算展示、跨局/跨会话持久化；拼装界面金币购买补给流出 | 新增金币数据、价值换算、购买补给、存档服务 |
| 模块/货物库存 | 无（货物仅飞行中拾取，模块仅残骸链接） | 存档内局外资源：结算时入库、下一轮携带、失败时销毁 | 新增库存数据结构与存档字段，拼装界面列表读取库存 |
| 出航校验 | 无（直接出航） | 至少包含核心模块才能出航，未通过弹提示不切换 | 拼装界面出航按钮增加现场校验 |
| 首次游戏 | 无此概念 | 首次跳过拼装，直接进入飞行 | 新增首次标记与预设初始飞船加载 |
| 整理系统 | `CargoOrganizationController` 独立管理 Tab/Esc、时间缩放 | 状态机内的「整理」状态 | 并入状态机，与 `EnterState` 的 `Time.timeScale` 控制统一协调 |
| UI 归属 | `SpaceshipGameFlowController.OnGUI` 内嵌全部界面 | 各状态独立 View，订阅 `GameStateChangedEvent` | UI 拆出控制器，控制器仅保留状态入口与跨系统协调 |
