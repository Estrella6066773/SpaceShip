## 1. 概述

随机模块是一种**特殊的模块配置方式**：在残骸组的某个模块位置上放置一个**占位符**，由关卡策划在 Inspector 中配置候选池与权重；关卡加载时，管理器按权重随机抽取一个具体的模块类型实例化，替换掉占位符。

设计目标：

- 策划在不写代码、不改预制体的情况下，为残骸组配置「可能是 A、可能是 B、也可能什么都没有」的模块位置
- 权重为任意正数，不要求归一化，系统自动按比例计算抽取概率，便于策划直接写直觉数值
- 随机只发生在关卡加载时一次，替换完成后该位置即为普通模块，运行时不再保留随机逻辑
- 残骸组的位置、布局、链接结构由策划在场景中手动摆放，管理器只负责模块内容的随机替换

## 2. 随机模块占位符（RandomModuleSlot）

### 2.1 对象描述

占位符是一个挂在残骸组某个模块位置上的组件。它**本身不是模块**，只声明「这个位置应该有一个模块，但具体是什么，由候选池决定」。关卡加载时由管理器解析，此后该位置由实例化出的具体模块接管。

### 2.2 数据

| 字段 | 规则 |
|------|------|
| 网格坐标 | 该占位符在残骸网格中的整数坐标；实例化的模块会写入此坐标 |
| 候选池 | 一个列表，每项包含一个模块类型和一个权重值 |

候选池每项（`RandomModuleCandidate`）：

| 字段 | 规则 |
|------|------|
| 模块类型 | 引用一个模块 Prefab（须包含 `ShipModule` 组件并配置好 `ModuleDefinition`）；抽中时实例化此 Prefab |
| 朝向 | 该候选抽中后模块在船体中的装配朝向：`0` = 随机朝向（从四个朝向中随机抽取，与种子共享同一随机源，可复现）；`1`/`2`/`3`/`4` = 固定朝向前/右/后/左 |
| 权重 | 任意正数，**不要求**总和等于 1 或 100；实际概率 = 该项权重 ÷ 候选池总权重 |

> **「模块类型」的实现口径**：实现中候选引用的是**模块 Prefab** 而非枚举/类名，因此支持同类模块的不同变体（例如不同朝向、不同强度配置的同种动力模块）。
>
> **「空置」即基础模块**：不设置独立的「空模块」勾选字段。想要某位置有「不生成模块」的概率时，在候选池中添加一个**基础模块（`ModuleKind.Empty`）Prefab** 作为候选即可，抽中它时该位置保持空缺。候选池为空（不添加任何模块）则此位置**永不生成**。空引用（未拖入 Prefab）的候选项同样按空置处理，但编辑器会提示。

### 2.3 权重与概率

- 权重为任意正数，系统自动按比例计算各候选的抽取概率
- 权重为 0 的候选不参与抽取（配置时应避免，编辑器给出提示）
- 候选池必须至少包含一个权重大于 0 的候选，否则该位置配置非法
- 同一模块类型在候选池中重复出现时允许（权重叠加生效），但编辑器给出提示

### 2.4 示例

策划配置三个候选：前向动力模块（权重 2.0）、基础模块（空置，权重 3.0）、固定式机炮（权重 0.5）。总权重 = 5.5。

- 前向动力模块的抽取概率 = 2.0 / 5.5
- 空置（不生成）的抽取概率 = 3.0 / 5.5
- 固定式机炮的抽取概率 = 0.5 / 5.5

## 3. 模块随机替换管理器（SalvageRandomizationManager）

### 3.1 对象描述

负责在关卡加载时，将残骸组中配置为随机模块占位符的位置替换为具体的模块类型。残骸组的位置、布局、链接结构由关卡策划在 Unity 场景中手动摆放，本管理器只处理模块内容的随机替换。

### 3.2 数据

| 字段 | 规则 |
|------|------|
| 随机种子 | 固定种子（默认 `20260728`）；相同场景配置与种子应产生相同结果 |
| 残骸组 | 本关所有需要解析随机模块的残骸组列表；每组含残骸根对象与按顺序解析的槽位列表 |

### 3.3 替换时机

关卡加载时执行，是整个关卡内容初始化的**第一阶段**（`LevelContentInitializationController`，早于货物初始化、飞船注册、导演启动与视野激活）。

管理器具备**自驱能力**：即使场景没有 `LevelContentInitializationController` 引用它，管理器也会在 `Start()` 时自行调用 `InitializeRandomModules` 完成解析（幂等保护，两路调用不会重复解析）。若未手工配置任何残骸组，管理器还会**自动收集**场景中所有「带随机槽位且位于 `ShipAssembly` 下的槽位」组成残骸组解析，策划只需把残骸（含槽位）放入场景即可。

### 3.4 替换流程

1. 确定该残骸的**固定模块**：残骸下不属于任何随机占位符层级的活动模块。随机占位符是占位符，其子层级内的模块一律不视为固定模块
2. 以固定模块与阵营 `Derelict` 配置残骸
3. 按配置顺序，对每个槽位逐一执行随机抽取并替换：
   - 收集有效候选（权重 > 0，且为空置或引用了 Prefab）
   - 将所有候选的权重相加得到总权重
   - 在 0 到总权重之间随机取一个值，落到哪个候选的累计区间内，就选哪个候选
   - 抽中空置（基础模块 / 空引用）→ 该位置保持空缺；抽中普通候选 → 实例化对应 Prefab
4. 全部槽位解析完成后重建残骸链接
5. 结算残骸货物（见 §5）

### 3.5 替换后处理

- 替换完成后，占位符不再保留随机逻辑（置为已解析状态），实例化出的模块即为该位置的**普通模块**
- 实例化后先尝试按占位符配置的方向与相邻模块建立链接；若无法链接，**依次旋转四个方向**再试
- 四个方向均无法链接时**销毁**实例，该位置保持空缺

### 3.6 随机种子与可复现性

随机抽取使用**固定随机种子**：管理器持有一个 `System.Random(种子)`，按残骸组列表顺序依次解析。相同场景配置与相同种子必然产生相同结果，便于回放与调试。

## 4. 配置校验（编辑器）

| 校验级别 | 内容 |
|----------|------|
| 错误 | 候选池为空，或没有任意一个有效候选（权重 > 0，且为空置或引用了 Prefab） |
| 警告 | 存在权重为 0 的候选（不参与抽取）；候选引用了场景中的模块实例（应引用 Assets 下的模块 Prefab）；候选池存在重复模块类型（确认权重叠加符合预期）；候选为空引用（按空置处理，确认是否符合预期） |
| 警告（链接兼容性） | 候选放在槽位网格坐标时，**四个旋转方向都无法与相邻固定模块建立链接**（双方相对方向链接面开启才可链接）。此类候选抽中后将被销毁、该位置保持空缺，属于配置层面的布局隐患，编辑器在菜单统一验证中提示 |

链接兼容性判定复用 `RandomModuleSlot.GetLinkCompatibilityWarnings`（公共查询）：遍历槽位四周的固定模块，模拟候选放置并尝试 4 个旋转方向，只要存在一个方向能与任一相邻固定模块链接即视为兼容。该查询同时被验收脚本复用，避免逻辑重复。

提供两类入口：

- 选中槽位时，Inspector 面板实时显示校验结果
- 菜单 `Spaceship / 飞船 / 验证随机模块配置`：遍历场景中所有管理器与槽位统一检查，并报告未被任何管理器引用的孤立槽位、以及链接不兼容的候选

## 5. 与货物系统的衔接

残骸中若解析出储存模块（预放置或随机抽中），由管理器在解析完成后统一结算货物：

- 确保残骸挂载货舱
- 把残骸上各储存模块的格子配置解析为**未鉴定**货物（阵营 `Derelict` 判定）
- 没有配置格子配置的模块保持空仓

该衔接保证随机抽出的储存模块同样进入「打捞 → 鉴定 → 结算」核心循环。详见 [《储存模块货物生成》](./储存模块.md)。

## 7. 验收标准

1. 策划可在残骸组某位置摆放随机模块占位符，在 Inspector 中配置候选池与权重，无需写代码
2. 权重为任意正数即可，总和不为 1 或 100 时抽取概率仍按比例正确
3. 空置候选（基础模块 / 空引用）被抽中时，该位置不实例化任何模块
4. 关卡加载时所有占位符一次性解析完成，解析后不再保留随机逻辑
5. 实例化后的模块与相邻模块自动建立链接；无法链接时依次旋转四个方向尝试
6. 四个方向均无法链接时销毁实例，该位置保持空缺
7. 相同场景配置与相同种子下，残骸模块构成完全一致（可复现）
8. 非法配置（候选池为空 / 无有效候选）在编辑器校验与运行时初始化中均报错
9. 抽中的储存模块携带未鉴定货物，进入「打捞 → 鉴定 → 结算」核心循环

## 8. 使用指南（策划配置）

面向关卡策划：如何在 Unity 场景中配置一套「带随机模块的残骸组」。**全程在 Inspector 操作，无需写代码。**

### 8.1 场景装配总览

一个完整的配置在场景中由四部分构成：

```
场景根
├── 启动系统（空对象，统一归拢所有启动/系统脚本，便于寻找与筛选）
│   ├── ShipSceneRegistry                 ← 飞船场景名册（注册玩家、敌舰、残骸）
│   ├── 模块目录（ModulePrefabCatalog）    ← 提供候选池可引用的模块 Prefab
│   ├── 随机替换管理器（SalvageRandomizationManager） ← 系统组件：解析残骸内嵌随机槽位（放入即生成）
│   ├── 关卡内容初始化（LevelContentInitializationController） ← 可选接入，触发第一阶段解析
│   └── …（事件系统 / 界面系统 / 可见性系统等其他启动组件）
└── 世界（残骸、敌舰、星球等玩法对象）
    ├── 残骸生成器（SalvageGenerator）    ← 场景级生成工具：为该场景生成某艘船破碎后的残骸
    │   └── 画布与逐格参数（SalvageGridCell） ← 候选池样式同 RandomModuleSlot
    └── …（由生成器运行时创建的残骸碎片也归入世界）
```

> **层级约定**：所有启动/系统类脚本（场景名册、游戏流程、游戏配置、事件系统、界面系统、可见性系统、模块目录、随机替换管理器等）统一放在空的「启动系统」物体下，各自一个子物体，方便在 Hierarchy 中寻找与筛选；残骸、敌舰、玩家飞船等玩法对象放在「世界」下。
>
> **残骸生成器不属于启动系统**：它不是一个全局工厂或管理器，而是**具体用于指定场景的生成工具**，是场景内容的一部分，挂在「世界」下，为该场景生成残骸。
>
> **随机替换管理器属于启动系统**：它是系统组件（解析残骸内嵌的随机槽位），与场景级生成器**并存不冲突**——生成器负责「从整船蓝图生成碎片化残骸」，管理器负责「解析场景里残骸上已摆放的随机槽位」。
>
> **关键概念**：残骸生成器本身**不是残骸**，它代表当前场景中一艘完整船的生成蓝图（画布 + 逐格参数）。游戏开始时逐格抽取、按端口连接、划分独立结构，再为每个结构生成一个残骸对象。旧「残骸内嵌随机槽位」的装配方式已被取代，见 §9。

### 8.2 配置步骤

**第 1 步：摆放残骸的固定模块**

在残骸根对象（含 `ShipAssembly`）下，按通常方式摆放核心模块等**固定模块**。这些模块不参与随机，是残骸的骨架。

**第 2 步：放置随机模块占位符**

在需要随机化的网格位置创建一个**空 GameObject**（位置对齐整数网格），挂上 `RandomModuleSlot` 组件。

**第 3 步：填写占位符的网格坐标**

在 Inspector 的「网格坐标」中填入该位置在残骸网格里的整数坐标（如 `(1, 0)`）。实例化的模块会写入这个坐标。

**第 4 步：配置候选池**

在「候选池」列表中逐项添加候选，每项：

| 字段 | 怎么填 |
|------|--------|
| 模块类型 | 从 `Assets/Prefabs/Modules/` 拖入一个模块 Prefab（如 `动力模块.prefab`、`固定式机炮.prefab`）；拖入 `基础模块.prefab`（Kind=Empty）表示**空置**——抽中时这里什么都不放 |
| 权重 | 任意正数，如 2.0 / 3.0 / 0.5；不要求总和为 1 或 100 |

> 示例：三个候选「动力模块 权重 2.0」「基础模块（空置）权重 3.0」「固定式机炮 权重 0.5」，总权重 5.5，动力模块抽取概率 2.0/5.5，空置概率 3.0/5.5。候选池为空则此位置永不生成。

**第 5 步：创建随机替换管理器**

在场景中创建一个空对象，挂上 `SalvageRandomizationManager`。在其「残骸组」列表中新增一项（`SalvageRandomizationGroup`）：

- **残骸**：拖入残骸根对象（`ShipAssembly`）
- **随机槽位**：把该残骸下的 `RandomModuleSlot` 按解析顺序加入列表

一个管理器可挂多个残骸组；一个残骸组可含多个槽位。

> **省事捷径**：残骸组可以不填。管理器在 `Start()` 时若发现残骸组为空，会自动把场景中所有带随机槽位且位于 `ShipAssembly` 下的槽位收集为残骸组解析。因此策划只需「放入残骸 → 放入管理器 → 进游戏」，无需手工引用槽位。

**第 6 步：接入关卡初始化（可选）**

在场景的 `LevelContentInitializationController`（通常挂在「游戏流程」下）中，把「随机模块管理器」引用指向刚创建的 `SalvageRandomizationManager`。关卡加载时即会自动完成解析。

> 该步为**可选**：`LevelContentInitializationController` 不引用管理器时，管理器也会在游戏开始（`Start`）自动解析，两路调用有幂等保护不会重复解析。测试场景可完全不接入初始化控制器。

### 8.3 校验

配置过程中随时可校验：

- **Inspector 实时校验**：选中任意 `RandomModuleSlot`，面板底部显示配置错误 / 警告 / 有效提示
- **菜单统一验证**：`Spaceship / 飞船 / 验证随机模块配置`——遍历场景所有管理器与槽位，报告错误、警告、未被引用的孤立槽位、以及链接不兼容的候选

### 8.4 验证运行结果

- **正式关卡**：直接进 PlayMode，`LevelContentInitializationController` 会在加载时自动解析
- **测试场景**：用探针脚本在场景摆好残骸组后进 PlayMode，执行菜单 `Spaceship / 飞船 / 解析场景随机模块并观察（运行时）`，控制台打印各槽位解析结果
- **回归验收**：菜单 `Spaceship / 飞船 / 验证随机模块（运行时）`，跑完整 8 项自动化用例

### 8.5 注意事项

| 事项 | 说明 |
|------|------|
| 固定模块识别 | 残骸下**不属于任何随机占位符层级**的活动模块才被视为固定模块；随机槽位的子层级内的模块一律不算 |
| 候选引用 | 候选应引用 `Assets/Prefabs/Modules/` 下的模块 **Prefab**，不要引用场景中已摆放的模块实例 |
| 权重与空置 | 权重为 0 的候选不参与抽取；空置通过引用「基础模块」Prefab（Kind=Empty）表达，空引用按空置处理 |
| 链接兼容性 | 若候选在槽位处四个旋转方向都无法与相邻固定模块链接，抽中后会被销毁、位置空缺。菜单统一验证会给出这类警告，配置后请务必跑一遍 |
| 可复现性 | 固定种子（默认 `20260728`）保证相同场景配置得到相同结果；改种子可调整整关随机结果 |
| 顺序敏感 | 同一残骸组内槽位按列表顺序解析，随机种子消耗顺序固定 |

### 8.6 残骸生成器（快速布置）

自 2026-08-05 起，随机模块的装配方式从「残骸内嵌槽位 + 管理器」升级为「**残骸生成器**」：生成器是一个**具体用于指定场景的生成工具**——它代表该场景中某一艘完整船的生成蓝图（画布 + 逐格参数），游戏开始时逐格抽取、按端口连接、划分独立结构，再为每个结构生成一个残骸对象。策划只需在场景「世界」下配置一份生成器，即可为当前场景批量生成若干残骸碎片。

**场景装配**：

1. 在「世界」下创建空物体，挂 `SalvageGenerator`（如 `残骸生成器（完整船）`）；
2. 配置「画布范围」（整数网格范围，如 `起点(-2,-2) 尺寸(5,5)`）；
3. 配置「逐格参数」：右键生成器 → `按画布生成空白格子列表` 一键铺满画布，再逐格添加候选池（样式与旧随机槽位候选池一致：模块 Prefab + 权重；空置引用 `基础模块.prefab`）；
4. 进 PlayMode：`Start()` 自动生成碎片化残骸；生成物为运行时创建的残骸碎片对象（`ShipAssembly` + `ShipCargoHold`，阵营 `Derelict`）。

详细设计与验证见 §9。原「标准残骸预制体」（内嵌 20 槽位 + 管理器）的装配方式已停用，场景中的「标准残骸」已清理为干净残骸（仅 `ShipAssembly` + `Rigidbody2D` + `ShipCargoHold`），不再内置任何随机槽位。

## 9. 残骸生成器（整船蓝图 → 碎片化残骸）

> 2026-08-05 新增，为现行装配方式。取代旧「随机模块替换管理器」；候选池、权重、固定种子可复现等核心概念沿用 §1–§2。

对应代码：`Assets/Scripts/Gameplay/World/SalvageGenerator.cs`

### 9.1 设计概述

**残骸生成器是一个具体用于指定场景的生成工具**：它代表当前场景中某一艘完整船的生成蓝图，而不是一个已生成的残骸单位，也不是全局工厂或管理器。生成器指定一张**画布**，逐格配置**生成参数**；游戏开始时：

1. 逐格按权重抽取，确定哪些格子生成哪个模块；
2. 尝试把抽取出的模块**连接**起来：相邻两模块的**链接端口都可用**才可连接，任一方不可用则不可连接；
3. 按连接关系划分出若干个**独立结构**（连通分量）；
4. 为每个独立结构**生成一个对应的残骸对象**（`ShipAssembly` + `ShipCargoHold`，阵营 `Derelict`）。

因此一艘配置得当的「完整船」在随机缺失模块后会破碎成多块互不相连的残骸，各碎片落在原船网格位置，直接进入打捞流程。**生成器本身不是残骸；它为指定场景生成残骸。**

**定位与设计约束**：残骸生成器是**场景级生成工具**，不是工厂、也不是管理器：

- **属于场景内容**：挂在场景「世界」下，为该场景生成内容，只服务这个场景；
- **不主动扫描系统**：事件源（流程事件源、模块事件源）由场景装配期 `[SerializeField]` 注入，生成器不自己去场景里找其他系统；仅当未注入时回退查找以保证事件不丢失；
- **无全局状态**：缺省世界规则使用本实例私有的默认规则，不持有全局单例；
- **只生成一次**：`Generate()` 幂等，本场景只生成一次（`Start` 自动触发）；编辑器调整参数后可手动「重新生成」预览；
- **先确定、后生成**：抽取阶段只在数据层确定「哪个格子生成哪个模块」，连接分析同样基于模块定义完成，直到分组确定后才实例化模块、逐结构生成残骸——生成器不临时持有场景中的模块产物。

### 9.2 数据

**画布（`CanvasRect`）**：整数网格范围（起点 + 尺寸），定义生成器覆盖的船体区域。

**逐格参数（`SalvageGridCell`）**：画布内一个格子的配置，候选池字段与 §2.2 旧随机槽位候选池一致：

| 配置 | 行为 |
|------|------|
| 候选池为空 | 该格视为「不生成内容」，**永不生成**模块 |
| 候选池含「空置」候选 | 添加基础模块（`ModuleKind.Empty`）Prefab 作为候选，抽中时该格留空，即存在**不生成模块的概率**（概率 = 空置权重 ÷ 总权重） |
| 候选池含模块 Prefab 候选 | 按权重随机抽取，抽中哪个生成哪个 |

**生成规则**：

- **是否使用固定随机种子（`useRandomSeed`）**：勾选（默认）时使用下方 `randomSeed` 作为固定种子，相同配置 + 相同种子必然产生相同结果，便于回放与调试；不勾选则每次生成随机（每次进游戏结果不同）
- **随机种子（`randomSeed`）**：固定种子（默认 `20260728`），控制本生成器的全部随机抽取（模块类型、空置、朝向）；仅在勾选「是否使用固定随机种子」时生效
- **世界规则**：生成的残骸使用的 `SpaceshipWorldRules`（留空时使用运行时默认规则）

### 9.3 生成流程

1. **逐格抽取（数据层确定模块）**：按列表顺序，对每个格子从其候选池中抽取一个候选（权重区间判定，同 §2.3），得到「格子 → 模块 Prefab + 装配朝向」的确定结果，**不实例化**：
   - 候选池为空 / 抽中空置（基础模块）→ 该格不生成；
   - 抽中模块 Prefab → 记录该格生成该模块及其朝向：候选指定了固定朝向则用指定值，否则从四个朝向中随机抽取；
2. **连接判定（数据层）**：对任意上下左右相邻两格已确定的模块，双方在相对装配方向上的**链接端口都开启**才判定为可连接（与 `ShipAssembly.CanLink` 判定一致；模块按候选朝向旋转后，其定义方向的链接面随旋转换算到装配方向）；
3. **连通分组**：以「可连接」为边做广度优先遍历，把已确定的模块划分成若干独立连通结构；
4. **逐结构生成残骸**：此时才实例化模块——为每个结构创建残骸对象，模块按原网格坐标归入对应残骸，重建链接、结算货舱（`ShipCargoHold`）、注册进 `ShipSceneRegistry`；残骸根定位在生成器位置，因此各碎片自然落在原船网格位置。

### 9.4 场景装配（策划配置）

残骸生成器是**场景级装配工具**：它属于场景内容，挂在「世界」下，为该场景生成残骸；**不是**「启动系统」下的全局系统组件（工厂/管理器）。

1. 在「世界」下创建空物体，挂 `SalvageGenerator`（如 `残骸生成器（完整船）`），放在船体网格对应的世界位置；
2. 配置「画布范围」：输入船体覆盖的整数网格范围（如 `起点(-2,-2) 尺寸(5,5)`）；
3. 配置「逐格参数」：
   - 右键生成器 → `按画布生成空白格子列表` 可一键铺满画布（全部为空候选池），再逐格添加候选池；
   - 需要「此处可能不出模块」→ 添加一个「基础模块」（空置）候选（权重即空缺概率）；
   - 需要「此处永不生成」→ 保持候选池为空；
   - 需要指定具体模块 → 从 `Assets/Prefabs/Modules/` 拖入模块 Prefab 并配置权重；如需固定朝向，把该候选的「朝向」设为 1~4（0 = 随机朝向，默认）；
4. （可选）拖入「世界规则」；在「场景装配」下拖入流程事件源与模块事件源（均位于「启动系统 → 事件系统」下）；`generateOnStart` 默认勾选，进游戏自动生成；
   - 想每次进游戏结果不同 → 取消勾选「是否使用固定随机种子」；想复现/调试某批结果 → 保持勾选并记录 `randomSeed` 的值；
5. 进 PlayMode：`Start()` 自动生成一次碎片化残骸（幂等，不会重复生成）；编辑器调整参数后可右键生成器 → `重新生成残骸（清空后重建）` 预览效果。

### 9.5 验证（2026-08-05，场景 `ShipTest`）

配置画布 5×5（`起点(-2,-2)`），6 格参数：`(0,0)` 动力、`(0,1)` 电磁盾、`(0,-1)` 储存、`(1,0)` 机炮(1)/空置(2)、`(-1,0)` 雷达(1)/空置(1)、孤立格 `(2,2)` 动力。种子 `20260728`，进 PlayMode 结果：

```
[残骸生成器] 抽取模块 4 个，按链接端口连接后划分为 3 个独立结构
残骸碎片 1：动力模块 + 电磁盾（端口兼容，连成一体）
残骸碎片 2：储存模块（与动力模块端口不兼容 → 独立结构）
残骸碎片 3：动力模块（画布右上角孤立格 → 独立结构）
```

雷达、机炮两格抽中「空置」（基础模块）留空，覆盖「空置概率不生成」路径；储存模块端口不兼容覆盖「任一方不可用则不可连接」路径；孤立格覆盖「独立结构单独成块」路径；三块残骸均落在生成器位置（原船网格位置）。

### 9.6 与旧机制的关系

- `RandomModuleSlot` / `SalvageRandomizationManager`（§2–§7）描述的是「残骸内嵌槽位 + 管理器解析」机制：**残骸预制体不再内置随机槽位与管理器**（2026-08-05 已从场景「标准残骸」清理，避免把垃圾塞回残骸）。
- **管理器并未废弃**：`SalvageRandomizationManager` 仍作为**系统组件收整在「启动系统」下**（随机替换管理器），负责解析场景里残骸上已摆放的随机槽位（`Start` 自驱 + 未配置残骸组时自动收集场景槽位），与场景级生成器**并存**：
  - 残骸生成器（「世界」）：从整船蓝图生成碎片化残骸；
  - 随机替换管理器（「启动系统」）：解析残骸内嵌的随机槽位。
- 候选池、权重、空置（基础模块类型）、朝向、固定种子可复现等**核心概念**由 `RandomModuleCandidate` 继续承载，被生成器的逐格参数复用。
