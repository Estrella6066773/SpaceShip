# 储存模块货物生成（特性设计）

> 本地设计主本 | 状态：已实现 | 更新：2026-08-04
>
> 对应代码：`Assets/Scripts/DataRuntime/CargoSlotConfiguration.cs`、`Assets/Scripts/Gameplay/Ships/Cargo/StorageModuleCargoConfiguration.cs`、`Assets/Scripts/Core/LevelContentInitializationController.cs`

---

## 1. 概述

储存模块用于储存食物、燃料、弹药、货物等物资。货物的初始内容可按**格子**独立配置，每个格子选择两种模式之一：**指定货物**或**随机货物**。

设计目标：

- 策划可在不写代码的情况下，为敌舰、残骸的储存模块配置固定或随机的初始物资
- 随机只发生在生成期一次，运行时全部为确定性货物，兼容残骸转移、鉴定与结算流程
- 支持同模块内不同格子混用两种模式

---

## 2. 格子结构

| 项目 | 规则 |
|------|------|
| 内部存储格子 | 2 × 2，共 4 格 |
| 格位编号 | SlotIndex 0～3（左上、右上、左下、右下） |
| 每格容量上限 | 每格同类最多 10 个（`UnitsPerSlot = 10`） |
| 空槽 | 指定模式货物留空或数量为 0，即视为空槽 |

> **「同类」判定**：合并与堆叠只发生在**同一具体货物定义**（`CargoItemDefinition`）之间。不同具体物品即使同属一个类别（例如两个不同的普通宝藏），也各自独立占格、互不合并。

---

## 3. 每格配置模式（二选一）

### 3.1 指定货物

| 字段 | 规则 |
|------|------|
| 货物类型 | 食物 / 燃料 / 弹药 / 宝藏 |
| 数量 | 该格存放的货物数量，范围 0～10，0 表示空槽 |

### 3.2 随机货物（候选池）

| 字段 | 规则 |
|------|------|
| 候选池 | 每项包含一个货物类型、一个数量、一个权重值 |
| 权重 | 任意正数，**不要求**总和等于 1 或 100；实际概率 = 该项权重 ÷ 候选池总权重 |
| 空槽候选 | 某候选不填货物（留空），表示抽中该候选时该格为空 |
| 数量 | 候选数量为固定值，范围为 1～10；如需数量随机，请以多个候选项分别列出 |

**校验规则**：

- 权重为 0 的候选视为无效，不参与抽取（配置时应避免）
- 随机模式格子的候选池必须至少包含一个权重大于 0 的候选，否则该配置非法
- 候选池中同一货物重复出现时允许（权重叠加），但编辑器给出提示

---

## 4. 混用规则

同一个储存模块内，不同格子可以使用不同配置方式：部分格子指定、部分格子随机。每格配置互相独立，不受其他格子影响。

---

## 5. 货物填充

| 项目 | 规则 |
|------|------|
| 填充时机 | 关卡加载时（飞船初始化货舱阶段） |
| 随机抽取 | 对配置为随机模式的格子，按权重随机抽取货物类型与数量并写入 |
| 一次性 | 随机结果**在本次运行中只结算一次**；填充完成后该格不再保留随机逻辑 |

---

## 6. 鉴定状态（补充条目 2026-08-04）

货物初始的鉴定状态不写在格子配置里，而是由**飞船阵营**决定：

| 飞船阵营 | 初始鉴定状态 |
|----------|--------------|
| 玩家飞船 | 已鉴定（`Identified`） |
| 敌舰 / 残骸 | 未鉴定（`Unidentified`） |

未鉴定货物进入玩家货舱后，会触发货物揭示流程（`CargoRevealCoordinator` 逐格鉴定、史诗货物强制打开整理界面）。随机宝藏以未鉴定状态入仓，**不会**绕过「打捞 → 鉴定 → 结算」的核心循环。

---

## 7. 销毁与货物去向（补充条目 2026-08-04）

「销毁时货物一并销毁」仅指**模块被击毁**这一条路径。模块离开飞船时有三种去向，行为不同：

| 场景 | 货物去向 |
|------|----------|
| 模块被击毁（HP 归零） | 内部货物一并销毁 |
| 模块被钩爪拆除 / 断裂脱落 | 货物随模块保留，成为可打捞残骸 |
| 整船坠毁 | 货物保留在残骸中，可供打捞 |

> 说明：拆除、断裂、残骸打捞是核心循环「打捞战争遗留资源」的载体，因此货物必须保留。

---

## 8. 配置层级与存放位置（补充条目 2026-08-04）

格子配置挂在**储存模块对象**上（`StorageModuleCargoConfiguration`），而非飞船蓝图级。这意味着：

- 每个「储存模块」预制体自带自己的格子配置
- 同一模块预制体被多艘船复用时，配置被共享；如需船与船之间的差异，应使用不同的模块预制体变体，或依赖随机种子（见 §9）

蓝图级的 `ShipInitialCargoPlacement`（指定类型 + 数量 + 目标模块）仍保留，作为**兼容的补充机制**，与新格子配置并存（先填格子配置，再叠加蓝图初始货物）。两者叠加超出容量时以失败报错。

> **现状（2026-08-04 更新）**：模块预制体 `Assets/Prefabs/Modules/储存模块.prefab` 已挂载 `StorageModuleCargoConfiguration` 并配置混用格子（随机 + 指定），货物定义资产（食物/燃料/弹药/宝藏）已就位。工坊拼装该模块或关卡中的随机残骸模块会按配置生成初始货物。现有 Blueprint 飞船（玩家船、敌舰）的内联储存模块仍使用旧的 `ShipInitialCargoPlacement`，作为 §8 允许的兼容补充机制与新格子配置并存。

## 9. 随机种子与可复现性（补充条目 2026-08-04）

随机抽取使用**固定随机种子**，保证相同场景配置与种子产生相同结果：

- 基础种子：关卡内容初始化控制器上的 `cargoRandomSeed`（默认 `20260728`）
- 每艘船：`基础种子 + 船序号 × 7919`
- 每个储存模块：`船种子 + 模块序号 × 397`

> **修复记录（2026-08-04 补充）**：
>
> - 种子统一为纯序号公式：每艘船 `基础种子 + 船序号 × 7919`、每个储存模块 `船种子 + 模块序号 × 397`。Prefab 直挂路径（`ShipPrefabRuntimeInstaller.InitializeCargo`）与关卡路径（`LevelContentInitializationController.InitializeShipCargo`）一致，已通过三次同种子重复解析验证。
> - **种子已接入实际运行路径**：此前 `LevelContentInitializationController` 与 `SalvageRandomizationManager` 未挂载到任何场景，ShipTest 的 `AssemblyPlaytestBootstrap` 与 `SpaceshipWorldMap` 混用 `UnityEngine.Random.Range` 导致每次进入场景结果不同。现基础种子由 `SpaceshipGameConfiguration.CargoRandomSeed` 提供，经 `AssemblyPlaytestBootstrap` 传入 `SpaceshipWorldMap.Configure`（世界地图内部所有随机已统一改为固定 `System.Random`，含小行星、残骸模块构成、货物解析）与固定残骸场（每个模块 `基础种子 + 模块序号 × 397`）。已通过 PlayMode 验收测试验证同种子两次构建残骸模块构成与货物完全一致。
> - **解析原子性**：`ResolveInto` 先解析全部四格、再校验目标模块货舱为空，最后统一写入；任一格非法或目标已占时整体失败，不留部分残留、不覆盖既有货物。
> - **`resolved` 已序列化**：避免场景序列化已填货物后重载重复解析误判配置错误。

## 10. 边界与异常

| 场景 | 行为 |
|------|------|
| 随机模式候选池为空 | 配置非法，初始化失败并报错 |
| 指定模式货物留空或数量 0 | 视为空槽，不写入任何货物 |
| 格子配置与蓝图初始货物叠加超容量 | 初始化失败并报错；并存时给出警告提示 |
| 同一 Prefab 同时带格子配置与蓝图初始库存 | 编辑器校验器给出并存警告，提醒确认为有意配置 |
| 储存模块对象上未挂货物配置 | 该模块无初始货物，不报错 |

## 12. 验收标准

1. 储存模块 2 × 2 格子，每格可独立配置为指定或随机模式
2. 指定模式按「货物类型 + 数量」写入；随机模式按权重抽取，权重不要求归一化
3. 同模块内可混用两种模式
4. 关卡加载时随机格一次性结算，运行时不再保留随机逻辑
5. 玩家船初始货物已鉴定；敌舰/残骸为未鉴定，进入揭示流程
6. 模块被击毁时货物销毁；拆除 / 断裂 / 整船坠毁时货物保留在残骸中
7. 相同种子下随机结果可复现（已验收：PlayMode 测试「相同种子_两次构建_残骸模块与货物完全一致」通过）
8. 非法配置（随机池为空）在编辑器校验和运行时初始化时均报错；解析失败整体回滚不留残留
9. 随机残骸可生成储存模块并携带未鉴定货物；玩家打捞后货物按未鉴定状态转入玩家货舱并进入揭示流程（已验收：PlayMode 实测 8 组残骸中 5 组含储存模块且全部带货物，打捞转移后新增货物均为未鉴定）

## 13. 货物系统设定落库与实现状态（补充条目 2026-08-04）

> 依据玩家提供的《货物系统》设定整理。设定全文见文档库，本节收敛与代码实现相关的关键点与验收状态。

### 13.1 揭示状态

- 未鉴定：货物生成时的初始状态，内容对玩家不可见，等待首次被查看。
- 已鉴定：货物被玩家首次查看后的状态，内容完全可见，此后不再触发揭示特效。
- 除玩家飞船自带的货物初始为「已鉴定」外，其余货物（敌舰、残骸、打捞）生成时均标记为「未鉴定」。

### 13.2 揭示流程

触发方式共**三处并存**，互不排斥（去重与优先级保护由程序实现保证）：

1. **进入整理界面**：玩家按 Tab 打开整理界面时，对货舱中全部「未鉴定」货物执行揭示。首次进入即「首次揭示」；此后每次打开若仍有未鉴定货物，继续揭示剩余。
2. **史诗宝藏强制**：打捞到史诗宝藏时被强制拉入整理界面并锁定拖拽，立即揭示。
3. **结算前强制**：触发结算时若仍存在未鉴定货物，强制进入整理界面揭示，揭示完成后**自动退出并跳转结算界面**（`SpaceshipGameFlowController`，见《仓库整理界面.md》§2.1）。

队列规则：

1. 系统遍历玩家飞船中所有「未鉴定」货物。
2. 货物按**链接到玩家飞船的原始顺序（打捞顺序）**逐一弹出，不按价值重新排序。
3. 若存在史诗宝藏，**优先揭示史诗宝藏**并播放最高规格特效；史诗揭示完成后，其余未鉴定货物按原始顺序逐一弹出。
4. 每次弹出将货物从「未鉴定」变为「已鉴定」，伴随**对应稀有度的特效和音效**，弹出之间有短暂间隔。
