# 编辑器工具入口统一管理

> 类型：程序设计 | 状态：设计草案，已确认方案路线 | 更新：2026-08-13
>
> 本文档描述 Spaceship 项目「编辑器工具入口」的统一管理方案：让一个工具的入口信息只声明一次，菜单、工具中心、工具清单文档三处入口由同一份描述驱动。

---

## 1. 背景与问题

### 1.1 现状盘点

当前 `Spaceship/` 根菜单下约 **30 个 `[MenuItem]`**，散落在约 **20 个文件**、**4 个以上编辑器程序集**中：

| 程序集 | 承载的工具入口 |
|---|---|
| `Assembly-CSharp-Editor`（默认程序集） | `Assets/Editor/ShopSetupTool.cs`、`Assets/Scripts/Editor/InspectorSystem/` |
| `Spaceship.Game.Editor` | `Assets/Scripts/Tools/Editor/` 下 10+ 个工具 |
| `Spaceship.Validation.Editor` | `Assets/Scripts/Validation/Editor/` 下 5 个验证器 |
| `Spaceship.Vision.Editor` | `Assets/Scripts/Vision/Editor/` |
| `Spaceship.Framework.SequenceMap.Editor`（第三方框架） | 14 个窗口入口 |

### 1.2 暴露的问题

- **P1 菜单层级与命名不统一**：中英混用（`Spaceship/Shop/…`、`Spaceship/Tools/…` 与 `Spaceship/工具/…`、`Spaceship/检查器/…` 并存）；分类粒度混乱（「验证」职责散落在 `飞船/验证*`、`残骸`、`配置迁移`）；所有 `[MenuItem]` 未设 `priority`，菜单顺序靠字母/插入序。
- **P2 入口分散、无单一权威源**：每个工具的「菜单路径、窗口标题、打开行为」各自为政，魔法字符串满天飞；新增工具需手工同步菜单、`工具清单.md`、潜在快捷键三处。
- **P3 文档与代码脱节**：`工具清单.md` 已过期，缺 `Shop`、`残骸/转译残骸生成器工具`、`配置迁移`、`装配`、`RandomModuleConfigurationValidator` 等条目。
- **P4 无统一「工具中心」聚合入口**：工具全靠记忆菜单路径，无可搜索、可浏览、带说明的中心面板。

---

## 2. 设计目标

1. 分类、命名、排序**规范化**；
2. 打开行为（窗口/命令）**统一封装**，杜绝各自 `GetWindow`；
3. 工具清单文档**自动生成**，与代码永不脱节；
4. 新增工具**零配置**（只加特性，无需手工改菜单与文档）。

---

## 3. 关键工程约束

Unity 菜单项必须用 `[MenuItem]` **静态特性**声明，**无法在运行时动态增删菜单项**。因此「反射生成菜单」不成立，统一管理落在两个层面：

- **入口层**：引入「工具中心」窗口 + 反射目录（数据驱动，可运行时扫描）。
- **菜单层**：保留 `[MenuItem]` 作为快捷入口，但收敛为「薄壳」，统一走帮助方法与常量路径。

> 若要「只写一次特性、菜单也自动生成」，唯一彻底解是 Roslyn Source Generator（编译期扫描特性生成 `[MenuItem]` 方法）。复杂度高，本方案不采用，作为后续可选项。

### 3.1 程序集约束（方案落点）

工具入口分布在多个 asmdef 程序集中，而 asmdef 程序集**无法引用默认 `Assembly-CSharp-Editor` 程序集**。因此承载工具描述特性的基础设施必须放进**独立的 asmdef**，供各编辑器程序集引用：

```
Assets/Scripts/Editor/ToolInfra/
├── Spaceship.Editor.ToolInfra.asmdef      ← 独立编辑器程序集（autoReferenced: true）
├── SpaceshipEditorToolAttribute.cs        ← 工具描述特性
├── EditorToolKind.cs                      ← 入口类型枚举
├── EditorToolDescriptor.cs                ← 工具描述符
├── EditorToolCatalog.cs                   ← 反射目录（注册表）
├── SpaceshipEditorMenu.cs                 ← 菜单常量 + 统一打开/执行帮助层
├── EditorToolHubWindow.cs                 ← 工具中心窗口
└── ToolListDocumentGenerator.cs           ← 工具清单文档生成器
```

- `Spaceship.Game.Editor`、`Spaceship.Validation.Editor`、`Spaceship.Vision.Editor` 在 asmdef 的 `references` 中加入 `"Spaceship.Editor.ToolInfra"`；
- 默认 `Assembly-CSharp-Editor`（`Assets/Editor/`、`Assets/Scripts/Editor/InspectorSystem/`）经 `autoReferenced: true` 自动引用；
- `SequenceMap` 等第三方框架**不引用、不纳入**。

## 4. 方案架构（三层结构）

### 4.1 层一：工具描述符（数据 / 单一真相源）

```csharp
[AttributeUsage(AttributeTargets.Method)]
public sealed class SpaceshipEditorToolAttribute : Attribute
{
    public string Id;          // 稳定标识，如 "salvage.translator"
    public string DisplayName; // 显示名，如 "转译残骸生成器工具"
    public string Category;    // 分类路径，如 "残骸" 或 "飞船/旧版"
    public int Order;          // 组内排序
    public EditorToolKind Kind; // Window / Command / Validator
    public string Description; // 说明（工具中心 + 文档共用）
    public string Shortcut;    // 可选快捷键提示
}
```

典型用法（改造后的工具类）：

```csharp
[SpaceshipEditorTool(
    Id = "salvage.translator",
    DisplayName = "转译残骸生成器工具",
    Category = "残骸",
    Order = 20,
    Kind = EditorToolKind.Window,
    Description = "把蓝图/完整船/场景飞船转译为「已定」残骸生成器预制体。")]
[MenuItem(SpaceshipEditorMenu.Salvage + "转译残骸生成器工具")]
public static void Open() =>
    SpaceshipEditorMenu.Open<SalvageGeneratorTranslatorWindow>("残骸生成器转译");
```

约定：特性打在**静态方法**上（一个入口方法 = 一个工具），方法签名为 `static void`（无参），与 `[MenuItem]` 约束一致。

### 4.2 层二：目录（注册表）

```csharp
public sealed class EditorToolDescriptor
{
    public string Id;
    public string DisplayName;
    public string Category;
    public int Order;
    public EditorToolKind Kind;
    public string Description;
    public string Shortcut;
    public string MenuPath;        // 由 Category + DisplayName 推导，供文档/中心展示
    internal Action Invoke;        // 首次反射时由 MethodInfo 构造委托并缓存
}
```

`EditorToolCatalog` 在 `[InitializeOnLoad]` 时扫描所有程序集，收集带 `[SpaceshipEditorTool]` 特性的静态方法：

```csharp
public sealed class EditorToolCatalog
{
    public static EditorToolCatalog Instance { get; }

    public IReadOnlyList<EditorToolDescriptor> All { get; }      // 按 Category 分组、组内按 Order、DisplayName 排序
    public IReadOnlyList<EditorToolGroup> Groups { get; }         // 分类树（Category 首段为顶级）

    static EditorToolCatalog()
    {
        // AppDomain.CurrentDomain.GetAssemblies()
        //   .Where(a => !a.IsDynamic)
        //   .SelectMany(a => a.GetTypes())
        //   .SelectMany(t => t.GetMethods(BindingFlags.Static | BindingFlags.Public | BindingFlags.NonPublic))
        //   .Where(m => m.GetCustomAttribute<SpaceshipEditorToolAttribute>() != null)
        // 对每个命中方法：读特性构建描述符，并用 Delegate.CreateDelegate 缓存执行委托。
    }
}
```

> 特性类型在 `ToolInfra` 程序集内，跨程序集用 `GetCustomAttribute<T>()` 收集即可命中，无需程序集引用关系；运行时程序集不含该特性，天然被排除。

### 4.3 层三：入口（菜单 + 工具中心 + 文档）

#### 4.3.1 统一菜单帮助层

```csharp
public static class SpaceshipEditorMenu
{
    // 分类常量（单一权威路径，杜绝魔法字符串）
    public const string Root      = "Spaceship/";
    public const string Hub       = Root + "工具中心";
    public const string Mission   = Root + "任务/";
    public const string Ship      = Root + "飞船/";
    public const string Legacy    = Ship + "旧版/";
    public const string Salvage   = Root + "残骸/";
    public const string Validate  = Root + "验证/";
    public const string Config    = Root + "配置/";
    public const string Tools     = Root + "工具/";
    public const string Assembly  = Root + "装配/";
    public const string Inspector = Root + "检查器/";

    /// <summary>统一打开窗口。</summary>
    public static T Open<T>(string title) where T : EditorWindow
        => EditorWindow.GetWindow<T>(title);

    /// <summary>统一执行命令（捕获异常并输出到 Console）。</summary>
    public static void Run(string toolId, Action action);
}
```

#### 4.3.2 工具中心窗口

- `[MenuItem(SpaceshipEditorMenu.Hub, priority = -100)]`，置于菜单最顶。
- UI Toolkit 布局：左侧分类树 + 右侧工具列表（搜索框、双击打开/执行、展示 `Description` 与 `Shortcut`）。
- 数据源 = `EditorToolCatalog.Instance`，运行时扫描，天然完整。

#### 4.3.3 工具清单文档生成器

`ToolListDocumentGenerator` 遍历目录，按分类表格输出 `工具清单.md`（含说明），由工具中心内「导出工具清单」按钮触发，消除人工维护。

## 5. 菜单层级规范化

```
Spaceship/
├── 工具中心                     （唯一聚合入口，priority -100）
├── 任务/                        （新增：任务流程编辑器，对齐《任务系统重构与可视化编辑器》§7.7）
├── 飞船/                        （构建/装配/测试）
│     └── 旧版/                  （已废弃项，收敛标记）
├── 残骸/
├── 验证/                        （所有验证器集中，从「飞船/验证*」迁出）
├── 配置/                        （配置迁移、生成器）
├── 工具/                        （杂项，合并原 Tools）
├── 装配/
├── 检查器/
├── Vision/                      （或本地化为「视野」，待定）
└── SequenceMap/                 （第三方框架，保持不动）
```

规范要点：

- 一律**中文**菜单（对齐项目现状与规范）；
- 验证器归 `验证/`；
- 废弃项归 `飞船/旧版/`；
- `SequenceMap` 非本模块维护、按《任务系统重构与可视化编辑器》§7.1「禁止改动」，作为外部框架保留原样，**不纳入统一目录**。

## 6. 迁移计划

| 阶段 | 产出 | 说明 |
|---|---|---|
| 一 | `ToolInfra/`：特性 + 描述符 + 目录 + 帮助层 + 工具中心窗口 | 新增独立 asmdef + 5~6 个文件 |
| 二 | 工具中心接入 `EditorToolCatalog`，跑通「扫描 → 展示 → 打开」 | 验证闭环 |
| 三 | 存量工具迁移：逐个补 `[SpaceshipEditorTool]` + 改走 `SpaceshipEditorMenu`，统一分类/排序 | 约 20 文件，机械改动，仅 Spaceship 自有工具 |
| 四 | 文档生成器 + 重生成 `工具清单.md` | 1 个文件 |
| 五（可选） | Source Generator 自动生成 `[MenuItem]`，删掉手工菜单 | 进阶，暂不实施 |
