## 架构原则

### 1. 显式组合优先

- 场景对象由开发者**手动创建和摆放**
- 系统引用通过 `[SerializeField] private` 在 Inspector 中装配
- 不使用 Bootstrapper 自动创建完整系统
- 不使用运行时场景全局搜索代替正式依赖
- 不默认使用 `DontDestroyOnLoad`、全局单例或跨场景常驻对象

### 2. 单一职责

| 角色 | 允许负责 | 不允许负责 |
|------|----------|-----------|
| Director | 开局、结束、跨系统流程协调 | 具体库存算法、单个实体运动、UI 绘制 |
| System | 一个玩法领域的规则和运行时状态 | 创建无关系统、直接操作所有 UI |
| Actor | 单个运行实体的局部行为和表现 | 整局流程、全局统计 |
| EventSource | 声明和广播一类事件 | 保存玩法状态、执行业务规则 |
| UI/View | 显示状态、转发玩家界面操作 | 修改库存字典、推进关卡状态机 |
| Config | 保存静态调参和定义 | 保存本局实时状态 |

### 3. 依赖方向固定

| 允许的依赖 | 禁止的依赖 |
|-----------|-----------|
| Director → System | System → Director（命令） |
| Director → Actor | Config → 运行时场景实例 |
| System → Config | EventSource → 订阅者 |
| Actor → EventSource | 玩法系统 → Audio/FX 具体 API |
| UI/Audio/FX → EventSource | Audio/FX → 玩法系统 |
| UI → Director（查询） | 跨模块目录直接耦合 |

### 4. 通信模式分离

| 类型 | 使用场景 | 形式 |
|------|----------|------|
| **Command** | 必须立即执行的操作 | 公共方法 |
| **Query** | 需要同步获得结果 | 只读属性/返回值方法 |
| **Event** | 已发生的事实，通知多个被动系统 | 实例事件源 |
| **Callback** | 初始化时注入窄接口 | `Func`/`Action` |

**禁止把所有通信都改成事件。** 需要返回值、顺序保证或失败结果的操作使用 Command 或 Query。

## 目录规范

### 模块化目录（当前落地结构）

代码与资源按模块划分，**不再按开发者归属划分目录**。实际结构见工程内 `Assets/AGENTS.md` 的「目录结构」章节，概览如下：

```
Assets/
├── Scripts/                          # Spaceship.* 运行时与编辑器脚本
│   ├── Core/                         # 基础设施（事件/时间/日志/通用工具/Director）
│   ├── Configs/                      # 共享可调配置的 ScriptableObject 类型
│   ├── DataRuntime/                  # 运行时数据访问层（读 SO / 表索引 / 缓存）
│   ├── Events/                       # 按领域分类的实例事件源
│   ├── Gameplay/                     # 玩法层（Ships/Enemies/World/Workshop/Combat）
│   ├── UI/                           # UI 层（HUD/面板/世界空间交互）
│   ├── Tools/                        # 菜单、窗口、批处理工具（含 Editor/）
│   ├── Validation/                   # 资源校验（命名/引用/缺失，含 Editor/）
│   └── Vision/                       # 视野渲染模块（URP RenderFeature + 感知数据桥接）
├── Framework/                        # 通用框架（可迁移）
│   ├── AudioFramework/               # 通用音频框架
│   ├── FXFramework/                  # 通用特效框架
│   ├── EventBinding/                 # 事件触发绑定共享工具
│   └── SequenceMap/                  # 流程图编辑器工具
├── Art/                              # 美术资源（Sprites/Fonts/Shaders）
├── Prefabs/                          # 预制体（Blueprints/Modules/System）
├── Scenes/
│   ├── Main/                         # 正式场景
│   └── Test/                         # 测试场景
├── Data/
│   └── ScriptableObjects/            # 中文命名的 SO 资产
├── Documentation/                    # 项目文档
└── Settings/                         # URP 渲染设置（第三方，只读）
```

### 强制规则

- 所有自有资产必须位于模块化目录（`Scripts/`、`Framework/`、`Art/`、`Data/` 等）下
- 第三方插件保持独立目录，禁止直接修改
- 目录名、C# 文件名和类名使用英文 PascalCase
- 文档内容、Inspector 标签使用中文
- 一个 C# 文件只放一个主要 public 顶层类型
- `.meta` 文件必须与资产一起移动和提交

## 命名空间规范

格式：`Spaceship.<Module>`

当前项目使用：
- `Spaceship.Core` / `Spaceship.Gameplay` / `Spaceship.UI` / `Spaceship.Events` / `Spaceship.Data` / `Spaceship.Configs`（运行时模块）
- `Spaceship.Framework.Audio` / `Spaceship.Framework.FX` / `Spaceship.Framework.EventBinding` / `Spaceship.Framework.SequenceMap`（通用框架）
- 编辑器代码对应追加 `.Editor`
- 命名空间与目录一一对应，程序集边界由分层 asmdef 约束

---

## ScriptableObject 命名规则

- 自建 SO 资产文件名**必须使用中文正式名称**（如 `飞船游戏总配置.asset`）
- `CreateAssetMenu` 菜单路径使用中文
- Inspector 分组标题、枚举选项使用中文
- C# 类型和成员继续使用英文 PascalCase
- 运行时中文使用项目内授权字体资产，不依赖操作系统字体
- 重命名时同步移动 `.meta` 文件并保持 GUID 不变
