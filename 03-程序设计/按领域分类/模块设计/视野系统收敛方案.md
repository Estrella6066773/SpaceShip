# 视野系统收敛方案

> 作者：代码分析生成 | 创建日期：2026-08-02 | 最后修改：2026-08-02
>
> **状态：已落地**（2026-08-02 模块化迁移中完成）——视野渲染已唯一化到 `Spaceship.Vision` 模块（并入 `Spaceship.Game` 程序集），玩法侧收敛为感知逻辑。本文正文以当前模块化状态为准，历史归属仅作背景说明。

本方案把视野系统从「玩法数据层 + SpriteMask 呈现」与「视野模块 URP RenderFeature 呈现」的双轨状态，收敛为：**渲染唯一化到视野模块，玩法侧收敛为纯感知逻辑，视野半径数据源统一**。

模式定义见 [模块分层与粘合代码模式](../架构设计/模块分层与粘合代码模式.md)。

| `SpaceshipVisionRenderFeature` + Shader | 视野模块 | 视野遮罩渲染 | 保留 |

### 重叠点 1：视野半径算法重复

两套独立的半径计算，基于同一数据 `ShipAssembly.FurthestHullDistance`：

| 出处 | 公式 |
|------|------|
| `SpaceshipVisibilityController.VisionRadius` | `FurthestHullDistance + hullVisionPadding` |
| `SpaceshipVisionTarget.VisibleRadiusWorld` | `FurthestHullDistance / divisor + extraVisibleRadius` |

### 重叠点 2：呈现方式双轨

`SpaceshipVisibilityController.LateUpdate` 检测 `SpaceshipVisionController.Instance.EffectEnabled`：开启则隐藏 SpriteMask 走 RenderFeature，否则走 SpriteMask。同一时刻只生效一套，另一套属于**潜伏的死表现分支**。

## 目标结构

```
L0 数据层（玩法）         L1 感知层（玩法）          L2 表现层（视野模块）
ShipAssembly               ShipSensorModules          SpaceshipVisionController
  └─ FurthestHullDistance    └─ IsPointIlluminated      └─ RenderFeature（唯一呈现）
  └─ WorldCenterOfMass             ▲
        │                          │
        └──► 统一视野半径公式 ◄─────┘
                 │                        ▲
                 ▼                        │ 几何桥接（保留）
        SpaceshipVisionTarget            PlayerShipVisionPolygonBridge
        （只消费半径数据）                （光束几何 → 多边形区域）
```

- **数据**：质心与最远船体距离来自 `ShipAssembly`（玩法数据层），唯一。
- **感知**：`ShipSensorModules.IsPointIlluminated` 是 AI 感知规则（敌舰「看见玩家」），纯逻辑，与画面渲染解耦。
- **表现**：画面视野渲染唯一由视野模块 RenderFeature 承担。

## 统一视野半径

### 统一公式

```
视野半径 = 质心到最远船体端距离（FurthestHullDistance） + 附加可见半径
视野中心 = ShipAssembly.WorldCenterOfMass
```

去掉视野渲染侧的 `visibleRadiusDistanceDivisor` 除法参数，避免两套公式长期并存。

### 配置归属

附加可见半径并入**共享配置**，由双方读取同一来源：

| 方案 | 说明 | 推荐度 |
|------|------|--------|
| A. 并入 `SpaceshipWorldRules` | 新增 `BaseVisionPadding` 字段，玩法与视野模块均读取 | 推荐（数据驱动，单一配置） |
| B. 独立 SO `SpaceshipVisionConfiguration` | 视野专用配置资产 | 可选，若视野调参独立于世界规则 |

采用方案 A 时：

- `SpaceshipVisibilityController` 不再定义 `hullVisionPadding`（改读世界规则）。
- `SpaceshipVisionTarget` 移除 `visibleRadiusDistanceDivisor` 与 `extraVisibleRadius`（或仅保留局部偏移覆盖），改读同一世界规则。

## 各组件调整

### `SpaceshipVisibilityController` 收敛为感知数据提供者

- **移除**：SpriteMask 呈现分支（`UpdateBaseVisionMask`、`ApplyShipMasks`、`KeepAsteroidsVisible`、`missingMaskReported`）。
- **保留**：`VisionCenter` / `VisionRadius` 数据查询。
- **可选**：重命名为 `ShipVisionDataProvider`，语义从「控制器」改为「数据提供者」。

### `SpaceshipVisionTarget` 收敛为渲染绑定

- 保留：`WorldCenter` 计算（质心 + 局部偏移）、按 Tag 过滤。
- 修改：`VisibleRadiusWorld` 使用统一公式与配置。
- 自动绑定逻辑（启动查找 `Player` Tag 的 `SpaceshipVisionTarget`）保留，显式 `SetTarget` 优先。

### 小行星常显

小行星始终可见的规则由玩法侧 `KeepAsteroidsVisible` 维护。收敛后该表现规则归属渲染层，改用视野模块的忽略机制：

- `SpaceshipVisionIgnoreTag` / `IgnoreSpaceshipVision` 挂到小行星预制体，或由 `SpaceshipWorldMap` 生成时统一添加。
- 删除玩法侧逐帧遍历强制 unmask 的代码。

### 桥接层保留

`PlayerShipVisionPolygonBridge`（玩法）→ `SpaceshipVisionPolygonRegion`（视野）是合理的跨模块数据桥接（粘合代码），保留不动。
