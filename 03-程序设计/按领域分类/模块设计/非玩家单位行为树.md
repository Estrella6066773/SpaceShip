# 非玩家单位行为树

> 作者：AI 规划 | 创建日期：2026-08-15 | 状态：已实现（原生 SequenceMapGraphRunner 装配）
> 配套文档：`通用游戏 API 框架.md`（API 框架与 SequenceMap 接入规划）、`通用游戏 API QA 测试流程.md`（通用 QA 流程与用例风格）

本文档记录「非玩家单位行为树」的重构内容：非玩家单位（非玩家单位）的 AI 由原先的硬编码状态机，迁移为 **SequenceMap 行为树**驱动，并将行为能力沉淀为三层 API（运行时适配器 → 核心能力层 → SequenceMap 适配层）。三态（Normal/Scan/Battle）的选择与复合行为（巡逻/追击/逃跑）全部下沉到单张 SM 图内表达，C# 脚本只保留基本 API 原语与薄装配。**单位行为类型本身也改为纯资产数据驱动**：以 `NonPlayerUnitBehaviorConfig`（含 `id` / `displayName` / 图引用）取代 `NonPlayerUnitKind` 枚举。

船体跑图**直接依赖 SequenceMap 框架自带的原生组件** `SequenceMapGraphRunner`：策划在 Inspector 里拖图、绑 `self`，游戏侧不再用自定义宿主「创建子物体 + 反射写 graph + 自己 Activate」。

---

## 1. 概述与目标

### 1.1 为什么重构

重构前，非玩家 AI 由硬编码状态机 `NonPlayerUnitBehaviorController` / `NonPlayerUnitBehaviorContext` 驱动：每种非玩家单位类型的决策逻辑与移动、感知、开火能力耦合在同一份 C# 代码里。新增一种非玩家单位行为、调整一种巡逻节奏，都需要改代码、重新编译。

重构后：

- **数据驱动**：决策逻辑改为 SequenceMap 行为树图资产，行为由「图节点」表达，编辑图即改行为，无需改代码；
- **状态机与复合行为入图**：三态选择由单张图内的条件分支完成，巡逻/追击/逃跑等复合行为由图节点组合基本 API 原语与数学库向量运算实现，不再藏在 C# 里；
- **能力下沉复用**：移动、感知、开火等原语收敛为核心能力层 `NonPlayerUnitApi`（供任意 C# 消费者调用）+ SequenceMap 适配层 `SequenceMapNonPlayerUnitApi`（供图节点调用），图内不再直接触碰组件细节。

### 1.2 目标

1. 用 SequenceMap 行为树替代硬编码状态机，`NonPlayerUnitController` 退化为纯运行时适配器；跑图使用原生 `SequenceMapGraphRunner`，不再包一层自定义 Host / Driver；
2. 行为类型改为纯资产数据驱动：以 `NonPlayerUnitBehaviorConfig`（`id`/`displayName`/图）为权威来源，新增单位类型不改任何 C# 代码；
3. 现有「追击者 Chaser」「逃跑者 Fleer」两棵图资产为手动画图示例，未来类型按「新增单位类型指南」扩展；
4. 行为能力经 `NonPlayerUnitApi` / `SequenceMapNonPlayerUnitApi` 暴露，纳入通用游戏 API 框架，QA 可用 `QAApiVerifier` 冒烟验证。

## 3. 架构与分层

```text
行为树图节点（SequenceMap 图资产）
   │  调用 [SequenceMapApi] 扁平签名 + 数学库向量运算
SequenceMap 适配层   SequenceMapNonPlayerUnitApi（方法首参 GameObject self，解析出 NonPlayerUnitController 后转发）
   │  转发
核心能力层          NonPlayerUnitApi（方法首参 NonPlayerUnitController self，封装控制器与场景名册）
   │  调用
运行时适配器        NonPlayerUnitController（移动 / 感知 / 战斗原语 + 导航指令层）
   │  由原生组件跑图驱动
原生 SM Runner      SequenceMapGraphRunner（船体根上已挂载；graph / objectVariableBindings.self / runOnAwake）
   │  装配期填写
装配辅助            ShipSequenceMapRunnerInstaller（按 behaviorId 读配置，写原生字段；不包生命周期）
   │  读图
配置资产            NonPlayerUnitBehaviorConfig（每种行为类型绑定一棵单张图资产，位于 Resources）
```

| 层 | 类型 | 职责 | 关键点 |
|---|---|---|---|
| 运行时适配器 | `NonPlayerUnitController` | 封装移动、感知、战斗能力为最小 AI 原语，代理到 `ShipNavigation` / `ShipMotionController` / `ShipSensorModules` / `ShipCombatController` | 不再持有任何决策状态机；每帧只处理行动开关与舰体失效 |
| 原生 SM 组件 | `SequenceMapGraphRunner` | 框架自带的配置资产导入组件：拖入 `SequenceMapGraphAsset`，用「对象变量预设」绑 `self`，`runOnAwake` 启停 | 挂在船体根上；策划在 Inspector 操作的就是这些原生字段 |
| 装配辅助 | `ShipSequenceMapRunnerInstaller` | 编辑器导出 / 运行时蓝图构建时按 `behaviorId` 填写原生 `graph` 与 `self` 绑定，并挂 `NonPlayerUnitRadarContactEventBridge` | 空 `behaviorId` 不挂 Runner（或禁用已有 Runner）；禁止创建子物体与反射 |
| 核心能力层 | `NonPlayerUnitApi`（`Spaceship.Api` 命名空间） | 类型化签名（首参 `NonPlayerUnitController self`）的静态门面，封装控制器与 `ShipSceneRegistry`，无 SequenceMap 依赖 | 任意 C# 消费者可直接调用；含同步查询与返回 `IEnumerator` 的异步等待 |
| SequenceMap 适配层 | `SequenceMapNonPlayerUnitApi`（`Spaceship.Api.Adapters.SequenceMap` 命名空间） | 扁平签名（首参 `GameObject self`）+ `[SequenceMapApi]` 中文元数据，解析出控制器后转发核心层 | 仅此层依赖 SequenceMap 元数据；图内看到的是这层方法 |
| 雷达联络事件桥 | `NonPlayerUnitRadarContactEventBridge` | 监听本舰真实玩家联络边沿，向同物体 `SequenceMapGraphRunner` 投递自定义事件 `RadarContactChanged`（参数 0 = 1/0） | 装配期与 Runner 一并挂载；惰性单位禁用 |
| 配置资产 | `NonPlayerUnitBehaviorConfig` | 每种行为类型绑定一棵单张图资产，含 `id`/`displayName`，装配期按 `id` 经 `Resources.Load` 取图 | 手动画图后手动新建资产，放 `Resources/NonPlayerUnit/{id}.asset` 下 |
| 图资产 / 生成代码 | `Graphs/*.asset` + `Api/Generated/*.cs` | 决策逻辑本体与编译产物 | 生成代码必须落入 `Spaceship.Game` 程序集 |

> **与事件-订阅规范的关系**：按项目编码规范，对象间沟通优先使用事件-订阅。本模块的图节点调用 `NonPlayerUnitApi` / `SequenceMapNonPlayerUnitApi`，属于「同步获得返回值（Query）」与「必须立即执行、有顺序或失败结果要求（Command）」两类允许的例外，故直接以静态方法调用，而非事件广播。雷达联络**边沿**则由 `NonPlayerUnitRadarContactEventBridge` 转成 Runner 自定义事件，供图内 `OnCustomEvent` 等待（事件驱动，避免轮询漏报）。现有 Chaser/Fleer 图仍可用同步 `HasRadarContact` 节拍轮询；新图优先异步路径。

### 3.1 感知与移动：同步查询与事件等待

全库写法以 [`API同步与异步规范.md`](../规范与标准/API同步与异步规范.md) 为准。本模块实例：

| 模式 | API / 机制 | 用法 |
|---|---|---|
| 同步查询 | `HasRadarContact` / `CanSeePlayer` / `KnowsPlayer` / `IsFartherThan` / `MoveToward` / `ApproachIfFarther` | 当前快照或单帧给输入；已经满足则不必等事件 |
| 事件等待 | `OnCustomEvent == "RadarContactChanged"` / `"PlayerVisibleChanged"` | 本舰桥无参 `TriggerEvent`；醒来后再查同步节点 |
| 过程协程 | `MoveTo` / `ChaseKnownPlayer` | 持续移动直到到达、进入射击距离、失去感知或超时，然后停推进 |

不要为联络/看见再写 `WaitUntil`。现有 Chaser/Fleer 图仍可同步轮询。

## 4. 关键类型

### 4.1 `NonPlayerUnitBehaviorConfig`（行为类型定义，取代 `NonPlayerUnitKind` 枚举）

原 `NonPlayerUnitKind` 枚举已删除，单位行为类型的「权威来源」改为 `NonPlayerUnitBehaviorConfig` 资产：

```csharp
public sealed class NonPlayerUnitBehaviorConfig : ScriptableObject
{
    [SerializeField] private string id;                    // 唯一标识，同时作为跨资产引用键与 Resources 加载路径名
    [SerializeField] private string displayName;           // Inspector 中文显示名
    [SerializeField] private SequenceMapGraphAsset behaviorGraph; // 该类型绑定的单张行为树图

    public string Id => string.IsNullOrWhiteSpace(id) ? name : id.Trim();
    public string DisplayName => string.IsNullOrWhiteSpace(displayName) ? Id : displayName.Trim();
    public SequenceMapGraphAsset BehaviorGraph => behaviorGraph;
    public void Configure(string behaviorId, string behaviorDisplayName, SequenceMapGraphAsset graph);
}
```

- 一份资产即「一类单位行为」的权威定义：`id`（如 `Chaser` / `Fleer` / `Sniper`）+ `displayName`（如「追击者」「逃跑者」「狙击者」）+ 一棵单张行为树图；
- 新增单位类型**不改 C# 代码**：手动画一张 SM 图，再新建本资产填 `id`/`displayName` 并拖入图，放到 `Resources/NonPlayerUnit/{id}.asset` 即可（详见「新增单位类型指南」）；
- `id` 留空时回退为资产文件名，保证 `Resources/NonPlayerUnit/{Id}.asset` 加载路径稳定；
- 「无行为（惰性，不移动）」不再由枚举 `None` 表示，而是「`behaviorId` 为空」。

### 4.2 `NonPlayerUnitController`（重构后保留哪些能力）

纯运行时适配器（`MonoBehaviour`，实现内部接口 `INonPlayerUnitBehaviorDriver`），`[RequireComponent]` 依赖 `ShipAssembly`、`ShipMotionController`、`ShipSensorModules`。重构后保留的能力如下。

**公开属性（只读查询）**

| 属性 | 含义 |
|---|---|
| `ActionsEnabled` | 是否允许自主行动 |
| `BehaviorId` | 当前行为类型 id（如 `Chaser` / `Fleer`）；空表示无行为（惰性） |
| `HomePosition` | 出生点（巡逻与回家锚点） |
| `WalkRadius` | 普通巡逻半径 |
| `EscapeDistance` | 逃跑撤退距离 |
| `ShootingDistance` | 射击距离：知道玩家后追踪，进入该距离后不再靠近（Inspector 可调；图内 `GetShootingDistance` 读取） |
| `Position` / `Forward` / `RotationZ` | 当前位置 / 世界前向 / Z 轴旋转角 |
| `PlayerPosition` | 玩家位置；玩家不可用时返回自身位置 |
| `HasPlayer` | 场景名册中是否存在可运行玩家船 |
| `HasRadar` / `HasCannon` / `HasLight` | 是否存在启用且未损毁的对应模块 |
| `CanSeePlayer` | 照明光束是否覆盖玩家（无照明模块则无直接视野） |
| `Phase` | 行为树图经 `MarkState` 上报的阶段名（仅调试标签） |
| `CurrentTarget` | 最近写入的移动/追击目标（调试用） |

**公开方法**

| 方法 | 作用 |
|---|---|
| `Configure(player, worldRules, waypoints)` | 兼容旧生成/装配流程的配置入口；玩家引用以场景名册为权威 |
| `SetActionsEnabled(bool)` | 开关自主行动，关闭时清空移动输入 |
| `SetBehaviorId(string)` | 设置行为类型 id，切换后由对应驱动接管 |
| `OnScannedBy(ShipAssembly)` | 收到扫描波时反向发波（仅限持有雷达、扫描者为本舰玩家时） |
| `EmitRadarWave()` | 主动从雷达模块发射扫描波 |
| `TryGetRadarPlayerPosition(out Vector2)` | 读取真实雷达联络的玩家位置，无联络返回 `false` |
| `IsReachable(Vector2)` | 直达路径是否被小行星阻挡（依赖照明射线检测） |
| `MoveToward(Vector2, bool)` | 把目标转为局部推进/转向输入（委托导航指令层） |
| `SamplePatrolTarget()` | 在出生点半径内随机采样一个可达巡逻目标（纯数据查询，采样失败回退出生点） |
| `StopMove()` | 清空脚本移动输入 |
| `RotateToward(Vector2)` | 仅转向指定世界坐标，不施加推进 |
| `RotateByDegrees(float)` | 按正负角度方向持续转向 |
| `FireCannon()` | 全部有效机炮朝玩家开火，返回是否至少成功发射一门 |
| `MarkState(string)` | 接收行为树图上报的阶段名，仅作调试日志 |
| `SetTarget(Vector2)` | 缓存当前目标 |

> 注意：`RotateByDegrees`、`HasLight`、`RotationZ` 等仅存在于控制器层，**未**暴露到 `NonPlayerUnitApi` / `SequenceMapNonPlayerUnitApi`（当前图未用到，属预留能力）。原 `PatrolStep()`（巡逻单步）已删除，巡逻逻辑由「图内 `SamplePatrolTarget` + `MoveToward`」组合替代。

### 4.3 `NonPlayerUnitApi`（核心能力层）

静态类，`Spaceship.Api` 命名空间，方法首参均为 `NonPlayerUnitController self`（运行时定位「我」）。不依赖 SequenceMap。按分组列出全部方法：

**感知**

| 方法 | 作用 |
|---|---|
| `bool HasPlayer(self)` | 玩家飞船是否存在且仍可运行 |
| `bool CanSeePlayer(self)` | 是否直接看见玩家（照明光束覆盖） |
| `bool HasRadar(self)` | 是否有启用且未损毁的雷达模块 |
| `bool HasCannon(self)` | 是否有启用且未损毁的固定机炮 |

**位置查询**

| 方法 | 作用 |
|---|---|
| `Vector3 GetPosition(self)` | 本舰当前世界坐标 |
| `Vector3 GetPlayerPosition(self)` | 玩家位置；玩家不可用时回退本舰位置 |
| `Vector3 GetForward(self)` | 本舰当前世界前向 |
| `bool HasRadarContact(self)` | 雷达是否已记录到玩家真实联络（同步查询） |
| `bool KnowsPlayer(self)` | 是否已知道玩家位置（`CanSeePlayer` 或 `HasRadarContact`） |
| `Vector3 GetRadarPlayerPosition(self)` | 雷达记录的玩家位置；无联络时回退玩家位置 |
| `Vector3 GetKnownPlayerPosition(self)` | 已知玩家位置：优先照明实时坐标，其次雷达联络；不知道时回退本舰位置 |
| `Vector3 SamplePatrolTarget(self)` | 在出生点半径内随机采样一个可达巡逻目标（纯数据查询，采样失败回退出生点） |
| `float GetEscapeDistance(self)` | 逃跑撤退距离（纯数据查询，供图内做逃跑方向向量运算） |
| `float GetShootingDistance(self)` | 射击距离（纯数据查询，供图内当 keepDistance 或另填数字覆盖） |
| `float GetDistanceTo(self, target)` | 本舰到目标世界坐标的平面距离 |
| `bool IsFartherThan(self, target, distance)` | 本舰到目标是否大于指定距离 |

**队友查询**

| 方法 | 作用 |
|---|---|
| `bool HasNearestAlly(self, string allyId)` | 是否存在行为类型 id 为 `allyId` 的队友 |
| `Vector3 GetNearestAllyPosition(self, string allyId)` | 最近该类型队友位置；不存在时回退本舰位置 |
| `bool TryGetNearestAllyPosition(self, string allyId, out Vector3 position)` | 在名册中查找距离 self 最近、行为类型 id 为 `allyId` 的队友位置（匹配 `controller.BehaviorId == allyId`） |

**可达性**

| 方法 | 作用 |
|---|---|
| `bool IsReachable(self, Vector3 target)` | 直达目标点的路径是否未被小行星阻挡 |

**状态**

| 方法 | 作用 |
|---|---|
| `string GetPhaseName(self)` | 当前决策阶段名（Normal / Scan / Battle） |
| `void MarkState(self, string stateName)` | 上报当前决策阶段名（仅作调试标签，由 SM 图内状态分支调用，本层不回写状态机） |

**行动**

| 方法 | 作用 |
|---|---|
| `void MoveToward(self, Vector3 target, bool allowForward)` | 朝指定世界坐标移动一拍 |
| `void MoveToward(self, target, allowForward, angle, speed, angVel)` | 同上，外加运动期望；未指定传 `UnspecifiedMotion()` |
| `IEnumerator MoveTo(self, Vector3 target, bool allowForward, float arriveDistance, float timeout)` | 持续移动直到到达或超时，然后停推进 |
| `IEnumerator MoveTo(..., angle, speed, angVel)` | 同上，外加运动期望；抵达只看距离 |
| `void ApproachIfFarther(self, target, keepDistance, allowForward)` | 同步一拍：远则绕墙靠近，已进入距离则停推进（不后退） |
| `void ApproachIfFarther(..., angle, speed, angVel)` | 同上，外加运动期望 |
| `IEnumerator ChaseKnownPlayer(self, keepDistance, allowForward, timeout)` | 每帧追踪已知玩家，直到进入射击距离、失去感知或超时 |
| `IEnumerator ChaseKnownPlayer(..., angle, speed, angVel)` | 同上，外加运动期望 |
| `void StopMove(self)` | 清空脚本移动输入 |
| `void RotateToward(self, Vector3 target)` | 仅转向指定世界坐标，不施加推进 |
| `void EmitRadarWave(self)` | 主动发射一条雷达扫描波（核心层返回 `bool`；图内 void） |
| `bool FireCannon(self)` | 全部机炮朝玩家开火，返回是否至少成功发射一门 |
| `void SetTarget(self, Vector3 target)` | 缓存当前目标 |

> 已删除的复合方法：`GetFleePosition`（逃跑目标决策已下沉为图内向量运算）、`MoveTowardPlayer`（`GetPlayerPosition` + `MoveToward` 组合，由图内直接串接）、`PatrolMove`（巡逻决策下沉为 `SamplePatrolTarget` + `MoveToward`）。

### 4.4 `SequenceMapNonPlayerUnitApi`（SequenceMap 适配层）

## 5. 行为树图资产

两棵图位于 `Assets/Scripts/Gameplay/NonPlayerUnits/NonPlayerUnitBehavior/Graphs/`（`Chaser.asset`、`Fleer.asset`）。追击者图声明 `self` 一个图变量；逃跑者图额外声明 `fleeAnchor` / `fleeDir` / `fleeTarget` 三个 `Vector3` 图变量与 `fleeLen` 一个 `Float` 图变量（用于零向量判断）。结构统一为「感知 → 条件分支自选三态 → 执行对应行为 → 回环」：

```text
root() → Wait(0.1) → CanSeePlayer($self)
                        ├─ true  → MarkState($self,"Battle") → [Battle 行为链]   → Goto(Wait)
                        └─ false → HasRadarContact($self)
                                      ├─ true  → MarkState($self,"Scan")   → [Scan 行为链]    → Goto(Wait)
                                      └─ false → MarkState($self,"Normal") → [Normal 行为链]  → Goto(Wait)
```

`Wait(0.1)` 作为循环节拍（感知不要每帧打满）。`Goto(n)` 回跳循环体首节点 `Wait(0.1)`，形成自循环。三态分支互斥且每轮只走一条，回环后重新感知，实现完整状态机。`self` 由原生 `objectVariableBindings` 在 `ActivateGraph` 开协程前写入，不再依赖「驱动每帧 SetValue + 缓冲帧」这条代理路径。

### 5.1 追击者 Chaser

| 分支 | 行为链（success 连线） | 行为含义 |
|---|---|---|
| Battle | `MoveToward($self, GetPlayerPosition($self), true)` → `Wait(0.1)` | 实时看见玩家时直接朝玩家撞击 |
| Scan | `MoveToward($self, GetRadarPlayerPosition($self), true)` → `Wait(0.3)` | 雷达有联络时朝雷达记录的玩家位置追踪 |
| Normal | `MoveToward($self, SamplePatrolTarget($self), true)` → `Wait(1)` → `EmitRadarWave($self)` | 巡逻一步，周期发射雷达波主动搜索 |

### 5.2 逃跑者 Fleer

| 分支 | 行为链（success 连线） | 行为含义 |
|---|---|---|
| Battle | `$fleeAnchor = GetNearestAllyPosition($self, "Chaser")` → `$fleeDir = VectorSubtract($fleeAnchor, GetPlayerPosition($self))` → `$fleeLen = VectorMagnitude($fleeDir)` → `$fleeLen < 0.001`（真 → `$fleeDir = GetForward($self)`；假 → `$fleeDir = VectorNormalize($fleeDir)`）→ `$fleeTarget = VectorAdd($fleeAnchor, VectorMultiply($fleeDir, GetEscapeDistance($self)))` → `MoveToward($self, $fleeTarget, true)` → `Wait(0.3)` | 实时看见玩家时，以最近追击者队友为锚点、沿远离玩家方向撤退 `EscapeDistance`；方向接近零向量时回退自身前向 |
| Scan | `MoveToward($self, GetRadarPlayerPosition($self), true)` → `Wait(0.3)` | 与追击者 Scan 相同：朝雷达记录的玩家位置追踪 |
| Normal | `MoveToward($self, SamplePatrolTarget($self), true)` → `Wait(1)` → `EmitRadarWave($self)` | 与追击者 Normal 相同：巡逻 + 周期雷达搜索 |

> 逃跑方向运算（锚点 → 远离玩家方向 → 零向量判断 → 归一化/回退前向 → 乘逃跑距离 → 加回锚点）由 SequenceMap 数学库的 `VectorSubtract` / `VectorMagnitude` / `VectorNormalize` / `VectorAdd` / `VectorMultiply` 在图内完成，无 C# 决策；`$fleeLen < 0.001` 条件分支在归一化前判断远离方向是否接近零，接近零则回退自身前向 `GetForward($self)`。三态中，`Normal` 与 `Scan` 对追击者/逃跑者**完全相同**，差异仅在 `Battle`：追击者朝玩家撞击，逃跑者做逃跑向量运算后撤退。

### 5.3 基础射击寻路（原语，由图拼装）

射击类非玩家单位不预置完整行为树：策划用 SequenceMap 自行配置，程序只提供可组合原语。语义是：

1. **知道玩家位置**（照明光束看见，或雷达真实联络）才开始追踪；
2. 沿绕墙路径靠近已知位置；
3. 进入射击距离后**不再靠近**（不自动后退；要拉开距离请另拼逃跑向量）；
4. 射击距离默认读本舰 `ShootingDistance`（Inspector 可调），图节点也可另填 `keepDistance` 覆盖。

推荐拼装（同步一拍循环，可与开火/转向并列）：

```text
KnowsPlayer($self)
  ├─ true  → ApproachIfFarther($self, GetKnownPlayerPosition($self), GetShootingDistance($self), true)
  │          → RotateToward($self, GetKnownPlayerPosition($self))  // 进入距离后瞄准
  │          → FireCannon($self)                                  // 可选
  │          → Wait(0.1) → Goto(循环首)
  └─ false → [巡逻 / 发雷达波] → Goto(循环首)
```

需要「先贴近再开火」的过程节点时，用协程（不要用 `MoveTo` 固定快照点，玩家会跑）：

```text
KnowsPlayer($self)
  ├─ true  → ChaseKnownPlayer($self, GetShootingDistance($self), true, 8)
  │          → RotateToward($self, GetKnownPlayerPosition($self))
  │          → FireCannon($self)
  └─ false → 巡逻
```

分支更细（远靠近 / 近开火）时用查询，不要把决策写回 C#：

```text
IsFartherThan($self, GetKnownPlayerPosition($self), GetShootingDistance($self))
  ├─ true  → MoveToward($self, GetKnownPlayerPosition($self), true)
  └─ false → StopMove($self) → RotateToward(...) → FireCannon($self)
```

> `MoveTo` 的目标在调用时拍死，只适合去固定坐标；追移动中的玩家必须每帧重取 `GetKnownPlayerPosition`（`ApproachIfFarther` 循环或 `ChaseKnownPlayer`）。
> `GetKnownPlayerPosition` 在尚未感知时回退本舰位置，因此追踪前必须先 `KnowsPlayer`（或 `CanSeePlayer` / `HasRadarContact`）。
> 默认 `shootingDistance = 12`，调参改非玩家单位 Inspector 或图节点数字即可，不必改代码。

### 5.5 持续时间（所有持续行为必填）

凡是占用图节点、会「做一段时间」的行为，都必须带 `durationSeconds`：

- 时间到了，**即使目标没达成也结束**，节点走 success，后续分支由图配置；
- 已达成目标（进入到达半径 / 射击距离 / 失去感知）可以提前结束；
- `durationSeconds <= 0` 立即结束，不再无限挂起。

| 持续节点 | 提前结束 | 时间到 |
|---|---|---|
| `朝坐标移动(持续)` | 无（做满时长） | 停推进 |
| `移动到坐标` | 进入 arriveDistance | 停推进 |
| `远则靠近否则停止(持续)` | 已进入 keepDistance | 停推进 |
| `追踪已知玩家至射击距离` | 进入距离或失去感知 | 停推进 |
| `转向坐标(持续)` | 无 | 停转向 |
| `机炮开火(持续)` | 无 | 停止尝试开火（不中断推进） |

一拍节点（无持续参数）留给旧图循环；新图优先用带持续的协程，不要用 `Wait` 外挂代替 duration。

```text
MoveTo($self, $patrol, true, 2, 8)
  → 抵达或 8 秒到  →  图内下一节点（巡逻下一点 / 发雷达 / 开火…）
ChaseKnownPlayer($self, GetShootingDistance($self), true, 6)
  → 进入射击距离或 6 秒到  →  FireCannon($self, 2)
```

### 5.4 运动期望（可选角度 / 速度 / 角速度）

移动节点有短签名（行为与以前完全相同）和带运动期望的长签名。长签名多三个 float：

| 参数 | 单位 | 含义 |
|---|---|---|
| `desiredAngleDegrees` | 度 | 期望世界朝向，与 `GetFacingAngle` 同一约定 |
| `desiredSpeed` | 米/秒 | 期望接近时的速度大小 |
| `desiredAngularVelocity` | 度/秒 | 期望角速度 |

规则：

1. **可选**：不需要就用短节点；需要某几项时用长节点，其余项传 `UnspecifiedMotion()`。不要填 `0` 表示省略——`0` 表示「期望就是 0」。
2. **尽量趋近**：物理性能不够时会被截断；有朝向期望时用平移贴目标、转向去贴朝向。
3. **抵达只看距离**：进入 `arriveDistance` / `keepDistance` 即成功，不要求朝向或速度已经达到期望。

```text
MoveTo($self, $patrol, true, 2, 8, UnspecifiedMotion(), 4, UnspecifiedMotion())
MoveToward($self, $target, true, 90, UnspecifiedMotion(), UnspecifiedMotion())
```

## 6. 行为树图的创建方式（手动画图，已移除生成工具）

| `NonPlayerUnitBehaviorTreeDriver.EvaluatePhase` | 三态状态机，下沉为单张图内条件分支 |
| 旧「默认硬编码状态机」语义 | 由「默认硬编码状态机」改为「无行为（惰性，不移动）」，现表示为「`behaviorId` 为空」 |
| `NonPlayerUnitKind` 枚举 | 已删除，单位类型改为 `NonPlayerUnitBehaviorConfig` 资产（`id`/`displayName`/图） |
| `NonPlayerUnitBehaviorTreeBuilder` 生成工具 | 已删除，改为 SequenceMap 编辑器手动画图 |
| `ShipSequenceMapHost` | 已删除：不再用自定义宿主创建子物体、反射写 graph、每帧 SetValue |
| `NonPlayerUnitBehaviorTreeDriver` | 已删除：非玩家单位薄壳不再包一层 Runner 生命周期 |

**迁移关系**

| 旧能力 / 概念 | 迁移到 |
|---|---|
| 决策状态机（感知 → 状态 → 行为） | 单张 SM 图内的 `CanSeePlayer` / `HasRadarContact` 条件分支自选三态 |
| 三态切换外壳 | 已删除；阶段选择完全在 SM 图内 |
| 逃跑目标计算 | SM 图内 `GetNearestAllyPosition($self, "Chaser")` + 数学库向量运算 + `GetEscapeDistance` |
| 巡逻 | SM 图内 `SamplePatrolTarget` + `MoveToward` |
| 移动 / 感知 / 开火等行为原语 | `NonPlayerUnitController`（适配器）+ `NonPlayerUnitApi` / `SequenceMapNonPlayerUnitApi` |
| 非玩家单位行为类型配置 | `ShipBlueprint.behaviorId` 字段 + `NonPlayerUnitBehaviorConfig` 资产 |
| 代理导入（Host / Driver） | 已删除；改为船体根挂载原生 `SequenceMapGraphRunner` |

**保留但重构**：`NonPlayerUnitController` 保留，由「状态机宿主」重构为「纯运行时适配器」，`Update()` 不再推进任何状态机，只处理行动开关与舰体失效。

**保留的接口名**：`NonPlayerUnitController` 实现的内部接口 `INonPlayerUnitBehaviorDriver` 是重构后的新接口（非旧类），仍被 `ShipSensorModules.NotifyScannedTarget` 用于回调 `OnScannedBy`。

## 8. 装配路径

`ShipBlueprint`（`Assets/Scripts/Data/Blueprints/ShipBlueprint.cs`）字段：

```csharp
[SerializeField, Tooltip("非玩家单位行为类型 id（如 Chaser / Fleer）；空表示无行为（惰性）。")]
private string behaviorId = string.Empty;
public string BehaviorId => behaviorId;
public void SetBehaviorId(string id) { behaviorId = id; }
```

新建蓝图（工坊保存 / 船体编辑器新建 / `CreateAssetMenu`）时 `behaviorId` 默认为空，表示惰性、不跑图。自定义 Inspector 由 `BlueprintLayoutConfig.asset` 渲染，已露出「行为类型 id」；改完后必须再导出 Prefab，运行中的旧实例不会自动换图。

### 8.1 生成 / 导出 / 运行时拼船（全部入口）

| 路径 | 入口 | 原生 Runner |
|---|---|---|
| 工坊保存 / 收起保存 | `ShipWorkshopAssetExporter` → `ShipPrefabTemplateBuilder.Build(..., blueprint.BehaviorId)` | 有 id 则挂；空 id 不挂。每次新建模板再 `SaveAsPrefabAsset` 覆盖，不会留下旧 Driver/Host 或重复组件 |
| 船体与残骸编辑器 保存/导出 | `ShipTemplateEditorWindow` → 同上，**必须传入** `blueprint.BehaviorId` | 同上 |
| QA 狙击者工具 | `SniperBehaviorBuildTools` → `BuildFromAssets(..., "Sniper")` | 同上 |
| 组装验证场景刷敌 | `AssemblyPlaytestBootstrap` → `BuildTestShip` → `AssembleShipCore(..., nonPlayerUnitBehaviorId)` | 运行时 `ApplyBehavior` |
| 场景里拖 Prefab / 实例化 `exportedPrefab` | Unity 直接实例化已导出预制体 | **只靠预制体上已挂的原生 Runner**（期望如此，不再二次装配） |
| 玩家船重建 | `BuildShip` / `BuildPlayerFromSnapshot` | 不挂（玩家船） |
| 工坊试驾 | `BuildWorkshopTestDrive` | **故意不挂**：人操船 + 手动战斗输入，避免 AI 抢控制权 |
| 残骸 / 随机模块 | `SalvageGenerator` 等 | 不走非玩家单位 AI |

`ShipPrefabTemplateBuilder`（工坊与编辑器导出 Prefab）与 `AssembleShipCore`（运行时蓝图拼船）都调用同一套 `ShipSequenceMapRunnerInstaller.ApplyBehavior`：

- 空 `behaviorId`：不挂 Runner（惰性）；若运行时物体上已有则 `enabled = false`；
- 非空：加载 `NonPlayerUnitBehaviorConfig`，在船体根挂（或复用）原生 `SequenceMapGraphRunner`，写入 `graph`、`self` 绑定、`runOnAwake = true`。

> 队友查询（`TryGetNearestAllyPosition`）读取的是 `NonPlayerUnitController.BehaviorId`。蓝图 `behaviorId`、控制器 `behaviorId`、Runner 上的图应一致：导出时由装配层一次写齐。
>
> 惰性非玩家单位（`非玩家单位1` / `非玩家单位2` / `非玩家单位3` 等空 `behaviorId`）预制体不挂 Runner，也不挂已删除的 Driver。
>
> 改 `behaviorId` 后再导出是覆盖写：新模板从零 `AddComponent`，不会残留旧 Host，也不会叠两个 Runner。

### 8.2 策划操作：新建一艘带行为的非玩家单位船体

1. **（若用现成 Chaser / Fleer 可跳过）** 按「新增单位类型指南」画好 SM 图并建 `NonPlayerUnitBehaviorConfig`。
2. **新建蓝图**：工坊拼装后保存，或「船体与残骸编辑器」新建飞船蓝图。此时 `behaviorId` 为空，导出的是惰性船。
3. **填行为**：选中蓝图资产，Inspector「行为类型 id」填 `Chaser` / `Fleer` / 自建 id；阵营设为非玩家单位。
4. **再导出**：工坊再保存，或船体编辑器「导出 / 保存」（会重建关联 Prefab）。打开导出的 Prefab，根物体应有原生 `SequenceMapGraphRunner`：流程图已拖入、`self` 绑船体根、「Awake 时运行」勾选。
5. **放进场景**：把 `exportedPrefab` 拖进关卡（名册要登记 `NonPlayerUnitController`），或把蓝图挂到组装验证场景 `AssemblyPlaytestBootstrap` 的非玩家单位蓝图列表。不要再手工加 Host / Driver。

## 新增单位类型指南（纯配置流程）

达成硬目标：**新增一类单位类型时，完全不改任何 C# 代码**，只需新建/配置资产。

### 操作步骤（以新增「狙击者 Sniper」为例）

1. **在 SequenceMap 编辑器手动画一张行为树图**
   - 用编辑器新增图，绘制 `Normal` / `Scan` / `Battle` 三条分支（结构参考现有 `Chaser` / `Fleer` 图，见第 5 节）；
   - 图内调用的 API 均来自 `SequenceMapNonPlayerUnitApi` / `SequenceMapMathLibrary`（通用 API，队友类型用 `string` id 参数，如 `GetNearestAllyPosition($self, "Chaser")`）；
   - 保存图，SequenceMap 编辑器自动生成/更新 `Api/Generated/*.cs` 生成代码。

2. **新建行为类型配置资产**
   - 在 `Assets/Scripts/Gameplay/NonPlayerUnits/NonPlayerUnitBehavior/Resources/NonPlayerUnit/` 下新建 `NonPlayerUnitBehaviorConfig` 资产，命名为 `Sniper.asset`；
   - Inspector 填 `id = Sniper`、`displayName = 狙击者`，并把第 1 步画好的图拖到 `BehaviorGraph`；
   - 保存。

3. **在蓝图/预制体上引用该 id 并挂原生 Runner**
   - 目标非玩家单位的 `ShipBlueprint.behaviorId` 填 `Sniper`（Inspector「行为类型 id」），再走工坊保存或船体编辑器导出（二者都会把 `BehaviorId` 交给 `ShipPrefabTemplateBuilder`，按 id 把图画到原生 Runner）；
   - 或打开已有船体 Prefab：在根物体上添加 `SequenceMapGraphRunner`，把图拖到「流程图」，在「对象变量预设」里把 `self` 拖成该船体根物体，勾选「Awake 时运行」；
   - `NonPlayerUnitController.behaviorId` 填同一 id（队友查询读这里；工坊/编辑器导出时会与 Runner 一起写齐）。

即完成：全程零 C# 改动（已有装配工具会写原生字段；纯手工配 Prefab 也不需要自造组件）。改过 `behaviorId` 后必须再导出一次 Prefab，否则场景里拖进去的仍是旧图。

### 关键约束

- `id` 必须与资产文件名一致（`Sniper` ↔ `Sniper.asset`），保证 `Resources/NonPlayerUnit/{id}.asset` 加载路径成立；
- 图内引用其他类型队友时用 `string` id 参数（如 `GetNearestAllyPosition($self, "Sniper")`），不要写死枚举；
- 「无行为」单位不需要任何配置：`behaviorId` 留空即可，运行时走惰性分支。

### 9.6 self 注入（原生绑定）

官方路径：在 `SequenceMapGraphRunner` Inspector 的「对象变量预设」把 `self` 绑到船体根。`ActivateGraph()` 会先 `ApplyObjectVariableBindings()` 再启动生成类协程。

当前框架的 `ActivateGraphCore` **不会**调用 `ResetVariables` 清掉已写入的对象变量，因此游戏侧不再每帧 `SetValue("self")`，也不再需要自定义 Host。若未来 SequenceMap 在激活协程里重新引入 ResetVariables，应在框架内于 Reset 之后再次 `ApplyObjectVariableBindings()`，而不是再包一层游戏宿主。

图循环体首节点仍保留 `Wait(0.1)` 作为节拍，与 self 注入无硬依赖。

## 10. 已知注意点 / 待人工确认项

1. **运行时验证场景待补齐**：`验证-非玩家单位行为` 依赖场景内同时存在追击者与逃跑者（含照明、雷达等模块）且玩家进入 Battle 条件。当前尚无专门的自动化场景覆盖，需人工在组装验证场景或配置化场景中确认（以代码为准）。
2. **`behaviorId` 来源**：权威序列化字段在 `NonPlayerUnitController` 与 `ShipBlueprint`；队友查询读控制器。装配层把蓝图 id 写到控制器，并按同一 id 给原生 Runner 配图，避免只改一处。
3. **空 `behaviorId` 不跑图**：`ApplyBehavior` 对空 id 不挂（或禁用）`SequenceMapGraphRunner`；空 id 单位由 `NonPlayerUnitController` 的 `Update` 直接 `StopMove`（惰性不移动）。
4. **未暴露的控制器能力**：`NonPlayerUnitController` 的 `RotateByDegrees`、`HasLight`、`RotationZ` 等未暴露到 `NonPlayerUnitApi` / `SequenceMapNonPlayerUnitApi`，属预留能力；若未来图内需要按角度转向或直接视野判断，需在两层补充方法。
5. **不再反射框架私有字段**：装配走原生 `SetGraph` / `BindObjectVariable` / Inspector 序列化；不要恢复 `BindingFlags.NonPublic` 写 `graph`。
6. **追击者 Battle 无开火节点**：当前 `Chaser` Battle 分支只做 `MoveToward(GetPlayerPosition)` 撞击，不调用 `FireCannon`；机炮开火能力已具备但未接入图。若后续需要「边追击边开火」，在 Battle 行为链内加入 `FireCannon($self)` 节点即可。
7. **逃跑方向零向量回退（已实现）**：图内在归一化之前先计算 `$fleeLen = VectorMagnitude($fleeDir)`，再用条件分支 `$fleeLen < 0.001` 判断远离方向是否接近零向量：为真（接近零）时回退 `$fleeDir = GetForward($self)` 取自身前向作逃跑方向；为假时 `$fleeDir = VectorNormalize($fleeDir)` 归一化原始方向，两路汇合后继续 `VectorAdd` + `MoveToward`。由此还原旧 `GetFleePosition` 在「远离方向长度过小」时回退本舰前向的语义，消除「无追击者队友且玩家与本舰位置重合时逃跑者原地不动」的边界缺陷。阈值 `0.001` 为「接近零」的经验阈值（远离方向为真实单位向量的常规场景下不会误触发），分支全部在图内表达，未新增任何 C# 决策逻辑。
8. **状态标签只读回传**：`NonPlayerUnitBehaviorPhase` 枚举不再驱动任何切换，仅用于 `NonPlayerUnitController.BehaviorPhase` 的标签解析与 `GetPhaseName` 查询；真正决定行为的是图内 `MarkState` 上报的字符串与条件分支。
9. **射击寻路只给原语、不预置图**：知道玩家位置后追踪、进入射击距离后停靠近，由 `KnowsPlayer` / `GetKnownPlayerPosition` / `GetShootingDistance` / `ApproachIfFarther` / `ChaseKnownPlayer` 组合完成。默认 `shootingDistance = 12`，调参改 Inspector 或图节点即可。不要把完整射击 AI 写回 C#。`ApproachIfFarther` 不后退；要拉开距离仍用逃跑向量拼装。
10. **运动期望不是抵达条件**：长签名的角度/速度/角速度只影响趋近方式。未指定必须用 `UnspecifiedMotion()`；短签名保持旧行为。SequenceMap 按参数个数匹配重载，旧图不必改。
11. **持续行为必填持续时间**：`MoveTo` / `ChaseKnownPlayer` / 带「持续」的移动、转向、开火都在 `durationSeconds` 用尽时结束（未达成也走 success）。不再支持不限时；`<=0` 立即结束。后续响应一律由图配置。
