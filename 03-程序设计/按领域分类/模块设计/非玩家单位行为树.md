# 非玩家单位行为树

> 作者：AI 规划 | 创建日期：2026-08-15 | 状态：已实现，待运行时验证
> 配套文档：`通用游戏 API 框架.md`（API 框架与 SequenceMap 接入规划）、`通用游戏 API QA 测试流程.md`（通用 QA 流程与用例风格）

本文档记录「非玩家单位行为树」重构的完整内容：非玩家单位（敌人）的 AI 由原先的硬编码状态机，迁移为 **SequenceMap 行为树**驱动，并将行为能力沉淀为三层 API（运行时适配器 → 核心能力层 → SequenceMap 适配层），由编辑器工具一键生成两棵行为树图资产、两份配置资产与两份生成代码。三态（Normal/Scan/Battle）的选择与复合行为（巡逻/追击/逃跑）全部下沉到单张 SM 图内表达，C# 脚本只保留基本 API 原语。

---

## 1. 概述与目标

### 1.1 为什么重构

重构前，非玩家 AI 由硬编码状态机 `EnemyShipBehaviorController` / `EnemyShipBehaviorContext` 驱动：每种敌人类型的决策逻辑与移动、感知、开火能力耦合在同一份 C# 代码里。新增一种敌人行为、调整一种巡逻节奏，都需要改代码、重新编译。

重构后：

- **数据驱动**：决策逻辑改为 SequenceMap 行为树图资产，行为由「图节点」表达，编辑图即改行为，无需改代码；
- **状态机与复合行为入图**：三态选择由单张图内的条件分支完成，巡逻/追击/逃跑等复合行为由图节点组合基本 API 原语与数学库向量运算实现，不再藏在 C# 里；
- **能力下沉复用**：移动、感知、开火等原语收敛为核心能力层 `EnemyApi`（供任意 C# 消费者调用）+ SequenceMap 适配层 `SequenceMapEnemyApi`（供图节点调用），图内不再直接触碰组件细节。

### 1.2 目标

1. 用 SequenceMap 行为树替代硬编码状态机，`EnemyShipController` 退化为纯运行时适配器，`NonPlayerUnitBehaviorTreeDriver` 退化为纯宿主；
2. 支持「追击者 Chaser」「逃跑者 Fleer」两种非玩家单位行为类型，未来可扩展更多类型；
3. 提供编辑器一键生成工具，产出图资产、配置资产与生成代码，保证「改图 → 生成 → 运行」闭环；
4. 行为能力经 `EnemyApi` / `SequenceMapEnemyApi` 暴露，纳入通用游戏 API 框架，QA 可用 `QAApiVerifier` 冒烟验证。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 非玩家单位 | 泛指不被玩家直接操控的飞船单位；敌人只是其中一种，未来可扩展不对玩家敌对的类型 |
| 行为类型（Kind） | `NonPlayerUnitKind` 枚举：`None` / `Chaser`（追击者）/ `Fleer`（逃跑者） |
| 行为阶段（Phase） | `NonPlayerUnitBehaviorPhase` 枚举：`Normal`（普通）/ `Scan`（警戒）/ `Battle`（战斗），由单张图内条件分支选择，仅作调试与表现查询标签 |
| 追击者 Chaser | 看见玩家 → 撞击；雷达有联络 → 追踪玩家 |
| 逃跑者 Fleer | 雷达有联络 → 追踪玩家；实时观测到玩家 → 以最近追击者队友为锚点、朝远离玩家方向逃跑 |
| 图资产 | `.asset` 文件，SequenceMap 行为树图（`SequenceMapGraphAsset`） |
| 生成代码 | 由图资产生成的 C# 文件，落入 `Spaceship.Game` 程序集，图内 API 调用依赖它编译 |
| `self` 图变量 | 每张图声明的 `GameObject` 型图变量，运行时由通用宿主注入为本舰 `gameObject`，图内 `$self` 用于 API 调用定位「我」 |
| 运行时适配器 | `EnemyShipController`，把飞船能力封装为最小 AI 原语，不持有决策状态 |
| 船体 SM 宿主 | `ShipSequenceMapHost`，通用组件，让任意船体挂载并运行一张 SM 图；仅负责创建 Runner、注入 `self`、启动/停止，不含敌人语义 |
| 驱动宿主（敌人薄壳） | `NonPlayerUnitBehaviorTreeDriver`，敌人专用薄壳，解析 `behaviorKind` 配置后复用 `ShipSequenceMapHost` 运行单张图，不做任何状态评估 |

## 3. 架构与分层

```text
行为树图节点（SequenceMap 图资产）
   │  调用 [SequenceMapApi] 扁平签名 + 数学库向量运算
SequenceMap 适配层   SequenceMapEnemyApi（方法首参 GameObject self，解析出 EnemyShipController 后转发）
   │  转发
核心能力层          EnemyApi（方法首参 EnemyShipController self，封装控制器与场景名册）
   │  调用
运行时适配器        EnemyShipController（移动 / 感知 / 战斗原语 + 导航指令层）
   │  驱动
行为树驱动宿主      NonPlayerUnitBehaviorTreeDriver（敌人薄壳：解析 behaviorKind 配置，复用通用宿主）
   │  复用
船体 SM 宿主        ShipSequenceMapHost（创建 Runner、注入 self、启动/停止、每帧重断言 self）
   │  注入图
配置资产            NonPlayerUnitBehaviorConfig（每种行为类型绑定一棵单张图资产，位于 Resources）
```

| 层 | 类型 | 职责 | 关键点 |
|---|---|---|---|
| 运行时适配器 | `EnemyShipController` | 封装移动、感知、战斗能力为最小 AI 原语，代理到 `ShipNavigation` / `ShipMotionController` / `ShipSensorModules` / `ShipCombatController` | 不再持有任何决策状态机；每帧只处理行动开关与舰体失效 |
| 驱动宿主（敌人薄壳） | `NonPlayerUnitBehaviorTreeDriver` | 敌人专用薄壳，解析 `behaviorKind` 配置并复用 `ShipSequenceMapHost` 运行单张图 | 仅用于 `behaviorKind != None` 的单位；`None` 单位惰性不移动 |
| 船体 SM 宿主 | `ShipSequenceMapHost` | 通用组件，让任意船体运行一张 SM 图：创建 Runner、注入 `self` 图变量、启动/停止、每帧重断言 `self` | 不含敌人语义；`graph` 可直接在 Inspector 拖入或运行时注入 |
| 核心能力层 | `EnemyApi`（`Spaceship.Api` 命名空间） | 类型化签名（首参 `EnemyShipController self`）的静态门面，封装控制器与 `ShipSceneRegistry`，无 SequenceMap 依赖 | 任意 C# 消费者可直接调用 |
| SequenceMap 适配层 | `SequenceMapEnemyApi`（`Spaceship.Api.Adapters.SequenceMap` 命名空间） | 扁平签名（首参 `GameObject self`）+ `[SequenceMapApi]` 中文元数据，解析出控制器后转发核心层 | 仅此层依赖 SequenceMap 元数据；图内看到的是这层方法 |
| 配置资产 | `NonPlayerUnitBehaviorConfig` | 每种行为类型绑定一棵单张图资产，运行时由驱动经 `Resources.Load` 加载 | 由编辑器工具编程式生成，放 `Resources/NonPlayerUnit/` 下 |
| 图资产 / 生成代码 | `Graphs/*.asset` + `Api/Generated/*.cs` | 决策逻辑本体与编译产物 | 生成代码必须落入 `Spaceship.Game` 程序集 |

> **与事件-订阅规范的关系**：按项目编码规范，对象间沟通优先使用事件-订阅。本模块的图节点调用 `EnemyApi` / `SequenceMapEnemyApi`，属于「同步获得返回值（Query）」与「必须立即执行、有顺序或失败结果要求（Command）」两类允许的例外，故直接以静态方法调用，而非事件广播。AI 决策本身不订阅任何游戏事件，感知信息由驱动每帧注入 `self`，图内通过 `CanSeePlayer`、`HasRadarContact` 等查询原语每帧重读。

## 4. 关键类型

### 4.1 `NonPlayerUnitKind`

```csharp
public enum NonPlayerUnitKind
{
    [InspectorName("无行为（惰性）")] None,
    [InspectorName("追击者")] Chaser,
    [InspectorName("逃跑者")] Fleer
}
```

- `None` 语义在本次重构中改为「无行为（惰性，不移动）」，**不再**代表「默认硬编码状态机」；
- `Chaser` / `Fleer` 由 SequenceMap 行为树驱动；
- 敌人只是非玩家单位的一种，枚举命名保留了未来扩展不对玩家敌对类型的空间。

### 4.2 `EnemyShipController`（重构后保留哪些能力）

纯运行时适配器（`MonoBehaviour`，实现内部接口 `IEnemyShipBehaviorDriver`），`[RequireComponent]` 依赖 `ShipAssembly`、`ShipMotionController`、`ShipSensorModules`。重构后保留的能力如下。

**公开属性（只读查询）**

| 属性 | 含义 |
|---|---|
| `ActionsEnabled` | 是否允许自主行动 |
| `BehaviorKind` | 当前行为类型（None / 追击者 / 逃跑者） |
| `HomePosition` | 出生点（巡逻与回家锚点） |
| `WalkRadius` | 普通巡逻半径 |
| `EscapeDistance` | 逃跑撤退距离 |
| `Position` / `Forward` / `RotationZ` | 当前位置 / 世界前向 / Z 轴旋转角 |
| `PlayerPosition` | 玩家位置；玩家不可用时返回自身位置 |
| `HasPlayer` | 场景名册中是否存在可运行玩家船 |
| `HasRadar` / `HasCannon` / `HasLight` | 是否存在启用且未损毁的对应模块 |
| `CanSeePlayer` | 照明光束是否覆盖玩家（无照明模块则无直接视野） |
| `Phase` | 行为树图经 `MarkState` 上报的阶段名（仅调试标签） |
| `CurrentTarget` | 最近写入的移动/追击目标（调试用） |

**公开方法**

| 方法 | 作用 |
|---|---|
| `Configure(player, worldRules, waypoints)` | 兼容旧生成/装配流程的配置入口；玩家引用以场景名册为权威 |
| `SetActionsEnabled(bool)` | 开关自主行动，关闭时清空移动输入 |
| `SetBehaviorKind(NonPlayerUnitKind)` | 设置行为类型，切换后由对应驱动接管 |
| `OnScannedBy(ShipAssembly)` | 收到扫描波时反向发波（仅限持有雷达、扫描者为本舰玩家时） |
| `EmitRadarWave()` | 主动从雷达模块发射扫描波 |
| `TryGetRadarPlayerPosition(out Vector2)` | 读取真实雷达联络的玩家位置，无联络返回 `false` |
| `IsReachable(Vector2)` | 直达路径是否被小行星阻挡（依赖照明射线检测） |
| `MoveToward(Vector2, bool)` | 把目标转为局部推进/转向输入（委托导航指令层） |
| `SamplePatrolTarget()` | 在出生点半径内随机采样一个可达巡逻目标（纯数据查询，采样失败回退出生点） |
| `StopMove()` | 清空脚本移动输入 |
| `RotateToward(Vector2)` | 仅转向指定世界坐标，不施加推进 |
| `RotateByDegrees(float)` | 按正负角度方向持续转向 |
| `FireCannon()` | 全部有效机炮朝玩家开火，返回是否至少成功发射一门 |
| `MarkState(string)` | 接收行为树图上报的阶段名，仅作调试日志 |
| `SetTarget(Vector2)` | 缓存当前目标 |

> 注意：`RotateByDegrees`、`HasLight`、`RotationZ` 等仅存在于控制器层，**未**暴露到 `EnemyApi` / `SequenceMapEnemyApi`（当前图未用到，属预留能力）。原 `PatrolStep()`（巡逻单步）已删除，巡逻逻辑由「图内 `SamplePatrolTarget` + `MoveToward`」组合替代。

### 4.5 `NonPlayerUnitBehaviorConfig` + `NonPlayerUnitBehaviorPhase`

两者合并于 `NonPlayerUnitBehaviorConfig.cs`：

```csharp
public enum NonPlayerUnitBehaviorPhase { Normal, Scan, Battle }
```

`NonPlayerUnitBehaviorConfig`（`ScriptableObject`）每种行为类型各绑定一棵单张 `SequenceMapGraphAsset`：

- `BehaviorGraph`：单张行为树图引用；
- `Configure(graph)`：编辑器工具装配入口；
- `BehaviorGraph` 只读属性：运行时取图。

配置资产由工具生成到 `Resources/NonPlayerUnit/{Chaser,Fleer}.asset`，运行时 `Resources.Load<NonPlayerUnitBehaviorConfig>("NonPlayerUnit/Chaser")` 即可命中。

> `NonPlayerUnitBehaviorPhase` 枚举不再用于切换三棵图，仅作为 `GetPhaseName` / 驱动的阶段标签解析（`ParsePhase`）与调试用。

### 4.6 `NonPlayerUnitBehaviorTreeDriver`（敌人薄壳）

`MonoBehaviour`，敌人专用薄壳，把敌人语义（`behaviorKind` → 配置 → 图）解析为一张 SM 图，并把「运行 SM」这一通用能力委托给通用宿主 `ShipSequenceMapHost`，自身不做任何状态评估与 Runner 生命周期管理。

**关键成员**

- `[SerializeField, InspectorName("行为类型")] NonPlayerUnitKind behaviorKind`：序列化行为类型字段，**字段名与类型保持不变**，保证既有敌人 Prefab 序列化兼容；
- `ConfigResourcePrefix = "NonPlayerUnit/"`：配置加载前缀；
- `Phase`（当前阶段标签，由 `controller.Phase` 解析，只读）、`BehaviorKind`、`ActiveRunner`（经宿主透出，仅调试）、`IsReady`（经宿主透出）。

**装配流程（`Initialize(kind)`）**

1. 记录 `behaviorKind`，并 `controller.SetBehaviorKind(kind)` 保持两边一致；
2. `LoadConfig()`：`Resources.Load` 加载对应配置，缺失时输出告警；
3. `EnsureHost()`：运行时 `AddComponent<ShipSequenceMapHost>()`（复用通用宿主），把 `config.BehaviorGraph` 设到宿主的 `graph` 字段后调用 `host.Activate()`。

> 三态（Normal/Scan/Battle）的选择已移到 SM 图内的条件分支（`CanSeePlayer` → `HasRadarContact`），本类不再有 `EvaluatePhase()`，不再切换 Runner，也不再持有 `runner` 或每帧 `SetValue`——这些已全部下沉到 `ShipSequenceMapHost`。

### 4.7 `ShipSequenceMapHost`（船体 SM 宿主）

`MonoBehaviour`（`[DisallowMultipleComponent]`，命名空间 `Spaceship.Gameplay`），通用组件：让任意船体（玩家 / 敌人 / 残骸等，不限于非玩家单位）挂载并运行一张 SM 图。只承载「运行一张 SM 图」的通用能力，不含任何敌人语义（不引用 `NonPlayerUnitKind` / `EnemyShipController` / `NonPlayerUnitBehaviorConfig`）。

**序列化字段**

| 字段 | 含义 |
|---|---|
| `SequenceMapGraphAsset graph` | 要运行的图资产（Inspector 直接拖图，不经过任何 kind / Resources 间接层） |
| `string selfVariableName = "self"` | 注入本舰 `gameObject` 的图变量名 |
| `bool runOnEnable = true` | 启用时自动启动图 |

**公开 API**

| 成员 | 作用 |
|---|---|
| `SetGraph(SequenceMapGraphAsset)` | 设置要运行的图（运行期由宿主消费者在激活前注入） |
| `Activate()` | 创建 Runner 并激活图；无图告警跳过，重复调用幂等 |
| `Stop()` | 停用 Runner 子物体（触发 Runner 的 OnDisable 清理） |
| `Graph` / `SelfVariableName` / `ActiveRunner` / `IsReady` | 只读查询（调试用） |

**职责内聚**

- `EnsureRunner()`：建子物体 `SequenceMapGraphRunner`，用反射（`BindingFlags.NonPublic`）注入私有字段 `graph`、`runOnAwake=false`（与旧驱动的既有做法一致）；
- `OnEnable()`：`runOnEnable && graph != null && runner == null` 时自启动一次；
- `Update()`：每帧 `runner.SetValue(selfVariableName, gameObject)` 重断言 `self`；
- `OnDisable()`：`Stop()` 停图。

**self 注入机制与坑（详见第 9 节）**

- 图激活（`ActivateGraph()`）是协程，其首帧会执行 `SequenceMapGeneratedGraphBase` 的 `ResetVariables`，把图变量重置为默认值——`self` 被重置为 `null`；
- 修复：`StartGraph` 在 `ActivateGraph()` 之后立即补一次 `SetValue(selfVariableName, gameObject)`，`Update()` 每帧再补一次（幂等、开销极小），保证除协程首帧外 `self` 始终指向本舰；
- 生成图的循环体首节点固定为 `Wait(0.1)`（见第 5 节），保证「首帧 ResetVariables 之后、第一个行为节点执行之前」`self` 已被注入。

## 5. 行为树图资产

两棵图位于 `Assets/Scripts/Gameplay/Enemies/EnemyBehavior/Graphs/`（`Chaser.asset`、`Fleer.asset`）。追击者图声明 `self` 一个图变量；逃跑者图额外声明 `fleeAnchor` / `fleeDir` / `fleeTarget` 三个 `Vector3` 图变量与 `fleeLen` 一个 `Float` 图变量（用于零向量判断）。结构统一为「感知 → 条件分支自选三态 → 执行对应行为 → 回环」：

```text
root() → Wait(0.1) → CanSeePlayer($self)
                        ├─ true  → MarkState($self,"Battle") → [Battle 行为链]   → Goto(Wait)
                        └─ false → HasRadarContact($self)
                                      ├─ true  → MarkState($self,"Scan")   → [Scan 行为链]    → Goto(Wait)
                                      └─ false → MarkState($self,"Normal") → [Normal 行为链]  → Goto(Wait)
```

`Wait(0.1)` 作为「注入缓冲帧」，保证协程首帧 ResetVariables 后、第一个行为节点执行前，`self` 已被驱动注入。`Goto(n)` 回跳循环体首节点 `Wait(0.1)`（`nodeId = 2`），形成自循环。三态分支互斥且每轮只走一条，回环后重新感知，实现完整状态机。

### 5.1 追击者 Chaser

| 分支 | 行为链（success 连线） | 行为含义 |
|---|---|---|
| Battle | `MoveToward($self, GetPlayerPosition($self), true)` → `Wait(0.1)` | 实时看见玩家时直接朝玩家撞击 |
| Scan | `MoveToward($self, GetRadarPlayerPosition($self), true)` → `Wait(0.3)` | 雷达有联络时朝雷达记录的玩家位置追踪 |
| Normal | `MoveToward($self, SamplePatrolTarget($self), true)` → `Wait(1)` → `EmitRadarWave($self)` | 巡逻一步，周期发射雷达波主动搜索 |

### 5.2 逃跑者 Fleer

| 分支 | 行为链（success 连线） | 行为含义 |
|---|---|---|
| Battle | `$fleeAnchor = GetNearestChaserPosition($self)` → `$fleeDir = VectorSubtract($fleeAnchor, GetPlayerPosition($self))` → `$fleeLen = VectorMagnitude($fleeDir)` → `$fleeLen < 0.001`（真 → `$fleeDir = GetForward($self)`；假 → `$fleeDir = VectorNormalize($fleeDir)`）→ `$fleeTarget = VectorAdd($fleeAnchor, VectorMultiply($fleeDir, GetEscapeDistance($self)))` → `MoveToward($self, $fleeTarget, true)` → `Wait(0.3)` | 实时看见玩家时，以最近追击者队友为锚点、沿远离玩家方向撤退 `EscapeDistance`；方向接近零向量时回退自身前向 |
| Scan | `MoveToward($self, GetRadarPlayerPosition($self), true)` → `Wait(0.3)` | 与追击者 Scan 相同：朝雷达记录的玩家位置追踪 |
| Normal | `MoveToward($self, SamplePatrolTarget($self), true)` → `Wait(1)` → `EmitRadarWave($self)` | 与追击者 Normal 相同：巡逻 + 周期雷达搜索 |

> 逃跑方向运算（锚点 → 远离玩家方向 → 零向量判断 → 归一化/回退前向 → 乘逃跑距离 → 加回锚点）由 SequenceMap 数学库的 `VectorSubtract` / `VectorMagnitude` / `VectorNormalize` / `VectorAdd` / `VectorMultiply` 在图内完成，无 C# 决策；`$fleeLen < 0.001` 条件分支在归一化前判断远离方向是否接近零，接近零则回退自身前向 `GetForward($self)`。三态中，`Normal` 与 `Scan` 对追击者/逃跑者**完全相同**，差异仅在 `Battle`：追击者朝玩家撞击，逃跑者做逃跑向量运算后撤退。

| 驱动告警「未找到配置资源」 | 未运行生成工具，或配置不在 `Resources/NonPlayerUnit/` 下 | 运行菜单生成；确认 `Resources/NonPlayerUnit/{Chaser,Fleer}.asset` 存在 |

| 追击者不进入 Battle | 玩家不在照明光束内（无照明模块则永远看不见玩家） | 确认追击者配备照明模块，且玩家进入光束范围 |

| 图内 API 面板看不到「游戏/非玩家单位」 | Registry 未刷新 | 刷新 SequenceMap API 扫描 |

### 9.6 self 注入机制与坑（必读）

`SequenceMapGraphRunner.ActivateGraph()` 是协程，其首帧会执行 `SequenceMapGeneratedGraphBase` 的 `ResetVariables`，把图变量重置为默认值——`self` 因此被重置为 `null`。若图循环体首节点直接调用 API，会在首帧读到 `null`。

修复分两层，缺一不可：

1. **驱动激活后立即注入**：`ActivateGraph` 在 `ActivateGraph()` 之后补 `SetValue("self", gameObject)`；
2. **每帧重断言**：`Update()` 每帧对 `runner.SetValue("self", gameObject)`（幂等、开销极小），保证除协程首帧外 `self` 始终指向本舰；
3. **图结构缓冲帧**：每张图循环体首节点固定 `Wait(0.1)`，保证「首帧 ResetVariables 之后、第一个行为节点执行之前」`self` 已由驱动注入。

三者配合的时序：`ActivateGraph()` 首帧重置变量 → 驱动首帧/后续帧重新写入 `self` → `Wait(0.1)` 缓冲 → 循环体 API 节点读到正确 `self`。

## 10. 已知注意点 / 待人工确认项

1. **运行时验证场景待补齐**：`验证-非玩家单位行为` 依赖场景内同时存在追击者与逃跑者（含照明、雷达等模块）且玩家进入 Battle 条件。当前尚无专门的自动化场景覆盖，需人工在组装验证场景或配置化场景中确认（以代码为准）。
2. **`behaviorKind` 双来源**：`EnemyShipController`（序列化字段，默认 `None`）与 `NonPlayerUnitBehaviorTreeDriver` 各自持有 `behaviorKind`；队友查询读的是 `EnemyShipController.BehaviorKind`。当前 `driver.Initialize` 用 `SetBehaviorKind` 保持一致，但需留意两条装配路径（Inspector 手动设置 vs 蓝图驱动）不要只改一处。
3. **`None` 单位无驱动**：`BuildTestShip` 仅在 `behaviorKind != None` 时挂 `NonPlayerUnitBehaviorTreeDriver`；`None` 单位由 `EnemyShipController` 的 `Update` 直接 `StopMove`（惰性不移动），不创建任何 Runner。
4. **未暴露的控制器能力**：`EnemyShipController` 的 `RotateByDegrees`、`HasLight`、`RotationZ` 等未暴露到 `EnemyApi` / `SequenceMapEnemyApi`，属预留能力；若未来图内需要按角度转向或直接视野判断，需在两层补充方法。
5. **反射依赖框架私有字段**：驱动通过反射读写 `SequenceMapGraphRunner` 的私有字段 `graph`、`runOnAwake`（`BindingFlags.NonPublic`）。这依赖框架内部实现，若 SequenceMap 升级改动字段名/可见性，需同步调整（符合「不改框架本体、只新增 API」的约束，但属脆弱点）。
6. **追击者 Battle 无开火节点**：当前 `Chaser` Battle 分支只做 `MoveToward(GetPlayerPosition)` 撞击，不调用 `FireCannon`；机炮开火能力已具备但未接入图。若后续需要「边追击边开火」，在 Battle 行为链内加入 `FireCannon($self)` 节点即可。
7. **逃跑方向零向量回退（已实现）**：图内在归一化之前先计算 `$fleeLen = VectorMagnitude($fleeDir)`，再用条件分支 `$fleeLen < 0.001` 判断远离方向是否接近零向量：为真（接近零）时回退 `$fleeDir = GetForward($self)` 取自身前向作逃跑方向；为假时 `$fleeDir = VectorNormalize($fleeDir)` 归一化原始方向，两路汇合后继续 `VectorAdd` + `MoveToward`。由此还原旧 `GetFleePosition` 在「远离方向长度过小」时回退本舰前向的语义，消除「无追击者队友且玩家与本舰位置重合时逃跑者原地不动」的边界缺陷。阈值 `0.001` 为「接近零」的经验阈值（远离方向为真实单位向量的常规场景下不会误触发），分支全部在图内表达，未新增任何 C# 决策逻辑。
8. **状态标签只读回传**：`NonPlayerUnitBehaviorPhase` 枚举不再驱动任何切换，仅用于 `NonPlayerUnitBehaviorTreeDriver.Phase` 的标签解析与 `GetPhaseName` 查询；真正决定行为的是图内 `MarkState` 上报的字符串与条件分支。
