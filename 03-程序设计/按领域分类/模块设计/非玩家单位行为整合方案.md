# 非玩家单位行为整合方案

> 作者：代码分析生成 | 创建日期：2026-08-02 | 最后修改：2026-08-02
>
> **状态：已落地**（2026-08-02 模块化迁移中完成）——`NonPlayerUnitController` 与行为状态机已合入 `Spaceship.Gameplay` 模块，全部旧命名空间已统一为 `Spaceship.<Module>`。本文正文以当前模块化状态为准，历史归属仅作背景说明。

本方案合并非玩家单位行为系统目前存在的**两个并行宿主**，消除 `INonPlayerUnitRuntime` 的重复实现，并与 [移动系统统一方案](./移动系统统一方案.md) 联动，让非玩家单位的移动指令统一走 `ShipNavigation` 指令层。

模式定义见 [模块分层与粘合代码模式](../架构设计/模块分层与粘合代码模式.md)。

---

## 现状与问题

同一个行为状态机 `NonPlayerUnitBehaviorController`（`Spaceship.Gameplay`）在迁移前存在两个并行宿主：

| 宿主 | 迁移前位置 | 职责 | 独有能力 |
|------|------|------|----------|
| `NonPlayerUnitController` | 场景实际使用 | 实现 `INonPlayerUnitRuntime`，驱动移动/开火；实现 `INonPlayerUnitBehaviorDriver` 反扫描 | 反扫描驱动、旧 UI 兼容状态 `NonPlayerUnitShipState` |
| `NonPlayerUnitBehaviorAuthoring` | 并行替代（已移除） | 自带私有 `RuntimeAdapter`，同样完整实现 `INonPlayerUnitRuntime` | 丰富调试：Gizmo 标签、逐帧日志、可达性/移动决策日志 |

### 重复代码规模

两个 `INonPlayerUnitRuntime` 实现中，以下方法**逐行重复**（共约 200 行）：

- `MoveToward`（世界目标点 → 局部输入）
- `RotateToward` / `RotateByDegrees`
- `IsReachable`（照明遮挡判定）
- `FireCannon`（检测开火是否成功）
- `TryGetRadarPlayerPosition`（雷达反扫描）
- `IsActiveModuleKind` 筛选条件
- `ResolvePlayerShip`（从场景名册解析玩家）

`NonPlayerUnitBehaviorAuthoring.Awake` 还会通过 `disableBuiltInEnemyController` 禁用 `NonPlayerUnitController`，两个组件在同一实体上互斥共存，是「双轨并存」的直接来源。

---

## 目标：单一宿主

合并后非玩家单位根对象只挂载**一个**宿主组件，其职责结构如下：

```
NonPlayerUnitController（合并后的唯一宿主）
│
├── 决策层   NonPlayerUnitBehaviorController   ← 非玩家单位行为状态机，保持不变
├── 指令层   ShipNavigation                 ← 统一导航转换（移动方案 L1）
├── 执行层   ShipMotionController           ← 移动物理
│            ShipCombatController           ← 开火
│            ShipSensorModules              ← 感知（雷达 / 照明）
│
├── 适配粘合 INonPlayerUnitRuntime 实现          ← 变薄：委托指令层/执行层
│            INonPlayerUnitBehaviorDriver       ← 反扫描驱动（保留）
│            NonPlayerUnitShipState                 ← 旧 UI 兼容概略状态（保留）
│
└── 调试开关 统一 Debug 配置组               ← 原有全部调试开关合并
```

### 关键设计

1. **宿主位置**：合并后的 `NonPlayerUnitController` 位于 `Spaceship.Gameplay` 模块（`Scripts/Gameplay/NonPlayerUnits/`），场景中 `ShipSceneRegistry` 与验证器均依赖它。
2. **行为状态机归属**：`NonPlayerUnitBehaviorController`、`EnemyBehaviorContext`、`INonPlayerUnitRuntime`、`NonPlayerUnitBehaviorSettings` 等类型与宿主同属 `Spaceship.Gameplay`，作为「非玩家单位 AI 决策模块」的核心。
3. **`NonPlayerUnitBehaviorAuthoring` 移除**：其调试能力并入唯一宿主的开关；组件与 `NonPlayerUnitBehaviorAttachTool` 编辑器工具一起退役（2026-08-02 已执行）。

## 宿主实现（合并后）

### 导航与移动（变薄）

`INonPlayerUnitRuntime` 中以下方法改为委托，不再手写转换：

| 接口成员 | 委托目标 |
|----------|----------|
| `MoveToward(target, allowForward)` | `navigation.MoveToward` |
| `RotateToward(worldPoint)` | `navigation.RotateToward` |
| `RotateByDegrees(degrees)` | `navigation.RotateByDegrees` |
| `StopMove()` | `navigation.Stop` |
| `IsReachable(target)` | `sensors.TryGetLightBlockingHit`（保留现逻辑，去掉重复的遍历实现） |
| `FireCannon()` | `combat.TryFireAll` + `WasCannonFiredRecently` |
| `TryGetRadarPlayerPosition(out pos)` | `sensors.TriggerImmediateScan` + `sensors.Contacts` |

`NonPlayerUnitBehaviorSettings` 中仅保留**行为节奏参数**（距离/时长/间隔/角度范围）；转向死区 `moveTurnDeadZoneDegrees`、`rotateDeadZoneDegrees` 在 `ShipNavigationSettings`；传感器偏移在传感器配置。旧坦克式 `moveForwardAngleLimit` / `moveStrafeAngleLimit` 已删除。

### 反扫描驱动（保留）

```csharp
public interface INonPlayerUnitBehaviorDriver
{
    bool ActionsEnabled { get; }
    void SetActionsEnabled(bool enabled);
    void OnScannedBy(ShipAssembly scanner);
}
```

`OnScannedBy` 逻辑保留：被玩家雷达扫中时立即反扫描，把雷达结果交给行为框架的搜索阶段。`ShipSensorModules.NotifyScannedTarget` 不再需要从多个 `MonoBehaviour` 里寻找驱动者，直接调用唯一宿主。

### 调试开关统一

| 开关 | 原宿主 | 合并后 |
|------|--------|--------|
| `verboseLogging` | 控制器 | 保留，作为总日志开关 |
| `drawDebugGizmos` | 两者都有 | 保留，绘制出生点/目标/玩家连线 |
| `enableDetailedDebug` | 行为框架 | 保留，开启 Scene 标签 |
| `drawDebugLabels` | 行为框架 | 保留 |
| `logRuntimeSignals` / `logTargetChanges` / `logMovementDecisions` / `logReachabilityChecks` | 行为框架 | 并入一个 `[Header("调试")]` 分组，默认关闭 |

## 落地步骤

1. 新建 `ShipNavigation` + `ShipNavigationSettings`（见移动系统方案），迁入导航转换。
2. 把 `NonPlayerUnitBehaviorAuthoring` 的调试开关与 Gizmo 绘制并入 `NonPlayerUnitController`。
3. 重写 `NonPlayerUnitController` 的 `INonPlayerUnitRuntime` 实现为薄委托。
4. 删除 `NonPlayerUnitBehaviorAuthoring` 及其 `RuntimeAdapter`；同步更新 `NonPlayerUnitBehaviorAttachTool`（或一并移除）。
5. 更新 `ShipSensorModules.NotifyScannedTarget` 为直接调用唯一宿主。
6. 更新手工场景验证器：非玩家单位组件检查改为「必须挂载合并后的宿主」。
