# 飞船组装系统

> 作者：代码分析生成 | 创建日期：2026-07-29 | 最后修改：2026-08-02

本文档描述飞船的模块化网格组装系统的技术设计。

## 系统概述

飞船组装系统是本项目的核心玩法的技术实现。飞船由多个独立模块在 **1 米网格** 上自由组合而成，每个模块有独立的类型、生命值、链接关系与物理属性。

## ShipAssembly — 飞船总成

飞船总成是飞船的「根对象」，管理所有子模块并对外提供飞船级别的数据：

### 职责

- 管理 `ShipModule[]` 子模块列表与 `CarriedModules`（钩爪携带的模块）
- 实时计算**总质量**：所有未摧毁模块质量之和
- 实时计算**质心位置**：加权平均所有模块位置（`WorldCenterOfMass`）
- 提供**几何快照**（`GetGeometrySnapshot`）：最远船体端、最大跨度、包围盒，供视野系统使用
- 判断**阵营归属**（`ShipFaction`）：`IsDerelict`（无存活核心）时强制返回 `Derelict`；`HasCore`、`IsOperational`
- 处理**摧毁逻辑**：核心模块被摧毁 → 整艘飞船坠毁（`MarkDestroyed(reason)`）
- 重建**模块链接关系**；模块被毁/拆除后按连通性 `SplitDisconnectedGroups` 拆分
- **残骸重组**：`TryTransferSingleModuleFrom` 把残骸模块按相对坐标旋转平移装入本船（先试装，无外部链接则回滚），转移时搬运货舱内容并按目标阵营决定鉴定状态

### 关键字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `Modules` | `ShipModule[]` | 当前所有模块 |
| `CarriedModules` | `ShipModule[]` | 钩爪携带的模块 |
| `TotalMass` | `float` | 总质量 |
| `CenterOfMass` | `Vector2` | 质心世界坐标 |
| `Faction` | `ShipFaction` | 阵营（残骸时强制 Derelict） |
| `LoadCapacity` | `int` | 载重上限 |
| `IsDestroyed` | `bool` | 是否已被摧毁 |

## ShipModule — 飞船模块

### 网格定位

每个模块在世界中的位置由以下方式确定：

- 以核心模块为中心（`(0, 0)` 网格坐标）
- 每个模块占据 **1m × 1m** 空间
- 四向链接点：Forward `(0, +1)`、Right `(+1, 0)`、Back `(0, -1)`、Left `(-1, 0)`
- 模块旋转通过四分之一圈（`gridRotationQuarterTurns`）控制朝向

### 生命值系统

- 每个模块有独立生命值（基础生命 × 质量倍率）
- **损坏表现为运行时程序化生成裂纹**（3 档），关闭状态发暗
- 生命值归零 → `ApplyDamage` 交给 Assembly 的 `DestroyModule`
- 摧毁后从 ShipAssembly 移除，可能触发**断裂**（`SplitDisconnectedGroups`，「链」上的后续模块一同脱落）

### 链接系统

- 相邻模块通过**智能链接判断**自动建立链接
- 每个面有启用/禁用链接标志（`Links` 集合）
- 链接碰撞体检测（`ModuleLinkAnchorView` 生成四向锚点）：
  - 已链接 → 锁定碰撞对
  - 分离 → 取消链接并重新检测
  - 近期拆除 → 60 秒内使用较短链接时长（2 秒 vs 普通 5 秒）
- 链接反馈：引导线 + 进度条 + 锚点高亮（`ShipLinkFeedbackPresenter`）

## 模块类型（ModuleKind）

模块类型定义在 `ModuleDefinition` ScriptableObject 中，运行时通过 `ShipModule.ModuleKind` 访问。

| 枚举值 | 中文名 | 特殊功能 | 受限条件 |
|--------|--------|----------|----------|
| `Core` | 核心模块 | 飞船必须品 | 被摧毁则整船坠毁 |
| `Thruster` | 动力模块 | 四向推进（Forward/Right/Back/Left） | 方向与数量决定推进速度 |
| `Radar` | 寻敌雷达 | 100m 扫描敌方/所有阵营 | 可开关 |
| `Light` | 发散光束 | 60° 扇面 × 80m 照明 | 可开关 |
| `Cannon` | 固定式机炮 | 子弹射击，按弹药消耗 | 冷却时间 |
| `Grapple` | 拆卸钩爪 | 长按 2 秒拆卸目标模块 | 不可拆卸核心 |
| `Shield` | 电磁盾 | 吸收伤害、反弹弹丸/雷达 | 消耗能源 |
| `Storage` | 储存模块 | 4 个货物槽位 | 每槽同类限 10 个 |
| `Empty` | 基础模块 | 纯质量/装甲 | 无主动功能 |

## 物理模型

### 运动方程

基于 Rigidbody2D + Input System：

```
总速度 = 基础速度（玩家用 PlayerShipSettings / 敌舰用世界规则）
        + Σ(各方向动力模块 ThrusterSpeed)
超载惩罚：模块数 > LoadCapacity 时按超载倍数衰减
```

- 性能由动力模块的数量与朝向决定（无杠杆/力矩模型，纯方向速度叠加）
- 超载时（模块数 > LoadCapacity），性能按比例衰减

### 碰撞

- 模块之间的碰撞体用于链接检测（非物理碰撞）
- 飞船整体使用 Rigidbody2D 与外部世界碰撞
- 碰撞反馈通过 `ShipCollisionFeedback` 检测冲击并触发 `ShipCameraFollower.Shake` 摄像机震动

## 飞船蓝图（ShipBlueprint）

蓝图是 ScriptableObject，定义了飞船的初始布局：

```
ShipBlueprint
├── ShipModulePlacement[]
│   ├── ModuleDefinition (SO)
│   ├── GridX, GridY (网格坐标)
│   └── QuarterTurns (旋转)
├── ShipInitialCargoPlacement[]
│   ├── CargoType
│   ├── Count
│   └── TargetStorageModuleIndex
└── ExportedPrefab
```

蓝图运行时通过 `ShipPrefabRuntimeInstaller` 实例化为完整的 ShipAssembly，并提供 `IsValid`/`ValidateInitialCargo`/`IsLayoutConnected` 静态校验。

## 运行流程

### 实例化流程（LevelContentInitializationController）

1. 随机模块解析（`SalvageRandomizationManager.InitializeRandomModules`）
2. 货物初始化（重建链接 + 按种子初始化货舱）
3. 飞船注册（非玩家飞船同步到 `ShipSceneRegistry`）
4. 导演系统启动（`TemporaryGameDirector.Initialize`）
5. 视野/揭示激活（`SpaceshipVisibilityController` + `CargoRevealCoordinator`）

### 残骸拆分与重组流程

1. 右键拆除模块 → 单个模块变为带 Rigidbody2D 的独立残骸
2. 模块被摧毁/拆除 → `SplitDisconnectedGroups` 按连通性拆分残骸组，货舱内容随模块转移
3. 玩家飞船锚点与残骸锚点相叠 → 自动链接（`TryTransferSingleModuleFrom`）装入本船

### 销毁流程

1. 核心模块被摧毁 → 触发 `ShipAssembly.MarkDestroyed`
2. 广播 `ShipDestroyed` 事件（通过 `ShipFlowEventSource`）
3. 摄像机冻结（`ShipCameraFollower`）
4. 从 `ShipSceneRegistry` 注销
