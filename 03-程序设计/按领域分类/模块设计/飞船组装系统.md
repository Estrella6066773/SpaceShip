# 飞船组装系统

> 作者：代码分析生成 | 创建日期：2026-07-29 | 最后修改：2026-07-29

本文档描述飞船的模块化网格组装系统的技术设计。

---

## 系统概述

飞船组装系统是本项目的核心玩法的技术实现。飞船由多个独立模块在 **1 米网格** 上自由组合而成，每个模块有独立的类型、生命值、链接关系与物理属性。

## ShipAssembly — 飞船总成

飞船总成是飞船的「根对象」，管理所有子模块并对外提供飞船级别的数据：

### 职责

- 管理 `ShipModule[]` 子模块列表
- 实时计算**总质量**：所有未摧毁模块质量之和
- 实时计算**质心位置**：加权平均所有模块位置
- 管理**载重上限**：与模块数量对比，触发超载惩罚
- 判断**阵营归属**（`ShipFaction`：Player/Enemy/Derelict/Neutral）
- 处理**摧毁逻辑**：核心模块被摧毁 → 整艘飞船坠毁
- 重建**模块链接关系**

### 关键字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `Modules` | `ShipModule[]` | 当前所有模块 |
| `TotalMass` | `float` | 总质量 |
| `CenterOfMass` | `Vector2` | 质心世界坐标 |
| `Faction` | `ShipFaction` | 阵营 |
| `LoadCapacity` | `int` | 载重上限 |
| `IsDestroyed` | `bool` | 是否已被摧毁 |

## ShipModule — 飞船模块

### 网格定位

每个模块在世界中的位置由以下方式确定：

- 以核心模块为中心（`(0, 0)` 网格坐标）
- 每个模块占据 **1m × 1m** 空间
- 四向链接点：Forward `(0, +1)`、Right `(+1, 0)`、Back `(0, -1)`、Left `(-1, 0)`
- 模块旋转通过 `LocalDirection` 枚举控制朝向

### 生命值系统

- 每个模块有独立生命值（基础生命 × 质量倍率）
- 四档损坏精灵图（完好 → 轻微 → 严重 → 即将断裂）
- 生命值归零 → 模块被摧毁
- 摧毁后从 ShipAssembly 移除，可能触发**断裂**（「链」上的后续模块一同脱落）

### 链接系统

- 相邻模块通过**智能链接判断**自动建立链接
- 每个面有启用/禁用链接标志
- 链接碰撞体检测：
  - 已链接 → 锁定碰撞对
  - 分离 → 取消链接并重新检测
  - 近期拆除 → 60 秒内使用较短链接时长
- 链接反馈：四向锚点视图 + 候选锚点脉冲 + 世界空间进度条

## 模块类型（ModuleKind）

模块类型定义在 `ModuleDefinition` ScriptableObject 中，运行时通过 `ShipModule.ModuleKind` 访问。

| 枚举值 | 中文名 | 特殊功能 | 受限条件 |
|--------|--------|----------|----------|
| `Core` | 核心模块 | 飞船必须品 | 被摧毁则整船坠毁 |
| `Thruster` | 动力模块 | 四向推进（Forward/Right/Back/Left） | 位置决定力矩 |
| `Radar` | 寻敌雷达 | 100m 扫描敌方/所有阵营 | 可开关 |
| `Light` | 发散光束 | 60° 扇面 × 80m 照明 | 可开关 |
| `Cannon` | 固定式机炮 | 子弹射击，按弹药消耗 | 冷却时间 |
| `Grapple` | 拆卸钩爪 | 长按 2 秒拆卸目标模块 | 不可拆卸核心 |
| `Shield` | 电磁盾 | 吸收伤害、反弹弹丸/雷达 | 消耗能源 |
| `Storage` | 储存模块 | 4 个货物槽位 | 每槽同类限 10 个 |
| `Empty` | 基础模块 | 纯质量/装甲 | 无主动功能 |

## 物理模型

### 运动方程

基于 Rigidbody2D + Input System：

```
总推力 = Σ(动力模块推力系数) × 全局推力参数
力矩 = Σ(动力模块推力 × 模块到质心的垂直距离)[杠杆原理]
```

- 核心模块推力作用于质心，不产生力矩
- 动力模块推力按其相对于质心的位置产生力矩
- 超载时（模块数 > LoadCapacity），推力按比例衰减

### 碰撞

- 模块之间的碰撞体用于链接检测（非物理碰撞）
- 飞船整体使用 Rigidbody2D 与外部世界碰撞
- 碰撞反馈通过 `ShipCollisionFeedback` 产生摄像机震动

## 飞船蓝图（ShipBlueprint）

蓝图是 ScriptableObject，定义了飞船的初始布局：

```
ShipBlueprint
├── ShipModulePlacement[]
│   ├── ModuleKind
│   ├── LocalDirection (朝向)
│   ├── GridX, GridY (网格坐标)
│   └── ... 
└── ShipInitialCargoPlacement[]
    ├── CargoType
    ├── Count
    └── TargetStorageModuleIndex
```

蓝图运行时通过 `ShipPrefabRuntimeInstaller` 实例化为完整的 ShipAssembly。

## 运行流程

### 实例化流程（LevelContentInitializationController）

1. 读取 `SpaceshipGameConfiguration` → 获取玩家/敌舰蓝图
2. 遍历蓝图 `ShipModulePlacement[]`
3. 对每个放置项：从 `ModulePrefabCatalog` 获取对应 Prefab → Instantiate → 设置网格坐标和朝向
4. 建立模块间链接关系
5. 初始化货物（如果有）
6. 注册到 `ShipSceneRegistry`

### 销毁流程

1. 核心模块被摧毁 → 触发 `ShipAssembly` 摧毁
2. 广播 `ShipDestroyed` 事件（通过 `ShipFlowEventSource`）
3. 摄像机冻结（`ShipCameraFollower`）
4. 如果阵营为 Derelict → 生成残骸组（`SpaceshipWorldMap`）
5. 从 `ShipSceneRegistry` 注销
