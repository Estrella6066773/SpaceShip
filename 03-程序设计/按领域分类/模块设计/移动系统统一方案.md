# 移动系统统一方案

> 作者：代码分析生成 | 创建日期：2026-08-02 | 最后修改：2026-08-02
>
> **状态：已落地**（2026-08-02 实施）——`ShipActionCommand` / `IShipActionInput` / `PlayerShipInputSystem` / `ShipNavigation` 均已合入 `Spaceship.Gameplay.Ships.Movement` 模块。本文正文的「现状」描述为迁移前背景，实际代码以落地后的模块化结构为准。

本方案把玩家飞船与非玩家单位飞船的移动逻辑统一到同一套框架：**统一运动内核（执行层） + 导航指令层 + 玩家/AI 输入系统（决策层）**，由玩家输入系统和非玩家单位 AI 输入系统以相同方式向移动模块提交行动指令。

模式定义见 [模块分层与粘合代码模式](../架构设计/模块分层与粘合代码模式.md)。

---

## 现状与问题（迁移前）

| 位置 | 问题 |
|------|------|
| `ShipMotionController.ReadInput()` | 玩家 WASD 输入内嵌在移动模块内部，靠 `readPlayerInput` 布尔开关切换 |
| `NonPlayerUnitController.MoveToward / RotateToward / RotateByDegrees` | 「世界目标点 → 局部移动输入」的导航转换，第一份实现 |
| `NonPlayerUnitBehaviorAuthoring.RuntimeAdapter` | 同样的三份方法**逐行重复**，第二份实现（该组件已随非玩家单位整合移除） |
| `ShipWorkshopManualCombatInput` | 工坊试驾单独一套输入读取 |

物理执行本身已经统一（玩家与非玩家单位共用 `ShipMotionController`），需要拆分的是**输入源**与**导航指令转换**。

## 目标结构

```
L2 决策层（输入源）
┌─────────────────────────────────────────────────────┐
│  PlayerShipInputSystem      读 WASD/QE/鼠标           │
│  EnemyAiInputSystem         非玩家单位行为状态机 → 导航     │
│  WorkshopDriveInputSystem   工坊试驾                 │
└───────────────┬─────────────────────────────────────┘
                │ ShipActionCommand（统一行动指令）
                ▼
L0 执行层   ShipMotionController（物理驱动 + 性能计算）
                ▲
                │ MoveToward / RotateToward / RotateByDegrees
L1 指令层   ShipNavigation（目标点 → 局部输入转换）
                ▲
                │ 目标点
L2 决策层   NonPlayerUnitBehaviorController（非玩家单位 AI 状态机）
```

玩家、非玩家单位、工坊试驾三者在执行层完全共用；差异只出现在「谁产生指令、指令如何产生」。

> 落地说明：方案中的 `EnemyAiInputSystem` 输入源概念，实际以 `NonPlayerUnitController` 委托 `ShipNavigation`（行为状态机 → 导航 → 运动控制器）的方式实现，未新增独立组件类。

## 层与组件设计

### L0 执行层：`ShipMotionController` 改造

**保持不变**：物理驱动、性能计算（含动力模块加成与超载惩罚）、`Tick`、`GetPerformanceSnapshot`、`Velocity` 等查询。

**移除**：`ReadInput()` 方法与内部键盘读取。

**改造**：输入来源改为「输入源注入」，同时保留兼容回退。

```csharp
[Header("输入源")]
[SerializeField, Tooltip("产生行动指令的输入源；留空且启用旧版键盘读取时回退为玩家键盘输入。")]
private IShipActionInput actionInput;

[SerializeField, Tooltip("兼容旧场景：未显式注入输入源时，是否回退到本地玩家键盘输入。")]
private bool fallbackToPlayerKeyboardInput = true;
```

- `Update` 中不再自行读键盘，改为从 `actionInput`（或回退输入源）读取 `ShipActionCommand`。
- `SetManualInput` 保留，作为导航指令层与验收脚本的**旁路入口**（不经输入源，直接驱动），兼容现有调用方。

### L1 指令层：`ShipNavigation`（新增）

把「世界目标点」转换为飞船的局部推进与转向输入。这是从 `NonPlayerUnitController` 与 `RuntimeAdapter` 中**上提**的重复逻辑。

```csharp
/// <summary>
/// 导航指令层：把世界目标点转换为飞船的局部移动指令。
/// 玩家侧不直接使用；非玩家单位 AI 状态机与验收脚本通过它驱动飞船。
/// </summary>
public sealed class ShipNavigation
{
    private readonly ShipMotionController motion;
    private readonly ShipNavigationSettings settings;

    public ShipNavigation(ShipMotionController motion, ShipNavigationSettings settings) { ... }

    /// <summary>向目标点移动；角度在限位内时允许向前推进。</summary>
    public void MoveToward(Vector2 target, bool allowForward) { ... }

    /// <summary>仅转向指定世界坐标，不施加推进。</summary>
    public void RotateToward(Vector2 worldPoint) { ... }

    /// <summary>按正负角度方向持续转向。</summary>
    public void RotateByDegrees(float degrees) { ... }

    /// <summary>清空移动输入。</summary>
    public void Stop() { ... }
}
```

**参数配置**（`ShipNavigationSettings`，`[Serializable]`，中文 Tooltip）：

| 字段 | 含义 | 现出处 |
|------|------|--------|
| `moveTurnDeadZoneDegrees` | 移动时朝向死区 | `NonPlayerUnitBehaviorSettings.moveTurnDeadZoneDegrees` |
| `moveForwardAngleLimit` | 允许向前推进的角度限位 | `NonPlayerUnitBehaviorSettings.moveForwardAngleLimit` |
| `moveStrafeAngleLimit` | 开始叠加横移辅助的角度限位 | `NonPlayerUnitBehaviorSettings.moveStrafeAngleLimit` |
| `rotateDeadZoneDegrees` | 纯转向死区 | `NonPlayerUnitBehaviorSettings.rotateDeadZoneDegrees` |

非玩家单位行为参数中的这三个运行时驱动字段迁移到 `ShipNavigationSettings`；`NonPlayerUnitBehaviorSettings` 保留为纯行为节奏参数（距离/时长/间隔）。

## 急停（Counter-Strafe）

> 设计动机参考 FPS（CS:GO）的急停操作：正向移动中松开正向键后，快速按下反向键，利用反向推进把该轴向速度快速制动归零。本方案把该机制落到飞船的三维操控轴上，且**三个轴向独立判定、互不干扰，可同时触发叠加**。

### 行为定义

| 轴向 | 正向键 | 反向键 | 急停效果 |
|------|--------|--------|----------|
| WS（纵向） | W 前进 | S 后退 | 把飞船局部纵向（前/后）速度快速归零 |
| AD（横向） | D 右移 | A 左移 | 把飞船局部横向（左/右）速度快速归零 |
| QE（旋转） | E 顺时针 | Q 逆时针 | 把角速度快速归零 |

触发条件（每个轴向独立）：
1. 当前处于对应正向输入（正向键按住）；
2. 随后松开正向键，并在**急停触发窗口**内按下反向键（「松正 → 按反」间隔小于窗口）；
3. 窗口内按下反向键后进入急停减速，直到该轴向速度归零（或速度方向已与反向输入一致）。

急停期间该轴目标速度强制为 0，衰减速率使用急停减速速率（远高于普通加速度与阻力，实现快速制动）；速度归零后结束急停，若反向键持续按住则自然进入正常反向推进（对应 CS:GO「急停后继续按住反方向键会反向移动」的手感）。

### 实现

- **检测**：`ShipMotionController` 在 `Update` 中消费行动指令时，按 `move.x` / `move.y` / `turn` 三个轴向分别跑一个状态机（`CounterStrafeAxisState`），记录「松开正向键时刻」并在窗口内检测反向输入。三轴互不共享状态，可同时进入急停。
- **物理**：`Tick` 的线速度更新从「整体向量逼近」改为在飞船局部空间按横向/纵向两轴分别逼近。该重构与原有数学等价（旋转是等距变换），非急停轴行为完全不变；急停轴目标为 0 并使用急停衰减速率。
- **参数**（`ModuleDefinition` 核心模块，随核心装配生效）：

| 字段 | 含义 | 默认值 |
|------|------|--------|
| `counterStrafeWindowSeconds` | 急停触发窗口（松正向键到按反向键的最大间隔，秒） | 0.25 |
| `counterStrafeDeceleration` | 急停线速度衰减速率（米/秒²） | 120 |
| `counterStrafeAngularDeceleration` | 急停角速度衰减速率（度/秒²） | 2000 |

- **只读查询**（供特效 / UI / HUD 表现层使用）：`IsLongitudinalCounterStrafing`、`IsLateralCounterStrafing`、`IsRotationCounterStrafing`、`IsCounterStrafing`。

### 注意

- 急停只作用于「有对应轴向正向运动」的场景；速度已为零或已朝反向时不产生制动（物理层立即结束急停，交由正常推进逻辑）。
- 无核心（残骸）或输入被禁用时急停不生效；`SetInputEnabled(false)` 会清空全部急停状态。
- 若后续需要急停触发音效 / 特效反馈，通过事件-订阅框架新增 `CounterStrafeTriggeredEvent` 事件载荷，由装配层把事件源注入 `ShipMotionController`，避免玩法直接调用表现层 API。

#### 非玩家单位 AI 输入系统（`EnemyAiInputSystem`，与宿主合并同步推进）

```csharp
/// <summary>
/// 非玩家单位 AI 输入源：由非玩家单位行为状态机驱动，产生统一行动指令。
/// 内部经 ShipNavigation 把行为目标点转为移动输入，经 ShipCombatController 开火。
/// </summary>
public sealed class EnemyAiInputSystem : MonoBehaviour, IShipActionInput
{
    private NonPlayerUnitBehaviorController behavior;   // 决策层
    private ShipNavigation navigation;              // 指令层
    // 实现 IShipActionInput.ReadCommand()，把行为结果汇总为 ShipActionCommand
}
```

`INonPlayerUnitRuntime` 接口保留，但宿主实现变薄：`MoveToward / RotateToward / RotateByDegrees / StopMove` 直接委托 `ShipNavigation`，`FireCannon` 委托 `ShipCombatController`，`IsReachable` 委托传感器——不再各自手写转换。

#### 工坊试驾输入

`ShipWorkshopManualCombatInput` 改造为实现 `IShipActionInput`，或合并进 `PlayerShipInputSystem` 的可选开关（试驾时接管开火与移动）。

## 兼容与迁移

| 兼容点 | 策略 |
|--------|------|
| 旧场景 `readPlayerInput = true` | `ShipMotionController` 保留字段；未注入输入源时回退到玩家键盘输入，行为不变 |
| `SetManualInput` 调用方 | 保留为旁路入口，非玩家单位合并完成前 `NonPlayerUnitController` 可继续使用 |
| 手工场景验证器 | 阶段二结束后补充「输入源必须装配」的校验项 |
| `ShipPrefabRuntimeInstaller` | `Configure` 重载继续生效，读取 `readPlayerInput` 决定装配哪个输入源 |
