# 移动系统统一方案

> 作者：代码分析生成 | 创建日期：2026-08-02 | 最后修改：2026-08-02

本方案把玩家飞船与敌人飞船的移动逻辑统一到同一套框架：**统一运动内核（执行层） + 导航指令层 + 玩家/AI 输入系统（决策层）**，由玩家输入系统和敌人 AI 输入系统以相同方式向移动模块提交行动指令。

模式定义见 [模块分层与粘合代码模式](../架构设计/模块分层与粘合代码模式.md)。

---

## 现状与问题

| 位置 | 问题 |
|------|------|
| `ShipMotionController.ReadInput()` | 玩家 WASD 输入内嵌在移动模块内部，靠 `readPlayerInput` 布尔开关切换 |
| `EnemyShipController.MoveToward / RotateToward / RotateByDegrees` | 「世界目标点 → 局部移动输入」的导航转换，第一份实现 |
| `EnemyShipBehaviorAuthoring.RuntimeAdapter` | 同样的三份方法**逐行重复**，第二份实现 |
| `ShipWorkshopManualCombatInput` | 工坊试驾单独一套输入读取 |

物理执行本身已经统一（玩家与敌舰共用 `ShipMotionController`），需要拆分的是**输入源**与**导航指令转换**。

---

## 目标结构

```
L2 决策层（输入源）
┌─────────────────────────────────────────────────────┐
│  PlayerShipInputSystem      读 WASD/鼠标             │
│  EnemyAiInputSystem         敌人行为状态机 → 导航     │
│  WorkshopDriveInputSystem   工坊试驾                 │
└───────────────┬─────────────────────────────────────┘
                │ ShipActionCommand（统一行动指令）
                ▼
L0 执行层   ShipMotionController（物理驱动 + 性能计算）
                ▲
                │ MoveToward / RotateToward / RotateByDegrees
L1 指令层   ShipNavigation（目标点 → 局部输入转换）
                ▲
                │ 目标点
L2 决策层   EnemyShipBehaviorController（敌舰 AI 状态机）
```

玩家、敌舰、工坊试驾三者在执行层完全共用；差异只出现在「谁产生指令、指令如何产生」。

## 层与组件设计

### L0 执行层：`ShipMotionController` 改造

**保持不变**：物理驱动、性能计算（含动力模块加成与超载惩罚）、`Tick`、`GetPerformanceSnapshot`、`Velocity` 等查询。

**移除**：`ReadInput()` 方法与内部键盘读取。

**改造**：输入来源改为「输入源注入」，同时保留兼容回退。

```csharp
[Header("输入源")]
[SerializeField, Tooltip("产生行动指令的输入源；留空且启用旧版键盘读取时回退为玩家键盘输入。")]
private IShipActionInput actionInput;

[SerializeField, Tooltip("兼容旧场景：未显式注入输入源时，是否回退到本地玩家键盘输入。")]
private bool fallbackToPlayerKeyboardInput = true;
```

- `Update` 中不再自行读键盘，改为从 `actionInput`（或回退输入源）读取 `ShipActionCommand`。
- `SetManualInput` 保留，作为导航指令层与验收脚本的**旁路入口**（不经输入源，直接驱动），兼容现有调用方。

### L1 指令层：`ShipNavigation`（新增）

把「世界目标点」转换为飞船的局部推进与转向输入。这是从 `EnemyShipController` 与 `RuntimeAdapter` 中**上提**的重复逻辑。

```csharp
/// <summary>
/// 导航指令层：把世界目标点转换为飞船的局部移动指令。
/// 玩家侧不直接使用；敌人 AI 状态机与验收脚本通过它驱动飞船。
/// </summary>
public sealed class ShipNavigation
{
    private readonly ShipMotionController motion;
    private readonly ShipNavigationSettings settings;

    public ShipNavigation(ShipMotionController motion, ShipNavigationSettings settings) { ... }

    /// <summary>向目标点移动；角度在限位内时允许向前推进。</summary>
    public void MoveToward(Vector2 target, bool allowForward) { ... }

    /// <summary>仅转向指定世界坐标，不施加推进。</summary>
    public void RotateToward(Vector2 worldPoint) { ... }

    /// <summary>按正负角度方向持续转向。</summary>
    public void RotateByDegrees(float degrees) { ... }

    /// <summary>清空移动输入。</summary>
    public void Stop() { ... }
}
```

**参数配置**（`ShipNavigationSettings`，`[Serializable]`，中文 Tooltip）：

| 字段 | 含义 | 现出处 |
|------|------|--------|
| `moveTurnDeadZoneDegrees` | 移动时朝向死区 | `EnemyBehaviorSettings.moveTurnDeadZoneDegrees` |
| `moveForwardAngleLimit` | 允许向前推进的角度限位 | `EnemyBehaviorSettings.moveForwardAngleLimit` |
| `rotateDeadZoneDegrees` | 纯转向死区 | `EnemyBehaviorSettings.rotateDeadZoneDegrees` |

敌舰行为参数中的这三个运行时驱动字段迁移到 `ShipNavigationSettings`；`EnemyBehaviorSettings` 保留为纯行为节奏参数（距离/时长/间隔）。

### L2 决策层：输入源

#### 玩家输入系统（新增 `PlayerShipInputSystem`）

```csharp
/// <summary>
/// 玩家输入源：读取本地键盘与鼠标，产生统一行动指令。
/// 装配在玩家飞船根对象上，替代原本内嵌于移动/战斗模块内的输入读取。
/// </summary>
public sealed class PlayerShipInputSystem : MonoBehaviour, IShipActionInput
{
    // 从 ShipMotionController.ReadInput 迁入 WASD 读取
    // 从 ShipCombatController 迁入鼠标左键开火读取
    // 从 ShipAssemblyInteractionController 迁入鼠标右键交互读取（可选，阶段二）
    // 提供 SetActionsEnabled 控制，受游戏流程（Title/Failure 等状态）开关
}
```

#### 敌人 AI 输入系统（`EnemyAiInputSystem`，与宿主合并同步推进）

```csharp
/// <summary>
/// 敌人 AI 输入源：由敌舰行为状态机驱动，产生统一行动指令。
/// 内部经 ShipNavigation 把行为目标点转为移动输入，经 ShipCombatController 开火。
/// </summary>
public sealed class EnemyAiInputSystem : MonoBehaviour, IShipActionInput
{
    private EnemyShipBehaviorController behavior;   // 决策层
    private ShipNavigation navigation;              // 指令层
    // 实现 IShipActionInput.ReadCommand()，把行为结果汇总为 ShipActionCommand
}
```

`IEnemyShipRuntime` 接口保留，但宿主实现变薄：`MoveToward / RotateToward / RotateByDegrees / StopMove` 直接委托 `ShipNavigation`，`FireCannon` 委托 `ShipCombatController`，`IsReachable` 委托传感器——不再各自手写转换。

#### 工坊试驾输入

`ShipWorkshopManualCombatInput` 改造为实现 `IShipActionInput`，或合并进 `PlayerShipInputSystem` 的可选开关（试驾时接管开火与移动）。

## 兼容与迁移

| 兼容点 | 策略 |
|--------|------|
| 旧场景 `readPlayerInput = true` | `ShipMotionController` 保留字段；未注入输入源时回退到玩家键盘输入，行为不变 |
| `SetManualInput` 调用方 | 保留为旁路入口，敌舰合并完成前 `EnemyShipController` 可继续使用 |
| 手工场景验证器 | 阶段二结束后补充「输入源必须装配」的校验项 |
| `ShipPrefabRuntimeInstaller` | `Configure` 重载继续生效，读取 `readPlayerInput` 决定装配哪个输入源 |

## 落地步骤

1. 新增 `ShipActionCommand` 与 `IShipActionInput`（与架构总纲同步）。
2. 新建 `ShipNavigation` + `ShipNavigationSettings`，把 `EnemyShipController` / `RuntimeAdapter` 的导航转换迁入。
3. 新建 `PlayerShipInputSystem`，把 `ShipMotionController.ReadInput` 迁入；`ShipMotionController` 改为消费输入源。
4. 改造 `EnemyAiInputSystem`（依赖敌舰行为整合方案的宿主合并）。
5. 迁移 `ShipCombatController` 开火输入到玩家输入源（或先保留内部读取，阶段二处理）。
6. 更新手工场景装配文档与验证器。
