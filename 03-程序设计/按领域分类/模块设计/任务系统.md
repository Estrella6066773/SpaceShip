## 1. 系统概述

任务系统统一管理任务生命周期：激活检测、接取、按事件推进阶段、完成判定、奖励发放与状态持久化。本版仅主线任务，四类目标（摧毁敌舰 / 收集货物 / 到达目的地 / 存活天数），奖励仅金币。

**实现形态**：与商店系统一致——业务收敛在**可重建的领域服务** `QuestService`（无 MonoBehaviour 依赖，状态全部来自存档，可在任意场景重建），场景装配器 `QuestSystem` 负责装配、订阅事件、桥接事件源与持久化。因此任务系统可同时挂载于**休整站场景**（UI 查看 / 接取）与**探索场景**（事件推进 / 完成发放），两处共享同一份存档状态。

```
QuestEventSource（场景实例，广播任务事件）◄── UI / Audio / FX 订阅
    ▲
QuestSystem（场景装配器）
    ├── 订阅 探索事件源（ShipFlowEventSource / CargoEventSource）→ 推进进度
    ├── 持有 QuestService（领域服务，可重建）
    │     ├── QuestConfig / QuestGroupConfig（ScriptableObject，静态配置）
    │     ├── QuestRuntimeState（运行时状态：状态 + 当前阶段 + 进度）
    │     └── CoinManager（奖励金币，Command）
    └── GameSaveService（任务状态持久化，Command）
```

## 3. 配置层（ScriptableObject）

### 3.1 QuestConfig

```csharp
[CreateAssetMenu(menuName = "Spaceship/任务/任务定义", fileName = "任务定义")]
public sealed class QuestConfig : ScriptableObject
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `displayName` | `string` | 任务显示名称（中文） |
| `description` | `string` | 任务目标描述，任务界面展示 |
| `stages` | `List<QuestStageConfig>` | 有序阶段列表；**本版每任务至少 1 个阶段**（D-11） |
| `prerequisites` | `List<QuestConfig>` | 前置任务组（资产引用，避免循环引用；空 = 起始任务） |
| `prerequisiteLogic` | `QuestPrerequisiteLogic` | 前置逻辑：`All` 全部完成 / `Any` 任一完成（D-3） |
| `rewards` | `List<QuestRewardConfig>` | 完成时发放的奖励；本版仅金币（D-15） |

**稳定 ID**：任务节点以**资产名**（`name`）作为跨会话稳定 ID（参照商店 `GoodsKey` 用资产名的先例），用于存档条目与 UI 标识。

**校验规则**（`QuestConfig` 上提供 `bool IsValid` 静态校验）：
- `stages` 非空；
- 每阶段至少 1 个目标（本版约束恰好 1 个）；
- `prerequisites` 不包含自身（防循环激活）。

## 4. 运行时

### 4.1 状态枚举与运行时状态

```csharp
public enum QuestState
{
    [InspectorName("未激活")] Inactive,     // 激活条件未满足，任务不可见
    [InspectorName("待接取")] Available,    // 激活条件已满足，可被接取
    [InspectorName("进行中")] InProgress,   // 已接取，正在执行
    [InspectorName("已完成")] Completed     // 全部阶段完成，奖励已发放
}
```

**运行时状态 `QuestRuntimeState`**（每任务一份，存于 `QuestService`，随存档持久化）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `Config` | `QuestConfig` | 静态配置引用（资产） |
| `State` | `QuestState` | 任务状态 |
| `CurrentStageIndex` | `int` | 当前阶段索引（0 起） |
| `StageProgress` | `int` | 当前阶段目标当前进度值（本版每阶段单目标，单值即可表达；多目标版本扩为列表，D-10 预留点在配置层已预留） |

> **单值进度的自洽说明**：D-10 的「结构预留目标列表」落在配置层 `QuestStageConfig.objectives`（列表），运行时因本版每阶段恰一个目标，`StageProgress` 用单值即可；后续启用多目标时，将 `StageProgress` 改为按目标索引的列表，配置层无需变动。

### 4.2 QuestService（领域服务）

```csharp
public sealed class QuestService
```

**构造**：

```csharp
public QuestService(
    IReadOnlyList<QuestConfig> allQuestConfigs,   // 策划配置的全部任务节点（含组）
    SaveData saveData)                            // 存档：恢复/保存任务状态
```

构造时**从存档恢复**所有任务状态：已存档的任务按条目恢复；未存档的任务按激活条件初始化（起始任务 → `Available`，其余 → `Inactive`）。

**事件**（领域级，由 `QuestSystem` 桥接到场景事件源）：

| 事件 | 触发时机 |
|------|----------|
| `event Action<QuestStateChangedEvent> StateChanged` | 任何任务状态变更（含激活、接取、完成） |
| `event Action<QuestStageChangedEvent> StageChanged` | 阶段推进 |
| `event Action<QuestProgressChangedEvent> ProgressChanged` | 进行中任务阶段进度变化 |
| `event Action<QuestAcceptedEvent> Accepted` | 接取成功 |
| `event Action<QuestCompletedEvent> Completed` | 任务完成、奖励已发放 |

**Command（接取 / 持久化）**：

| 方法 | 签名 | 说明 |
|------|------|------|
| 接取任务 | `bool AcceptQuest(QuestConfig config)` | 仅 `Available` 可接取 → `InProgress`；否则返回 `false`（UI 命令调用，同步有结果） |
| 持久化 | `void PersistQuestStates()` | 把全部任务状态写入存档（`SaveData`）；由装配器在状态变更后调用 |

**Query（只读，供 UI）**：

| 查询 | 签名 | 返回 |
|------|------|------|
| 可见任务 | `IReadOnlyList<QuestRuntimeState> GetVisibleQuests()` | 待接取 + 进行中 + 已完成 |
| 全部任务 | `IReadOnlyList<QuestRuntimeState> GetAllQuests()` | 全部任务状态（含未激活；UI 遍历按组归类） |
| 按组归类 | `IEnumerable<IGrouping<QuestGroupConfig, QuestRuntimeState>> GetQuestsByGroup()` | 可见任务按组名分组 |
| 目标描述 | `string GetObjectiveDescription(QuestRuntimeState state)` | 当前阶段目标的人类可读描述（如「摧毁敌舰 0/3」） |
| 阶段进度 | `(int current, int target) GetStageProgress(QuestRuntimeState state)` | 当前阶段索引、当前值 / 目标值 |

**内部规则**（不进公共 API）：

#### 激活检测 `EvaluateActivations()`

- 遍历全部 `Inactive` 任务；
- 前置为空 → `Available`（起始任务）；
- 前置非空 → 按 `prerequisiteLogic` 检查前置任务是否全部 / 任一 `Completed`；
- 满足 → 状态置 `Available`，广播 `QuestStateChanged`（一个任务完成可扇出激活多个任务，D-5）；
- 检测时机：`QuestService` 构造后、任意任务状态变更后（接取与完成统一走此处）。

#### 接取

```csharp
public bool AcceptQuest(QuestConfig config)
```

- `config == null` 或状态 ≠ `Available` → 返回 `false`；
- 置 `InProgress`，广播 `QuestStateChanged` + `QuestAccepted`，持久化。

#### 事件推进 `AdvanceProgress(...)`

由装配器把探索事件源的事件转发到服务。对每个 `InProgress` 任务，仅当**当前阶段目标类型**与事件匹配时更新进度：

| 目标类型 | 订阅事件 | 载荷字段 → 进度 | 达成判定 |
|----------|----------|------------------|----------|
| `KillEnemies` | `ShipDestroyedEvent` | `ship.Faction == ShipFaction.Enemy` 时进度 +1 | `progress >= targetValue` |
| `CollectCargo` | `CargoChangedEvent` | `cargoType.ToCategory() == config.CargoCategory` 时 `progress = total` | `total >= targetValue` |
| `ReachDestination` | `ExpeditionCompletedEvent` | 事件到临时计数（见下） | `Destination == destinationName` |
| `SurviveDays` | `DayEndedEvent` | `progress = dayIndex + 1` | `progress >= targetValue` |

> **`ReachDestination` 语义**：目标「到达 X 地点」，事件携带目的地名称，到达即达成（非累加）。为与单值进度一致，其 `targetValue` 固定为 1，达成时 `progress = 1`。
> **`CollectCargo` 语义**：`CargoChangedEvent` 携带该类别**总量**（`total`），进度直接取总量（可能因消耗回退），与「玩家持有某类别货物达量」一致；事件字段为旧版 `CargoType`，经 `CargoCategoryCompatibility.ToCategory()` 转换后再与目标类别比较。
> **`KillEnemies` 敌我判定**：`ShipDestroyedEvent.Ship.Faction`（`ShipAssembly.Faction`）为 `Enemy` 才计数；残骸/玩家/中立不计。

#### 阶段推进与完成判定

1. 当前阶段进度达成 → 阶段完成；
2. 广播 `QuestProgressChanged`（达到目标值）与 `QuestStageChanged`（`oldStageIndex → newStageIndex`）；
3. 进入下一阶段（`CurrentStageIndex++`，`StageProgress = 0`）；
4. 若已是**最后一个阶段** → 任务 `Completed`：
   - 发放奖励：对每条 `rewards`，`Gold` → `coins.TryAdd(amount)`（Command，D-8 / C-10）；
   - 广播 `QuestStateChanged` + `QuestCompleted`（载荷含奖励明细）；
   - 持久化；
   - 触发新一轮激活检测 `EvaluateActivations()`（D-5 扇出）。

> **奖励发放通道**：`QuestService` 通过构造注入的 `CoinManager` 发放金币；金币变更由货币系统的 `CoinsChanged` 广播，任务系统**不重复广播金币事件**（任务系统设计 §5）。

## 5. 存档

### 5.1 QuestSaveEntry

```csharp
[Serializable]
public sealed class QuestSaveEntry
{
    private string questId;          // QuestConfig.name（稳定 ID）
    private int questState;          // QuestState（存整数枚举）
    private int currentStageIndex;   // 当前阶段索引
    private int stageProgress;       // 当前阶段进度当前值
}
```

> **防重复领奖**（D-13 核心动机）：任务 `Completed` 状态随存档持久化，重开恢复为 `Completed`，不会再回到 `Available`，玩家无法重复接取重复领奖。

### 5.2 SaveData 扩展

| 新增成员 | 类型 | 说明 |
|----------|------|------|
| `questStates` | `List<QuestSaveEntry>` | 全部任务状态条目 |
| `ReplaceQuestStates(...)` | 方法 | 整表替换（`QuestService` 持久化时调用） |
| `IReadOnlyList<QuestSaveEntry> QuestStates` | 只读属性 | 恢复时读取 |

### 5.3 schemaVersion

> 系统设计文档 D-13 写「`schemaVersion` 升至 4」，但商店系统实现时**存档已占用 4**（`GameSaveService.cs` 当前 `schemaVersion = 4`）。因此任务系统实际接入时 `schemaVersion` 默认值直接设为 **5**。

按存档版本维护规则（见 `.cursor/rules/save-data-versioning.mdc`）：当前开发阶段**不考虑新旧存档的兼容与迁移**——存档结构变更直接更新 `schemaVersion`，不编写旧档迁移或适配逻辑。

## 6. 场景装配

### 6.1 QuestSystem（场景装配器）

```csharp
[DisallowMultipleComponent]
public sealed class QuestSystem : MonoBehaviour
```

| SerializeField | 类型 | 说明 |
|----------------|------|------|
| `questConfigs` | `List<QuestConfig>` | 全部任务节点（休整站与探索场景各自装配，同一组资产） |
| `questEvents` | `QuestEventSource` | 场景任务事件源 |
| `saveService` | `GameSaveService` | 单存档服务 |
| `flowEvents` | `ShipFlowEventSource` | 探索事件源（飞船/天数/出航完成） |
| `cargoEvents` | `CargoEventSource` | 探索事件源（货物变化） |
| `coins` | `CoinManager` | 奖励金币的货币管理器；**休整站复用 `ShopSystem.Coins`** |

**CoinManager 复用规则**（重要）：
- 休整站场景：`coins` 显式注入 `ShopSystem.Coins`（同一实例，保证商店 UI 与任务奖励共享同一金币广播通道）；
- 探索场景：`coins` 留空 → 懒创建 `new CoinManager(saveService.Data)`，并把其 `CoinsChanged` 桥接到探索场景金币事件源（`ShipFlowEventSource.CoinsChanged`），保证探索 HUD 刷新。

**懒初始化 `EnsureInitialized()`**（首次访问 `Quests` / `QuestEventSource` 时）：

1. 自补 `GetComponentInChildren` 缺失引用（测试友好）；
2. 创建 `QuestService(allQuestConfigs, saveService.Data)`；
3. 桥接领域事件 → 场景事件源（5 个事件逐一转发）；
4. 订阅探索事件源：`flowEvents.ShipDestroyed`、`flowEvents.DayEnded`、`flowEvents.ExpeditionCompleted`、`cargoEvents.CargoChanged` → 转发 `AdvanceProgress`；
5. 初始化激活检测 `EvaluateActivations()`。

**卸载**：`OnDestroy` 退订全部事件源订阅，避免场景切换残留。

**持久化入口**：状态变更后由 `QuestService` 内部触发 `PersistQuestStates()`，随后装配器调用 `saveService.Save()`（写入时机与金币一致：变更即存、退出前存）。

**对外查询（供 QuestPanel）**：`public QuestService Quests => EnsureInitialized() ...`（只读访问领域服务）。

与 `ShopPanel` 同构（IMGUI 覆盖层），仅挂休整站场景。

|------|------|

## 8. 通信契约汇总

| 通信 | 形式 | 方向 |
|------|------|------|
| 探索事件 → 进度推进 | 事件订阅 | QuestSystem → ShipFlowEventSource / CargoEventSource |
| 奖励发放 | Command | QuestService → CoinManager（`TryAdd`） |
| 任务状态持久化 | Command | QuestService → GameSaveService |
| 任务状态广播 | 事件广播 | QuestService → QuestEventSource → UI |
| 可见任务 / 进度 / 描述查询 | Query | UI → QuestSystem.Quests |
| 接取任务 | Command | UI → QuestSystem.Quests（`AcceptQuest`） |
| 金币变更 | 复用 `CoinsChanged` | CoinManager → 金币事件源（任务系统不重复广播） |

**禁止的反模式**（对齐事件-订阅规则）：
- UI 直接修改任务状态（接取必须走 `AcceptQuest` 命令）；
- QuestService 引用 UI / 事件源引用订阅者；
- 用轮询替代事件推进（四类目标全部有事件支撑，不新增轮询）；
- 为「接取结果 / 激活条件满足与否」强行套事件（用 Command 返回值）。

## 9. 关键流程（时序）

### 9.1 接取 → 完成（单目标示例：摧毁敌舰 ×3）

```
休整站：QuestPanel ──AcceptQuest(序章)──▶ QuestService：Inactive→InProgress
                ◄── QuestStateChanged / QuestAccepted ──（面板刷新）
探索：  ShipAssembly.MarkDestroyed ──▶ ShipFlowEventSource ──▶ QuestSystem
         ──AdvanceProgress──▶ QuestService：ShipDestroyed 且 Faction==Enemy，进度+1
                ◄── QuestProgressChanged（0/3 → 1/3）
（重复至 3/3）
         ──▶ 阶段完成 → QuestStageChanged（如有下一阶段）
         ──▶ 最后阶段完成 → QuestState=Completed
                 ├── CoinManager.TryAdd(奖励金币) → CoinsChanged（金币 HUD 刷新）
                 ├── QuestStateChanged / QuestCompleted ──▶ 面板
                 ├── PersistQuestStates → saveService.Save()
                 └── EvaluateActivations()（扇出激活后续任务）
```

### 9.2 存档恢复（重开）

```
GameSaveService.Load ──▶ SaveData（含 questStates）
QuestSystem.EnsureInitialized ──▶ QuestService 构造：按条目恢复状态
    ├── 已完成任务 → Completed（不再 Available，防重复领奖）
    ├── 进行中任务 → InProgress + 当前阶段进度
    └── 未存档任务 → 起始任务 Available / 其余 Inactive → EvaluateActivations()
```

## 10. 测试要点

| 场景 | 验证内容 |
|------|----------|
| 起始任务 | 首次初始化后 `Available`，面板可见、可接取 |
| 线性解锁 | 前置 `All`：完成 A 后 B 从 `Inactive → Available` |
| 分支解锁 | 前置 `Any`：a / b 任一完成即解锁 c |
| 扇出激活 | 一个任务完成同时激活多个后续任务 |
| 多任务并行 | 同时持有多个 `InProgress`，各自独立推进 |
| 阶段推进 | 「先到 A 再回 B」两阶段任务顺序推进，`QuestStageChanged` 正确 |
| 四类目标 | 各目标的事件映射、进度累计与达成判定（含敌舰阵营过滤、货物类别匹配、目的地名称匹配、天数累计） |
| 奖励发放 | 完成 → 金币增加且仅一次；`CoinsChanged` 广播一次 |
| 防重复领奖 | 完成 → 退出 → 重开 → 任务保持 `Completed`，不可再接取 |
| 存档读写 | `schemaVersion=5` 存档正常读写，任务状态正确恢复（不做旧档迁移） |
| 休整站/探索双装配 | 两场景各自装配同一资产组，状态经存档一致 |
