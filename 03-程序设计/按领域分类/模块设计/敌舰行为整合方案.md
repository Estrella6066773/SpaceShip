# 敌舰行为整合方案

> 作者：代码分析生成 | 创建日期：2026-08-02 | 最后修改：2026-08-02
>
> **状态：已落地**（2026-08-02 模块化迁移中完成）——`EnemyShipController` 与行为状态机已合入 `Spaceship.Gameplay.Enemies` 模块，`Wuqiwusheng.EnemyBehavior` / `Kaki.Spaceship` 等旧命名空间已统一为 `Spaceship.<Module>`。

本方案合并敌舰行为系统目前存在的**两个并行宿主**，消除 `IEnemyShipRuntime` 的重复实现，并与 [移动系统统一方案](./移动系统统一方案.md) 联动，让敌舰的移动指令统一走 `ShipNavigation` 指令层。

模式定义见 [模块分层与粘合代码模式](../架构设计/模块分层与粘合代码模式.md)。

---

## 现状与问题

同一个行为状态机 `EnemyShipBehaviorController`（`Wuqiwusheng.EnemyBehavior`）目前有两个宿主：

| 宿主 | 位置 | 职责 | 独有能力 |
|------|------|------|----------|
| `EnemyShipController` | `Kaki.Spaceship`（场景实际使用） | 实现 `IEnemyShipRuntime`，驱动移动/开火；实现 `IEnemyShipBehaviorDriver` 反扫描 | 反扫描驱动、旧 UI 兼容状态 `EnemyShipState` |
| `EnemyShipBehaviorAuthoring` | `Wuqiwusheng.EnemyBehavior`（并行替代） | 自带私有 `RuntimeAdapter`，同样完整实现 `IEnemyShipRuntime` | 丰富调试：Gizmo 标签、逐帧日志、可达性/移动决策日志 |

### 重复代码规模

两个 `IEnemyShipRuntime` 实现中，以下方法**逐行重复**（共约 200 行）：

- `MoveToward`（世界目标点 → 局部输入）
- `RotateToward` / `RotateByDegrees`
- `IsReachable`（照明遮挡判定）
- `FireCannon`（检测开火是否成功）
- `TryGetRadarPlayerPosition`（雷达反扫描）
- `IsActiveModuleKind` 筛选条件
- `ResolvePlayerShip`（从场景名册解析玩家）

`EnemyShipBehaviorAuthoring.Awake` 还会通过 `disableBuiltInEnemyController` 禁用 `EnemyShipController`，两个组件在同一实体上互斥共存，是「双轨并存」的直接来源。

---

## 目标：单一宿主

合并后敌舰根对象只挂载**一个**宿主组件，其职责结构如下：

```
EnemyShipController（合并后的唯一宿主）
│
├── 决策层   EnemyShipBehaviorController   ← wuqiwusheng 状态机，保持不变
├── 指令层   ShipNavigation                 ← 统一导航转换（移动方案 L1）
├── 执行层   ShipMotionController           ← 移动物理
│            ShipCombatController           ← 开火
│            ShipSensorModules              ← 感知（雷达 / 照明）
│
├── 适配粘合 IEnemyShipRuntime 实现          ← 变薄：委托指令层/执行层
│            IEnemyShipBehaviorDriver       ← 反扫描驱动（保留）
│            EnemyShipState                 ← 旧 UI 兼容概略状态（保留）
│
└── 调试开关 统一 Debug 配置组               ← 原 Kaki + wuqiwusheng 全部开关合并
```

### 关键设计

1. **宿主位置**：合并后的 `EnemyShipController` 暂留在 `Kaki.Spaceship`（场景中 `ShipSceneRegistry` 与验证器依赖它）。目录与命名空间按模块重组属于阶段六（跨开发者迁移），本方案只做代码结构合并。
2. **行为状态机归属**：`EnemyShipBehaviorController`、`EnemyBehaviorContext`、`IEnemyShipRuntime`、`EnemyBehaviorSettings` 等类型保持 `Wuqiwusheng.EnemyBehavior` 命名空间不变，作为「敌舰 AI 决策模块」的核心；后续目录迁移时整体搬迁。
3. **`EnemyShipBehaviorAuthoring` 移除**：其调试能力并入唯一宿主的开关；组件与 `EnemyBehaviorAttachTool` 编辑器工具一起退役。

## 宿主实现（合并后）

### 导航与移动（变薄）

`IEnemyShipRuntime` 中以下方法改为委托，不再手写转换：

| 接口成员 | 委托目标 |
|----------|----------|
| `MoveToward(target, allowForward)` | `navigation.MoveToward` |
| `RotateToward(worldPoint)` | `navigation.RotateToward` |
| `RotateByDegrees(degrees)` | `navigation.RotateByDegrees` |
| `StopMove()` | `navigation.Stop` |
| `IsReachable(target)` | `sensors.TryGetLightBlockingHit`（保留现逻辑，去掉重复的遍历实现） |
| `FireCannon()` | `combat.TryFireAll` + `WasCannonFiredRecently` |
| `TryGetRadarPlayerPosition(out pos)` | `sensors.TriggerImmediateScan` + `sensors.Contacts` |

`EnemyBehaviorSettings` 中仅保留**行为节奏参数**（距离/时长/间隔/角度范围）；`moveTurnDeadZoneDegrees`、`moveForwardAngleLimit`、`rotateDeadZoneDegrees`、`lightSurfaceOffset` 迁移到 `ShipNavigationSettings` 与传感器配置。

### 反扫描驱动（保留）

```csharp
public interface IEnemyShipBehaviorDriver
{
    bool ActionsEnabled { get; }
    void SetActionsEnabled(bool enabled);
    void OnScannedBy(ShipAssembly scanner);
}
```

`OnScannedBy` 逻辑保留：被玩家雷达扫中时立即反扫描，把雷达结果交给行为框架的搜索阶段。`ShipSensorModules.NotifyScannedTarget` 不再需要从多个 `MonoBehaviour` 里寻找驱动者，直接调用唯一宿主。

### 调试开关统一

| 开关 | 原宿主 | 合并后 |
|------|--------|--------|
| `verboseLogging` | Kaki | 保留，作为总日志开关 |
| `drawDebugGizmos` | 两者都有 | 保留，绘制出生点/目标/玩家连线 |
| `enableDetailedDebug` | wuqiwusheng | 保留，开启 Scene 标签 |
| `drawDebugLabels` | wuqiwusheng | 保留 |
| `logRuntimeSignals` / `logTargetChanges` / `logMovementDecisions` / `logReachabilityChecks` | wuqiwusheng | 并入一个 `[Header("调试")]` 分组，默认关闭 |

## 落地步骤

1. 新建 `ShipNavigation` + `ShipNavigationSettings`（见移动系统方案），迁入导航转换。
2. 把 `EnemyShipBehaviorAuthoring` 的调试开关与 Gizmo 绘制并入 `EnemyShipController`。
3. 重写 `EnemyShipController` 的 `IEnemyShipRuntime` 实现为薄委托。
4. 删除 `EnemyShipBehaviorAuthoring` 及其 `RuntimeAdapter`；同步更新 `EnemyBehaviorAttachTool`（或一并移除）。
5. 更新 `ShipSensorModules.NotifyScannedTarget` 为直接调用唯一宿主。
6. 更新手工场景验证器：敌舰组件检查改为「必须挂载合并后的宿主」。
