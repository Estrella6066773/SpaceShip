# 事件系统设计

> 作者：代码分析生成 | 创建日期：2026-07-29 | 最后修改：2026-08-02

本文档描述 Spaceship 项目的实例事件系统架构。

---

## 设计目标

1. **解耦玩法与表现**：UI、Audio、FX 不反向控制玩法系统
2. **类型安全**：每个事件类型有强类型载荷结构体
3. **零堆分配**：事件载荷均为 `readonly struct`
4. **可追溯**：所有事件源在 Inspector 中可见
5. **单向广播**：事件源不引用订阅者

---

## 架构

```
SpaceshipEventSource (abstract MonoBehaviour)
├── ShipFlowEventSource    → 飞船生命周期事件
├── ModuleEventSource      → 模块变更事件
└── CargoEventSource       → 货物变更事件
```

每个事件源是一个场景中的 MonoBehaviour 实例，在 Inspector 中由 Director 引用。订阅者通过 C# event 标准机制订阅。

---

## 事件源基类

```csharp
public abstract class SpaceshipEventSource : MonoBehaviour { }
```

基类为标记用（区分事件源组件），`SpaceshipGameState` 枚举与全部事件载荷 struct 均定义在 `SpaceshipEventSource.cs`。

### 约束

- 不得引用任何订阅者
- 不得保存玩法状态
- 不得执行业务规则
- 只负责「广播已发生的事实」

## 事件类型清单

所有事件载荷定义在 `SpaceshipEventSource.cs` 中：

### ShipFlowEventSource

| 事件 | 载荷类型 | 广播时机 |
|------|----------|----------|
| `ShipSpawned` | `ShipSpawnedEvent` | 飞船完成初始化并注册 |
| `ShipDestroyed` | `ShipDestroyedEvent` | 飞船被摧毁（核心毁/动力全毁/燃料耗尽/能源不足） |
| `DayEnded` | `DayEndedEvent` | 日循环结束（时长由世界规则配置） |
| `GameStateChanged` | `GameStateChangedEvent` | 状态机切换 |
| `ExpeditionCompleted` | `ExpeditionCompletedEvent` | 降落新星球或返航母星 |

### ModuleEventSource

| 事件 | 载荷类型 | 广播时机 |
|------|----------|----------|
| `ModulesChanged` | `ModulesChangedEvent` | 模块链接/拆除/安装 |
| `ModuleDestroyed` | `ModuleDestroyedEvent` | 单个模块生命值归零 |
| `CoreExploded` | `CoreExplodedEvent` | 核心模块被摧毁时对相邻八格结算爆炸伤害后 |
| `RadarScanned` | `RadarScanEvent` | 雷达扫描完成 |

### CargoEventSource

| 事件 | 载荷类型 | 广播时机 |
|------|----------|----------|
| `CargoChanged` | `CargoChangedEvent` | 货物数量增减 |
| `EpicCargoAcquired` | `EpicCargoAcquiredEvent` | 获得史诗级宝物（转移给玩家时） |
| `CargoRevealStarted` | `CargoRevealStartedEvent` | 开始鉴定未识别货物 |
| `CargoIdentified` | `CargoIdentifiedEvent` | 货物鉴定完成 |
| `CargoRevealCompleted` | `CargoRevealCompletedEvent` | 所有待鉴定货物处理完成 |

## 载荷数据结构

所有事件载荷均为 `readonly struct`，使用值类型避免堆分配。

### ShipDestroyedEvent

| 字段 | 类型 | 说明 |
|------|------|------|
| `ship` | `ShipAssembly` | 被摧毁的飞船引用 |
| `reason` | `string` | 摧毁原因（"核心模块被摧毁"/"燃料不足"/"能源不足"/...） |

### ModulesChangedEvent

| 字段 | 类型 | 说明 |
|------|------|------|
| `ship` | `ShipAssembly` | 所属飞船 |

### CoreExplodedEvent

| 字段 | 类型 | 说明 |
|------|------|------|
| `coreModule` | `ShipModule` | 被摧毁的核心模块 |
| `worldPosition` | `Vector2` | 爆炸中心世界坐标 |
| `damage` | `int` | 爆炸伤害数值（`ModuleDefinition.CoreExplosionDamage`） |

### CargoChangedEvent

| 字段 | 类型 | 说明 |
|------|------|------|
| `ship` | `ShipAssembly` | 所属飞船 |
| `cargoType` | `CargoType` | 变更的货物类别 |
| `total` | `int` | 变更后的该类别总数 |

### RadarScanEvent

| 字段 | 类型 | 说明 |
|------|------|------|
| `ship` | `ShipAssembly` | 发起扫描的飞船 |
| `position` | `Vector2` | 扫描中心位置 |
| `radius` | `float` | 扫描半径 |

### DayEndedEvent

| 字段 | 类型 | 说明 |
|------|------|------|
| `dayIndex` | `int` | 已结束的天数序号 |

### GameStateChangedEvent

| 字段 | 类型 | 说明 |
|------|------|------|
| `previous` | `SpaceshipGameState` | 切换前状态 |
| `current` | `SpaceshipGameState` | 切换后状态 |
| `message` | `string` | 状态说明 |

### ExpeditionCompletedEvent

| 字段 | 类型 | 说明 |
|------|------|------|
| `destination` | `string` | 降落/返航目标名称 |
| `discoveredNewPlanet` | `bool` | 是否为新发现的星球 |

### 货物事件载荷

| 事件 | 载荷关键字段 |
|------|-------------|
| `EpicCargoAcquiredEvent` | `ship`（飞船）、`slot`（`CargoSlotRuntime` 槽位） |
| `CargoRevealStartedEvent` | `ship`、`slotCount`（待鉴定格数） |
| `CargoIdentifiedEvent` | `ship`、`slot`、`revealedIndex`（揭示序号） |
| `CargoRevealCompletedEvent` | `ship`、`revealedCount`（已揭示格数） |

## 订阅方映射

| 层 | 订阅的事件 | 响应行为 |
|----|-----------|----------|
| **UI** (`AssemblyPlaytestHud`) | ShipSpawned, ShipDestroyed, CargoChanged, DayEnded | 更新 HUD 数值 |
| **UI** (`CargoOrganizationController`) | CargoChanged, CargoRevealStarted, CargoIdentified, CargoRevealCompleted | 刷新货品列表、显示鉴定消息 |
| **UI** (`RadarAcceptancePanel`) | RadarScanned | 显示扫描结果 |
| **Audio** (`AudioManager`) | ShipSpawned→引擎音效；CargoChanged→拾取音效 | 播放对应音效 |
| **FX** (`FXPlayer`) | 可绑定任意事件 | 反射调用 `[TriggerAction]` 方法 |
| **Gameplay** (`NonPlayerUnitController`) | RadarScanned（自身雷达） | 检测玩家位置 |
| **Gameplay** (`ShipFoodConsumptionManager`) | DayEnded | 每日能源消耗结算 |
| **Gameplay** (`ShipCargoHold`/`CargoRevealCoordinator`) | CargoChanged, EpicCargoAcquired | 更新货舱、触发鉴定流程 |
| **Gameplay** (`SpaceshipGameFlowController`) | ShipDestroyed, DayEnded | 判断失败条件 |

## 动态绑定（FXPlayer）

`FXPlayer` 是通用的「事件→触发器方法」绑定器：

1. 在 Inspector 中配置事件源和触发器方法
2. 运行时 `FXPlayer` 使用反射查找匹配的事件
3. 方法上标注 `[TriggerAction]` 特性
4. 事件广播时自动调用对应方法

---

## 添加新事件的流程

1. 在 `SpaceshipEventSource.cs` 中定义新的 `readonly struct` 载荷
2. 在对应子类中声明 `event Action<T>`
3. 在广播方调用事件源实例的 Raise 方法
4. 在订阅方注册事件处理器

## 事故检查清单

- [ ] 新事件源是否已挂载到场景中的适当位置？
- [ ] 事件载荷是否为 `readonly struct`？
- [ ] 是否存在事件源引用订阅者的反向依赖？
- [ ] 玩法系统是否直接调用了 Audio/FX 播放器？
- [ ] 事件广播是否会产生递归调用？
