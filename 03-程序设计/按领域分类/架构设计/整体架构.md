# 整体架构设计

> 作者：代码分析生成 | 创建日期：2026-07-29 | 最后修改：2026-08-02

本文档描述 Spaceship 项目的整体代码架构、分层模型、设计模式与依赖关系。

---

## 分层模型

项目采用 **Director / System / Actor / EventSource** 四层架构模型：

```
Scene Composition Root
    │
    ├── Game Director / Facade ──────── 协调跨系统流程
    │       │
    │       ├── Gameplay Systems ────── 领域玩法规则
    │       │       │
    │       │       └── Scene Actors ── 单个运行实体
    │       │
    │       ├── Config Assets ───────── 静态配置数据
    │       │
    │       └── Event Sources ───────── 事件广播（单向流出）
    │               │
    │               ├── UI / Views ──── 状态显示，转发输入
    │               ├── Audio Framework ─ 音频播放
    │               └── FX Framework ──── 特效播放
```

### 各层职责

| 角色 | 允许负责 | 不允许负责 |
|------|----------|-----------|
| **Director** | 开局、结束、跨系统流程协调 | 具体库存算法、单个实体运动、UI 绘制、音频播放 |
| **System** | 一个玩法领域的规则和运行时状态 | 创建无关系统、直接操作所有 UI |
| **Actor** | 单个运行实体的局部行为和表现 | 整局流程、全局统计 |
| **EventSource** | 声明和广播一类事件 | 保存玩法状态、执行业务规则 |
| **UI/View** | 显示状态、转发玩家界面操作 | 修改库存字典、推进关卡状态机 |
| **Config** | 保存静态调参和定义 | 保存本局实时状态 |
| **Framework** | 提供通用 Audio、FX、工具能力 | 依赖具体游戏题材类型 |

## 依赖方向

在所有层之间，依赖方向严格约束：

```
┌──────────────────────────────────────────────────────────┐
│  Scene (Composition Root)                                │
│    │                                                     │
│    ▼                                                     │
│  Director ────────► Config Assets                        │
│    │                                                     │
│    ├──────────────► Systems                              │
│    │                    │                                │
│    ├──────────────►     ├──────────► Config Assets       │
│    │                    │                                │
│    │                    └──────────► EventSources        │
│    │                                     ▲               │
│    ├──────────────► Actors ─────────────┘               │
│    │                                                     │
│    │              UI ──────────────► EventSources        │
│    │                    │                                │
│    │              Audio ───────────► EventSources        │
│    │                    │                                │
│    │              FX ──────────────► EventSources        │
│    │                                                     │
│    └──────────────► UI ◄── (UI may query Director)       │
└──────────────────────────────────────────────────────────┘
```

### 关键约束

1. Director 可以向 System 发**命令**和查**状态**
2. System 可以向 Actor 发出**领域内命令**
3. System 和 Actor 可以向 EventSource **广播事实**
4. UI、Audio、FX **订阅** EventSource
5. Audio 和 FX 不得被玩法系统通过具体播放器 API 硬编码调用
6. EventSource 不得引用订阅者
7. Config 不得引用运行时场景实例
8. 禁止 Bootstrapper 自动创建系统，禁止 `DontDestroyOnLoad`（旧版 Bootstrap 仅作回归兼容，不参与正式场景）

## 通信模式

| 通信类型 | 使用场景 | 形式 | 示例 |
|----------|----------|------|------|
| **Command** | 必须立即执行一个明确操作 | 公共方法 | `StartRun()`、`AddItem()`、`Launch()` |
| **Query** | 需要同步获得当前结果 | 只读属性或返回值方法 | `CurrentPhase`、`GetCount()` |
| **Event** | 已经发生的事实，需通知多个被动系统 | 实例事件源 | `RunEnded`、`ItemRecovered` |
| **Callback** | 一个系统初始化时注入窄接口 | `Func` / `Action` | 命中查询、回收回调 |

**禁止**把所有通信都改成事件。需要返回值、顺序保证或失败结果的操作使用 Command 或 Query。

## 模块划分

代码按**面向模块**组织，命名空间统一为 `Spaceship.<Module>`，彻底取消按开发者归属划分的目录与命名空间：

| 模块 | 命名空间 | 目录 | 职责 |
|------|----------|------|------|
| 核心 | `Spaceship.Core` | `Scripts/Core/` | 游戏流程控制器、场景名册、运行时根节点 |
| 玩法 | `Spaceship.Gameplay` | `Scripts/Gameplay/` | 飞船组装、运动、战斗、货物、敌人行为、世界、工坊、投影物 |
| 界面 | `Spaceship.UI` | `Scripts/UI/` | 飞船工坊面板、货物整理、活动表现 |
| 事件 | `Spaceship.Events` | `Scripts/Events/` | 事件源声明与广播 |
| 数据 | `Spaceship.Data` | `Scripts/DataRuntime/` | ScriptableObject 配置与运行时数据 |
| 配置 | `Spaceship.Configs` | `Scripts/Configs/` | 表现等附加配置 |
| 视野 | `Spaceship.Vision` | `Scripts/Vision/` | 视野/迷雾渲染（URP Render Feature）与数据桥接 |
| 工具 | `Spaceship.Tools` | `Scripts/Tools/` | 运行期工具与测试发射器 |
| 校验 | `Spaceship.Validation` | `Scripts/Validation/` | 配置与手工场景装配校验 |
| 音频框架 | `Spaceship.Framework.Audio` | `Framework/AudioFramework/` | 通用音频播放与事件触发 |
| 特效框架 | `Spaceship.Framework.FX` | `Framework/FXFramework/` | 通用特效播放与事件触发 |
| 事件绑定 | `Spaceship.Framework.EventBinding` | `Framework/EventBinding/` | 音频/特效共享的反射事件绑定 |
| 序列图 | `Spaceship.Framework.SequenceMap` | `Framework/SequenceMap/` | 可视化序列图编辑器与代码生成 |

**模块耦合规则**：
- 程序集边界遵循分层 asmdef：`Spaceship.Framework.*`（底层框架）← `Spaceship.Game`（玩法/界面/事件/数据/工具/校验/视野）← 各 `.Editor` 编辑器程序集。
- 跨模块通信通过事件源或显式接口。
- `PlayerShipVisionPolygonBridge` 是玩法与视野之间的合理数据桥接（粘合代码），保留不动。
- `EnemyShipController` 作为敌舰唯一决策入口，实现敌人行为框架驱动接口。

## 设计原则

1. **显式组合优先**：场景对象手动创建，引用通过 `[SerializeField] private` 在 Inspector 中装配
2. **接口隔离**：模块间通过接口契约通信，禁止跨模块目录直接耦合
3. **数据驱动**：游戏逻辑由 ScriptableObject 配置驱动，代码不硬编码数值
4. **可测试性**：核心逻辑应可独立于 MonoBehaviour 进行单元验证（验收脚本）
5. **命名空间隔离**：每个模块的代码位于 `Spaceship.<Module>` 命名空间下
6. **重开可靠**：一局游戏可以在不重新加载场景的情况下恢复到干净初始状态
