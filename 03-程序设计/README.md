# 程序设计

本板块聚焦于 Spaceship 项目的**技术实现设计**，面向开发团队（程序员、TA）。

程序设计文档按**领域分类**组织：以技术方向为单位，沉淀架构、模块、数据、工具、规范。

> **重构导向（2026-08-02）**：代码框架已从「按程序员划分功能」完全迁移为「面向模块区分」的**多层独立模块 + 粘合代码嵌套**组织模式，统一命名空间 `Spaceship.<Module>`，并建立分层 asmdef 程序集边界。玩家与敌人共用同一套能力模块，仅在输入源层产生差异。模式定义见 [模块分层与粘合代码模式](./按领域分类/架构设计/模块分层与粘合代码模式.md)，迁移记录见 [跨开发者目录模块化迁移](./按领域分类/架构设计/跨开发者目录模块化迁移.md)。

## 设计原则

根据项目规范，以下原则应在所有程序设计文档中贯彻：

1. **显式装配优先于自动查找**：组件依赖通过 Inspector 显式装配，减少隐式 Find/Singleton
2. **接口隔离**：模块间通过接口契约通信，禁止跨模块目录直接耦合
3. **数据驱动**：游戏逻辑由 ScriptableObject 配置驱动，代码不硬编码数值
4. **可测试性**：核心逻辑应可独立于 MonoBehaviour 进行单元验证
5. **命名空间隔离**：全部代码统一使用 `Spaceship.<Module>` 命名空间，程序集边界由分层 asmdef 约束
