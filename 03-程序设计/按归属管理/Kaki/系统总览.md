## 核心系统

### SpaceshipGameManager

```1:33:d:\Unity\Spaceship\Assets\Kaki\Scripts\Core\SpaceshipGameManager.cs
public sealed class SpaceshipGameManager : MonoBehaviour
{
    [SerializeField] private SpaceshipGameConfiguration configuration;
    public SpaceshipGameConfiguration Configuration => configuration;
    public void Configure(SpaceshipGameConfiguration config);
    public bool TryGetConfiguration(out SpaceshipGameConfiguration config);
}
```

**职责**：游戏总配置的持有者。**不是静态单例**，不保存玩家、地图、Director 或运行时根节点，只持有 `SpaceshipGameConfiguration` 引用并做有效性校验。在手工装配场景中由场景作者挂载并拖入配置资产。

### SpaceshipGameFlowController

状态机管理四个互斥状态：

| 状态 | 触发 | 允许操作 | 失败/转移条件 |
|------|------|----------|--------------|
| `Title` | 运行时构建完成 | 开始游戏、退出 | → Expedition |
| `Expedition` | 点击开始 | 驾驶/战斗/交互 | 核心摧毁/动力全毁/燃料耗尽/食物不足 → Failure；降落/返航 → Complete |
| `ExpeditionComplete` | 降落或返航 | 再来一局、退出 | → Title |
| `Failure` | 生存条件失败 | 再来一局、退出 | → Title |

状态切换时控制 `Time.timeScale`（出航=1，其他=0）、开关移动/交互/战斗输入，并广播 `GameStateChanged`。`Update` 中每帧检查玩家 `IsOperational`，且无动力舱则强制 `MarkDestroyed`。兼容旧版 Bootstrap 入口字段。

### TemporaryGameDirector

游戏导演组件，负责：
- 日循环计时（**日时长来自 `SpaceshipWorldRules.DayDurationSeconds`，可配置**）
- 每日广播 `DayEnded` 事件（**食物结算已移出**，由 `ShipFoodConsumptionManager` 订阅后消耗）
- 玩家飞船初始化（统一装配物理/事件/货舱/运动/传感器/食物消耗）
- 事件源查找与验证（从序列化列表中按类型分类，缺失或重复时输出中文错误）

### ShipSceneRegistry

场景飞船名册（静态单例，多实例报错并自禁用），管理三类飞船注册：
- **玩家飞船**：通过 `SynchronizeShip` 自动归位（要求 `Player` Tag + `HasCore` + 交互/反馈组件）
- **敌舰**：要求挂载 `EnemyShipController`
- **残骸**：`IsDerelict`（无存活核心）

提供 `RosterChanged` 事件与 `EnumerateAllShips()`，是各系统查询飞船的中央入口。

### SpaceshipRuntimeScope

运行时根节点持有者。`Root` 静态属性记录自身，静态方法 `Attach(GameObject)` 把运行时 `new GameObject` 生成的临时物体（弹体、残骸、掉落货物）统一收纳到根节点之下，便于清场与定位。旧版 `AssemblyPlaytestBootstrap` 会创建该组件；纯手工场景如需运行时生成物，需场景作者自行放置。

### ShipWorkshopModeController

编辑/操控模式切换器，控制工坊内飞船的两种运行模式（`ShipWorkshopMode`：`Edit`/`Control`），切换失败时记录 `LastFailureReason`。

### LevelContentInitializationController

5 阶段关卡初始化流程（`[DefaultExecutionOrder(-800)]`）：
1. 随机模块解析（`SalvageRandomizationManager`）
2. 货物初始化（重建链接 + 按种子初始化货舱，含货物事件源前置校验）
3. 飞船注册（非玩家飞船同步到名册）
4. 导演系统启动（`TemporaryGameDirector.Initialize`）
5. 视野/揭示激活（视野 + `CargoRevealCoordinator` + 整理界面绑定，可配置 `enablePlayerInputWhenReady`）

## 事件系统

事件系统采用**分类事件源 + C# event** 模式，由抽象基类 `SpaceshipEventSource` 统一派生。

```
SpaceshipEventSource (abstract MonoBehaviour)
├── ShipFlowEventSource    → 飞船流程事件
├── ModuleEventSource      → 模块事件
└── CargoEventSource       → 货物事件
```

### 事件定义

所有事件载荷均为 `readonly struct`（零堆分配），定义在 `SpaceshipEventSource.cs` 中：

| 事件 | 载荷关键字段 | 广播时机 |
|------|------------|----------|
| `ShipSpawned` | `ship` | 飞船完成初始化并注册 |
| `ShipDestroyed` | `ship, reason` | 飞船被摧毁 |
| `ModulesChanged` | `ship` | 模块链接/拆除/安装 |
| `ModuleDestroyed` | `module` | 单个模块被摧毁 |
| `CargoChanged` | `ship, cargoType, total` | 货物数量变化 |
| `EpicCargoAcquired` | `ship, slot` | 获得史诗级宝物（转移给玩家时） |
| `CargoRevealStarted` | `ship, slotCount` | 货物鉴定开始 |
| `CargoIdentified` | `ship, slot, revealedIndex` | 单格货物鉴定完成 |
| `CargoRevealCompleted` | `ship, revealedCount` | 货物鉴定完成 |
| `RadarScanned` | `ship, position, radius` | 雷达扫描完成 |
| `DayEnded` | `dayIndex` | 每日结算 |
| `GameStateChanged` | `previous, current, message` | 游戏状态切换 |
| `ExpeditionCompleted` | `destination, discoveredNewPlanet` | 出航完成 |

### 架构约束

- EventSource 不得引用订阅者（单向广播）
- UI、Audio、FX 通过事件订阅解耦，不得被玩法系统直接调用
- 事件源实例由 Director 查找并验证，禁止全局单例
- `SpaceshipGameState` 枚举（Title/Expedition/ExpeditionComplete/Failure）定义于 `SpaceshipEventSource.cs`

## 飞船系统

### 组装系统（Ships/Assembly）

**ShipAssembly** — 飞船总成，管理所有子模块：
- 管理 `ShipModule[]` 子模块列表与 `CarriedModules`（钩爪携带的模块）
- 实时计算总质量、质心、几何快照（`GetGeometrySnapshot`：最远船体端/最大跨度/包围盒）
- 判断阵营：`IsDerelict`（无存活核心）时强制 `Derelict`；`Faction`、`HasCore`、`IsOperational`
- 摧毁逻辑：`MarkDestroyed(reason)` / `DestroyModule`（核心被毁触发整船坠毁）
- **残骸生成**：拆除单模块 → 独立残骸；模块被毁/拆除后按链接连通性 `SplitDisconnectedGroups` 拆分并转移货舱内容
- **拆解重组**：`TryTransferSingleModuleFrom` 把残骸模块按相对坐标装入本船（先试装，无外部链接则回滚）

**ShipModule** — 飞船模块组件：
- 1 米整数网格坐标 + 四分之一圈旋转
- 四向链接点（`Links` 集合）
- 生命值（`ApplyDamage` 归零后交给 Assembly 处理）
- **损坏表现为运行时程序化生成裂纹**（3 档，替代旧四档精灵图）
- 激活/关闭状态，近期拆除标记

**ShipAssemblyInteractionController** — 飞船交互控制器：
- **自动链接**：扫描残骸，玩家模块锚点与残骸锚点相叠累计时间（普通 5 秒；刚拆下 60 秒内 2 秒）后自动装入
- **手动拆除**：右键长按 2 秒（核心不可拆）；雷达/照明右键短按开关
- 进度通过 `LinkProgress01`/`DetachProgress01`/`StatusMessage` 暴露给 HUD

**ShipLinkFeedbackPresenter** — 链接引导线 + 进度条 + 锚点高亮（运行时创建）。
**ModuleLinkAnchorView** — 每个模块四向生成触发器锚点，作为自动链接的碰撞盒与高亮视觉。
**ShipPrefabRuntimeInstaller** — 导出 Prefab 的运行时自装配器（`Awake` 配置组件、`Start` 初始化货物），保障工坊导出飞船在任意场景运行。

| `Thruster` | 动力模块 | 四向推进 | 数量与朝向决定推进速度 |
| `Radar` | 寻敌雷达 | 环境感知 | 可开关，扫描不同阵营 |
| `Light` | 发散光束 | 视野扩大 | 60°/80m 照明范围 |
| `Cannon` | 固定式机炮 | 武器 | 弹药，冷却，射程限制 |
| `Grapple` | 拆卸钩爪 | 模块操作 | 长按 2 秒拆卸模块 |
| `Shield` | 电磁盾 | 防御 | 反弹弹丸与雷达信号 |

| `Empty` | 基础模块 | 纯质量 | 仅提供生命/装甲 |

### 物理运动（Movement）

**ShipMotionController** — 基于 `Rigidbody2D` + Input System：
- WASD 坦克式操作（A/D 旋转，W/S 前后）
- 性能 = 基础速度（玩家用 `PlayerShipSettings`，敌舰用世界规则）+ 各方向动力模块 `ThrusterSpeed` 之和
- 超载惩罚：模块数超限时按超载倍数衰减
- 提供 `GetPerformanceSnapshot` 供链接反馈与 HUD

**ShipCameraFollower** — 跟随质心、旋转跟随、整理模式（冻结旋转）、`Shake` 摄像机震动。
**ShipCollisionFeedback** — 碰撞冲击超阈值时触发 `ShipCameraFollower.NotifyImpact`。

### 战斗系统（Combat）

| 组件 | 职责 |
|------|------|
| `ShipCombatController` | 开火/冷却/弹药管理；**动力模块喷焰视觉 + 尾部灼烧伤害**（`DamageBehindThruster`，0.1s/次 1 点伤害） |
| `ShipShieldController` | 护盾独立充能、反弹弹丸（按模块局部坐标算反射法线）、反弹雷达信号 |
| `ShipGrappleController` | 自动索敌，对准范围内持续作用后拆卸并**携带**目标模块，寻找空闲链接位安装，或抓取独立残骸 |
| `ShipSensorModules` | 雷达自动扫描（只发现不同阵营且存活核心的目标，护盾会反射）＋照明几何判定；被扫目标收到 `OnScannedBy` 回调 |
| `ShipLightVisibilityGeometry` | **纯静态几何库**：发光面/扇形多边形/遮挡命中计算，供传感器、视野桥接、模块活动表现共用 |
| `Projectile2D` | 2D 弹体飞行与命中 |

### 货物系统（Cargo）

| 组件 | 职责 |
|------|------|
| `ShipCargoHold` | 货舱管理（每储存模块 4 槽、每槽 10 单位、转移/丢弃/消耗）；运行时为 `CargoSlotRuntime`（含**鉴定状态**与获取序号） |
| `CargoRevealCoordinator` | **货物鉴定协调器**：按史诗优先+获取顺序逐格揭示，玩家获得史诗货物时强制打开整理界面并锁定揭示 |
| `CargoConsumptionService` | 稳定扣货服务（按距离→网格坐标→槽位索引），供燃料/食物/弹药复用，支持 `CargoInsufficiencyPolicy` |
| `CargoPickup` | 掉落货物拾取体 |
| `StorageModuleCargoConfiguration` | 挂在储存模块上，固定 4 个槽位配置，初始化时按固定/权重随机装入 |

**货物鉴定流程（Reveal）**：残骸打捞 → 货物以未鉴定状态装入玩家货舱 → 打开整理界面或获得史诗货物时逐格揭示（0.45s/格）→ 揭示完成解锁界面。史诗货物（`CargoRarity.Epic`）转移给玩家时广播 `EpicCargoAcquired` 并强制揭示。

### 资源消耗系统（Resources）

| 组件 | 消耗规则 |
|------|----------|
| `ShipFuelConsumptionManager` | **按航程每 100 米结算一次**（核心 2 + 每存活动力模块 1），不足则坠毁 |
| `ShipFoodConsumptionManager` | **订阅 `DayEnded` 每日消耗 5 食物**（仅玩家存活船），不足则坠毁 |
| `ShipAmmunitionConsumptionManager` | 按开火次数经 `CargoConsumptionService` 消耗弹药 |
| `ShipTravelDistanceTracker` | 累计航行距离（单帧 >25m 视为传送跳过），广播 `DistanceRecorded` |

## 数据定义（DataRuntime）

共 8 个类型，是游戏配置的核心（其中 `CargoSlotConfiguration` 为可序列化配置类，其余为 ScriptableObject）：

| 类型 | 继承 | 职责 |
|------|------|------|
| `ModuleDefinition` | `ScriptableObject` | 模块定义（种类/质量/生命/功能/预制体引用），含 `ModuleKind`、`LocalDirection`、`ShipFaction`、旧版 `CargoType` 枚举 |
| `ShipBlueprint` | `ScriptableObject` | 飞船蓝图（模块网格布局 + 初始货物配置 + 导出预制体引用），含连通性与货舱容量校验 |
| `SpaceshipGameConfiguration` | `ScriptableObject` | 游戏总配置（组合所有子配置），含 `IsValid` 全链校验 |
| `SpaceshipWorldRules` | `ScriptableObject` | 世界规则（地图/日循环含 `FoodPerDay`/物理/视野/雷达/小行星/碰撞与残骸） |
| `PlayerShipSettings` | `ScriptableObject` | 玩家飞船行为参数（移动/链接/反馈/钩爪/相机） |
| `ShipWorkshopLibrary` | `ScriptableObject` | 工坊资料库（世界规则+玩家配置+表现配置+已保存蓝图） |
| `CargoSlotConfiguration` | 普通类（`[Serializable]`） | 货物槽位配置（`CargoSlotMode.Fixed/WeightedRandom` + 权重候选） |
| `CargoItemDefinition` | `ScriptableObject` | 货物物品定义（分类/稀有度/弹药类型/鉴定状态） |
